任务结果可确认

概述

AI Agent 需要根据任务执行后的状态、日志、命令输出或验证结果，判断操作是否成功完成。若页面仅展示操作步骤，或只写「运行正常」「确认成功」等结论，却未提供可核对的依据，Agent 就难以准确判断任务结果。

任务结果可确认原则旨在为关键操作提供明确、可读取、可核对的结果依据，帮助 AI Agent 判断任务是否完成、结果是否符合预期，以及是否需要进一步处理。

具体原则

  1. 执行步骤后，应提供可核对的状态、日志、退出码或验证结果，避免仅使用「成功」「完成」等结论性描述。
  2. 对关键命令，应提供必要的预期输出或判断条件，帮助 AI Agent 将实际结果与预期结果进行比对。执行命令不等于执行成功，出现输出也不一定代表任务完成。
  3. 对可能出现的失败、警告、超时或部分完成等情况，应说明相应表现及必要的处理方式，不得将未验证的结果描述为成功。
  4. 保留判断任务结果所需的关键输出、状态信息和必要上下文，避免因内容缺失、截断或缺少判断标准而无法确认结果。

预期效果

  1. 帮助 AI Agent 根据实际状态、日志、命令输出或验证结果判断任务是否完成。
  2. 降低将命令已执行、页面已响应或部分步骤已完成误判为任务成功的风险。
  3. 提高任务执行结果的可验证性，便于后续排查问题和确定下一步操作。

注意事项

  1. 预期结果应具体且可验证。尽量提供明确的状态、关键字段、输出示例或判断条件，避免使用「正常」「无问题」等模糊表述。
  2. 示例输出应与命令及环境相匹配。标明必要的版本、运行条件或输入参数；示例结果仅供参考时，应明确说明。
  3. 不得将预期结果当作实际执行结果。文档中的输出示例用于说明验证方式，不代表命令已在当前环境中执行成功。
  4. 失败信息应具有可操作性。对常见错误，尽可能说明错误表现、可能原因和排查步骤；不应只给出成功路径。
  5. 结果信息应保留必要上下文。涉及版本、路径、参数、运行环境或执行对象时，应提供足以判断结果适用范围的信息。
  6. 避免要求所有任务提供冗长日志。根据任务风险和复杂度，选择必要的验证信息；简单操作可以使用明确状态或简短输出。
