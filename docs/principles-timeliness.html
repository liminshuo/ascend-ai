版本号外显

在每篇文档的渲染页与元数据中显式展示版本号、发布日期与生命周期状态，让人和机器都能一眼确认这是哪一版、是否为当前主推版本。 找的准 · 序号 2 · 对应 问题论证 · 版本滞后。 · 设计专项见 版本信息外显。

对象

类型 说明 常见落点
日期与版本 更新日期与版本号（如 v8.0.0）须写成字；禁止仅靠列表顺序或「新」色标暗示时效。 文档列表、页头元信息
演进关系 取代、兼容、适用版本须用文字写明；版本号本身不能替代关系描述。 版本对照、变更说明

设计UI调整

调整建议

  • 新旧写成日期和版本：条目须标注可读的更新日期与版本号。角标可保留，但不得替代日期与版本文字。
  • 演进关系写成词：取代、兼容、适用版本须写成「已被 v8.0.0 取代」「兼容 8.0」等；版本号不能代替关系句。

调整示例

日期与版本须写成字

反面

CANN 安装指南 新

CANN 安装指南（旧版）

  • 常见疏漏：仅有「新」色标与「旧版」字样，机器无法识别更新日期与版本号。
正面

CANN 安装指南

v8.0.0 · 更新 2026-03-12

CANN 安装指南

v7.0.0 · 更新 2025-08-01

  • 正确做法：写成版本号（如 v8.0.0）与更新日期；「新」色标可留，只辅助。
  • 可免场景：页头已写明仅展示当前版本时，列表内可不重复日期。

演进关系须写成词

反面

CANN 安装指南

v8.0.0 · 更新 2026-03-12

CANN 安装指南

v7.0.0 · 更新 2025-08-01

  • 常见疏漏：版本与日期可抓取，但未写演进关系，机器无法判断 v7.0.0 是否仍适用、是否已被取代。
正面

CANN 安装指南

v8.0.0 · 更新 2026-03-12

CANN 安装指南

v7.0.0 · 更新 2025-08-01 · 已被 v8.0.0 取代

  • 正确做法：演进关系写成「已被 v8.0.0 取代」「兼容 8.0」等。

设计专项完整说明见 版本信息外显。

文档内容调整

调整建议

  • 每个文档页面必须在其元数据区域以结构化（机器可优先读）和自然语言（人类可读）两种形式，明确声明：产品/项目名称、文档对应的软件版本号（遵循SemVer）、该版本的发布日期、该版本的生命周期状态（如当前稳定版、维护中、已启用、EOS）、（可选）文档版本自身的版本号。所有版本差异必须使用表格进行条目化描述，禁止使用模糊散文。

调整示例

1. 版本元数据在 Frontmatter 中声明

Before · 无版本声明

# 算子开发入门

本文介绍 Ascend C 算子开发基本流程…

After · 完整版本 Frontmatter

---
product: CANN
version: "9.0.0"
release_date: "2026-06-01"
lifecycle_status: stable   # stable | rc | beta | deprecated
---

# 算子开发入门

本文介绍 Ascend C 算子开发基本流程…

前端调整

调整建议

  • 版本元数据结构化字段：CMS 中为每个页面增加强制填写的结构化字段：product-name、software-version（SemVer 格式校验）、release-date、lifecycle-status，发布时校验必填，缺失则阻断。
  • 元数据机器可读输出：版本信息同步写入页面 <head> 的 <meta> 标签和 JSON-LD，如 softwareVersion、datePublished、releaseNotes 字段，供大模型直接读取，不依赖解析页面正文。
  • SemVer 格式校验：CMS 在版本号字段录入时强制校验 SemVer 格式（X.Y.Z），拒绝模糊写法如"最新版"、"V2"。
  • 版本元数据在大纲接口中透传：页面大纲接口返回结果中包含版本元数据字段，大模型消费接口时可直接获取版本上下文，无需进入页面解析。

调整示例

1. 元数据写入 <head>

Before · 缺失版本元数据

<head>
  <title>算子开发入门</title>
  <!-- 无版本信息 -->
</head>

After · 完整结构化元数据

<meta name="version" content="9.0.0">
<meta name="release_date" content="2026-06-01">
<meta name="lifecycle_status" content="stable">
<link rel="canonical" href="https://…/900/operator_dev.html">

2. JSON-LD softwareVersion 机器可读版本声明

Before · 无 JSON-LD 版本字段

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "TechArticle",
  "headline": "算子开发入门"
}
</script>
<!-- 缺少 softwareVersion / datePublished /
     releaseNotes，Agent 无法判断版本时效 -->

After · 完整版本字段

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "TechArticle",
  "headline": "算子开发入门",
  "softwareVersion": "9.0.0",
  "datePublished": "2026-06-01",
  "dateModified": "2026-06-15",
  "releaseNotes": "https://…/900/changelogs.html",
  "isBasedOn": {
    "@type": "SoftwareApplication",
    "name": "CANN",
    "softwareVersion": "9.0.0",
    "applicationCategory": "AI Framework"
  }
}
</script>
