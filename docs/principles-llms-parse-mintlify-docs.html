Mintlify 文档分册

解析什么

对照 Mintlify 文档分册 https://www.mintlify.com/docs/llms.txt。从根清单的 Documentation index 跟过来。这一本只摊产品文档，不再套第三层 llms.txt。原则写法见分册llms。

它在解决什么

文档站页数多。若把每一页写进根 llms.txt，根文件会截断。根文件只留一条分册入口；分册再摊这一面的页。

这本分册怎么摊开

  • 叶子是 .md接口页、指南页直接链平行稿，不再写下一本 llms.txt。
  • 大面用 .md 索引英文文档 181 页交给 _llms/en/documentation.md：仍是目录（页清单），不是正文，也不是第三层 llms。
  • 按产品面分节API reference、Help center、Learn、OpenAPI Specs 分开，不是把导航原样搬家。

分册交付示例

对照文档分册开头与文末 Indexes。全文很长，这里只摘结构：页顶、文档总表、接口直链、语言索引。OpenAPI / Help center 等节现网仍在同一文件里。

分册 llms.txt 交付件拆解

对照 docs/llms.txt：这一面的目录。结构仍是标题 + 列表。下一跳是各页 .md 或 _llms 索引，不是再一本 llms.txt。

页顶

# Mintlify 仍是站点名。引用块说明这本分册面向产品文档，不是整站营销页。

文档总表

点开绿行，拿到的不是文章，是下面这种文件：181 个页名排在一起。

里面是页名，所以看起来像目录。但文件名叫 .md，是在告诉 Agent：别再找下一本 llms 了，开始对着这些页读。

  • 看见 llms.txt下一步是「再打开一本目录」（根 → 分册）。
  • 看见 .md下一步是「读」。清单再长，也是读这一面的页，不是再问路。

所以这里不能再套 llms.txt：Agent 会以为还有第三个面要选。没有。英文文档就是刚才选中的那一面，只是页太多，单独放进一个 .md 里列出来。

各页直链

## API reference 下列接口页，每条直接是 .md。页数可控的分组不必再包一层索引文件。

文末 Indexes

文末这些地址，和绿行是同一类文件：各语言的页名清单，仍是 .md。

价值收益

  • 根文件读得完文档页不堆进根清单。
  • 这一面找得到页分册里每条都能跟到 .md。
  • 不再套 llmsMintlify 到这一层为止，没有第 3 本 llms.txt。
