这条路径说明什么

  • 从上往下读，碰到候选先记下Agent 按文件顺序读，不是先把所有 URL 打开再挑。读到像入口的那条（橙行）先记下，不立刻跳走。
  • 候选所在的节要读完，后面几条也看同一节里，候选下面的条目仍会读，用来确认不是它们。产品线 Programming Guides 里，programming guide 后面的 best practices 就是这样。不是碰到黄行就走。
  • 其它章只扫标题和一句说明，再进下一层后面的 ## 跳读节名和描述，排除北美站、CUDA-Q、安装指南、API 等。相关才进节里看第一条。排除完，再打开下一份。这一问每层跟一条；问句要对照两页时，同一层可以跟两条。
  • 答案在当前文件就停第四份已经是编程指南，Part 4 / 附录只扫节名，不再打开。打开几次由「问句还缺什么」决定，不由目录有几层决定。
  • 先分站，再选产品NVIDIA 不是一座站。根清单按站点切开：北美营销、技术文档、开发者、GTC、地区博客。这一问是编程文档，所以进 Tech Docs，不进北美站或开发者站。进了文档站还要再选产品（CUDA），产品册才列页。分站是因为集团多入口会撑爆一份根文件，不是把导航菜单原样搬家。
  • 这一问有三本 llms分站之后，文档站里产品线仍是目录，所以再套一本产品 llms.txt。打开四份文件：三本 llms + 一篇正文。官网、博客没有产品线这一刀，第 2 本就列页。
