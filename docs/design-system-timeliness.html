版本与时效信息可识别

原则定义

技术文档、产品说明和操作指南会随版本迭代更新。若页面未明确标注版本、更新时间或内容状态，AI Agent 就难以判断内容适用哪个版本、是否仍有效，可能引用过时信息。

版本号、更新时间与生命周期状态须以可读文本呈现，并在列表、详情页与机器可读字段间保持一致；不能仅用颜色、图标、「新版」或「EOL」等缩写代替。

元素拆解

版本列表

版本列表为每一行分别承载版本号、生命周期状态与更新时间。三者须写成独立文本，状态不依赖颜色或内部代号。

版本号1 2生命周期状态 3更新时间
OmniAdvisor 版本号 版本状态 更新时间
v24.0.0 维护中 预计2026/6/30发布
v23.0.1 即将停止支持 2026/3/30
v2.2.0 已废弃 2025/9/30

视觉规则

  1. 1版本号展示具体版本号（如 v24.0.0），不用「新版」「旧版」等相对描述。
  2. 2生命周期状态使用「维护中」「即将停止支持」「已废弃」等可读中文，不单靠颜色或 EOL 缩写。
  3. 3更新时间展示明确日期或发布说明，格式统一；不依赖排序位置推断新旧。

前端规则

  1. 可见文本版本号与生命周期状态写入单元格可见文本；颜色 class 仅作样式，不得替代文案。
  2. time日期使用 <time datetime>，展示文案与 datetime 一致。

示例如下：

<td>v24.0.0</td>
<td>维护中</td>
<time datetime="2026-06-30">预计2026/6/30发布</time>

详情页页头须写明本文档适用的版本号与更新时间，并与版本列表同源、同值。

适用版本1 2更新时间

视觉规则

  1. 1适用版本在标题区域展示具体版本号，便于与列表对照。
  2. 2更新时间写清本文最后更新或发布日期，置于页头可见区域。

前端规则

  1. 可见版本版本号写入标题旁可见文本，不只放在 URL 或元数据。
  2. time更新时间使用 <time datetime>，与页头展示文案一致。

示例如下：

<h1>安装 Spark 引擎 <span>24.0.0</span></h1>
<time datetime="2026-04-14">更新时间：2026/04/14</time>

适用边界

上述规则适用于版本列表或文档详情中的版本、日期与状态需要被 AI 识别、筛选或引用的场景。

版本号、更新时间与生命周期状态应分别表达，不能相互替代；「最新」不等于「仍受支持」。历史版本可保留，但须标明状态并在必要时链向现行版本。

列表、详情与机器可读字段应随内容变更同步更新，避免不同入口的版本信息冲突。
