站级导读

尽管 /llms.txt 是行业惯例，但并非强制协议。实测中，多数 Agent 会绕开它，直接从搜索命中或外链落到人读 HTML。如果页内缺少回到站级导读的回链，模型就会被困在单篇正文里，既看不到邻篇，也断了继续扩抓的线索。 因此，H1 旁需要有视觉可见、源码可跟的 llms.txt 真链作为兜底，引导 Agent 从当前页回到发现层，再顺着目录抓取后续内容。

Agent 是如何发现入口的

主路径 · 发现层

按约定直接获取根目录或子路径的 llms.txt。

兜底入口 · 内容层

未走发现层时，通过 H1 旁指向 llms.txt 的真链（图标 / 文本）回接清单，再批量抓取邻篇。无需强制文案，但链接语义需明确目标。

核心原则

  • 视觉与源码统一入口需要显式呈现在 H1 标题旁。无论采用纯文本、带图标的文本还是纯图标，都应出现在用户的视觉流中，并在源码层面确保它是 main 区域内的真实 <a> 标签。
  • 主次分明站级导读的获取依然以发现层约定路径为主（详见发现层部署）。页面上的补救链接只作为兜底存在，不抢占主路径的职责。

执行要点

  • 指向约定路径href 需使用 llms.txt 的绝对地址（位于根目录或文档站子路径）。
  • 链上标明是 llms有文字位时应写明 llms.txt / LLMs 等可识别名。只用图标时，在 <a> 标签上添加 aria-label="llms.txt"（可同时设置 title），img 的 alt 留空。避免使用「更多」「AI」「站级导读」等与文件目标无关的文案。
  • 保持首包真实Agent 无法识别图片语义，可跟的只有源码中的真实链接。图标必须落在首包已有的 <a> 标签内。不要使用 CSS background-image 画图标，不要通过 JS 悬停插入 DOM，也不要只写在 <head> 或页脚中。

价值收益

  • 用户与 Agent 双赢用户界面提供清晰可见的入口路径，底层源码为 Agent 提供可靠的抓取锚点，两者兼顾。
  • 覆盖任意落点Agent 进入站点时未必途经文档站路径，可能直接落在门户或专题页。通过在各页标题旁挂载可见真链，即可确保从任何位置都能接回发现层，免去路径猜测。
