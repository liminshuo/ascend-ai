机器可读：内容消费入口显性化

「机器可读」是内容能被 Agent 直接消费；「入口显性化」是把消费路径做到渲染页上可见、可跟。本页围绕站级导读、本页 Markdown、块级平行源三类入口，说明人和 Agent 如何识别它们，以及设计、文档与前端如何落地。四个发现文件怎么写，见 发现层部署。

发现机制

与发现层「直打 /llms.txt」不同：这里 Agent 先落到一篇人读页。三路前两步和作答相同，差别在第 3、4 步：找哪类入口、读哪份源。三类入口如何识别见后面表2。

解决什么问题

发现层文件能告诉 Agent 知识在哪、先看哪篇。落到一篇渲染页时，消费路径却经常不在版面上：入口只在根路径、仓库或源码里，人和 Agent 都从当前页跟不进去。

  • 站级入口缺席 已部署 llms.txt，页脚仍只有法务链。隐藏链、无字链对人无效，审计也无法从版面核对。
  • 页级入口缺席 标题旁只有分享、收藏与仓库源码，没有「复制 / 打开本页 Markdown」，当前页平行源进不去。
  • 块级入口缺席 架构图、规格表停在截图里。楼层旁的 # 锚点只服务人跳转，带不走层级关系或规格数值。

三类入口如何被识别

表2 渲染页上的站级 / 页级 / 块级入口
粒度 人看见 Agent 跟到 不算入口 常见落点
站级 页脚等次要区的可读文案，如 llms.txt 站级导读文件（如 /llms.txt） 只部署文件、无字隐藏链、每页源码里才有的链 全站页脚、固定次要位
页级 标题旁「复制 / 打开本页 Markdown」 当前页平行 Markdown 仅仓库源码链、仅 rel="alternate" 文档页头工具区
块级 楼层标题旁的平行 MD 入口（可读文案或带说明的徽标） 该块的 Markdown：架构关系，或规格项 | 数值 章节 # 锚点、只有截图没有平行源 平台栈、产品规格表

核心原则

  • 发现层写文件，本页标入口 根路径有 llms.txt 不等于渲染页可识别；页上有入口也不等于文件写对。两页各管一层。
  • 入口在首包里，不用悬停注入 对人是默认可点的动作名；对 Agent 是已存在的 href 或带可见文本的控件。head 里的 alternate、无可见文案的隐藏链只能当辅助。

设计UI调整

调整建议

  • 站级放次要区，不抢主路径 页脚小字链即可，不要做成首页主 CTA 或 AI 角标体系。
  • 下拉里写出动作名 菜单展开后每一项仍是可读短语（复制 Markdown、打开 Markdown）；禁止悬停才出文案、禁止只有图标。
  • 块级入口跟在楼层标题旁 轻量、与标题同一行；徽标须带可读名称或 title，指向该块平行源，而不是本页锚点。

文档内容调整

调整建议

  • 与发现路径同名 入口文案须与 llms.txt / 本页 .md 路径语义一致，避免「更多」「AI」等空泛词。
  • 多模型写清动作 若提供多模型入口，列出具体模型或动作，勿只写「聊天」。

前端调整

调整建议

  • 可抓链接或可见文本控件 入口须为 <a href> 或带可见文本的 button；勿悬停才注入 DOM，勿做无人可读的隐藏链。
  • 与 alternate 联动 页头可输出 link rel="alternate" type="text/markdown"，与页级入口目标一致，但不能代替标题旁的可见动作。
