robots.txt 核验 Checklist

现网文件：robots.txt

#检查维度核验内容核验结果测评结果优先级
1 文件可访问性 检查 /robots.txt 是否能正常访问，内容是否可读取。 核验通过
访问正常：文件可正常打开，返回可读取的规则文本。
规则完整：包含通用爬虫和 AI Agent 的抓取规则。
未见异常：未发现异常跳转或错误页替代正文。
 P0
2 Sitemap 声明 检查 robots.txt 是否列出站点地图地址，以及地址格式是否正确。 核验通过
已声明站点地图：共列出 11 条地址。
覆盖多类内容：包含网站根站点地图、中英文站点地图及不同内容分类的站点地图。
地址可直接打开：均为带协议与域名的完整链接，未使用相对路径。
 P0
3 抓取规则合理性 检查抓取规则是否允许公开内容被发现，并限制不需要公开抓取的路径。 核验通过
公开内容允许抓取：通用规则允许访问网站内容。
指定路径受到限制：已限制 /profile/、/doc_center/ 路径。
 P0
4 llms 入口声明 检查是否声明 AI 可读取的网站知识入口。 核验通过
2026-10 修改后：已声明 /llms.txt、/llms-full.txt、/llms-content/ 等路径，并配置 LLM-Policy。
2026-06 基线对照：当时 llms 入口完全缺失（根目录无法访问、子产品未部署）。详见下方 llms Checklist 红条说明。
 P0

Sitemap 核验 Checklist

#检查维度核验内容核验结果测评结果优先级
1 站点地图可访问性 检查已声明的站点地图文件能否正常访问、解析，以及能否提取页面地址用于统计。 核验通过
文件均可正常访问：现网 11 个站点地图文件均返回 HTTP 200，内容格式正常，可提取页面地址。
 P0
2 页面自动化访问与正文获取 从站点地图中抽样检查页面，确认自动化访问能否返回预期正文（返回安全验证页不等于 URL 已失效）。 发现风险
多数抽样链接访问正常：案例库、博客、中英文栏目及任务页面等大多返回预期页面，标题与页面内容基本符合预期。
部分链接未能返回预期正文：抽查的 /document/detail/ 相关页面及部分外部链接未能正常获取预期内容，具体情况详见「页面可访问性」Checklist。
 P0
3 站点地图组织与覆盖 检查站点地图的声明情况、分片组织、页面覆盖及跨文件重复情况，确认入口是否完整、统计口径是否清晰。 发现风险
站点地图采用并列组织方式：现网 11 个站点地图文件均已在 robots.txt 中声明。
根站点地图未汇总其他分片：根目录 sitemap.xml 仅包含自身的 295 条页面地址，未进一步指向其他站点地图文件。
存在跨文件重复记录：站点地图共包含 77,430 条记录，去重后为 76,753 条，存在约 677 条重复记录。
 P1
4 页面更新时间（lastmod） 检查站点地图是否填写页面更新时间，以及时间信息能否合理反映页面的实际更新情况。 发现风险
少量页面缺少更新时间：共 85 条记录未填写 lastmod，约占总记录的 0.11%，主要分布于中文和英文站点地图。
更新时间的准确性待核验：抽样页面普遍缺少可供对照的更新时间信息，部分同类页面的 lastmod 日期高度一致。约 93% 的记录标注为 2026 年，需进一步确认这些时间是否真实反映页面更新情况。
 P1
5 URL 可识别性 检查站点地图分片命名和 URL 路径是否便于识别页面所属栏目、语言及内容主题。 发现风险
分片文件名的语义不够明确：如 sitemapdata1、sitemapdoc1，仅凭文件名较难判断其具体内容范围。
部分 URL 难以直接识别主题：现网约 6 万条 URL 位于 /document/detail/ 路径下，另有部分博客数字 ID、任务 UUID 和案例 topic ID 等路径。仅凭地址较难判断页面主题，可能增加人工核验或辅助选页的判断成本。
 P2

llms.txt 核验 Checklist

2026-06 基线：llms 入口完全缺失。当时根目录 /llms.txt 无法访问，且未发现子产品部署该文件，AI Agent 缺乏结构化导航。以下表格为 2026-10 修改后基线实测。
#检查维度核验内容核验结果测评结果优先级
1 索引文件可访问性 检查 llms.txt 和 llms-full.txt 是否能够正常访问并读取文本。 核验通过
文件均可正常访问：两个文件均返回 HTTP 200，响应内容为纯文本。相对 6 月基线，根目录 llms 入口已补齐。
 P0
2 HTML 与 Markdown 对应关系 检查目录条目是否同时提供 HTML 页面地址及对应的 Markdown 文件路径。 核验通过
路径对应关系完整：约 26,147 条条目同时包含 HTML 页面地址和 Markdown 路径，占比约 99.96%。该结果反映目录映射情况，不代表目标 Markdown 文件均可正常读取。
 P0
3 目录结构与内容质量 检查目录分类、标题和条目说明是否有助于 AI 判断内容主题与相关性。 发现风险
已具备分层/分册索引能力：相对 6 月「完全缺失」，10 月已出现根目录与子产品 llms.txt 等结构化入口。
主题分类仍不够清晰：目录仍大量以连续清单形式排列，部分说明较笼统或含转义符号，不利于快速识别内容重点。
 P1
4 文件体量与读取效率 检查目录文件体量，以及在指定测试条件下能否被 AI 工具完整读取。 发现风险
文件体量较大：llms.txt 和 llms-full.txt 均超过 12 MB，目录包含约 2.6 万条条目。
实测存在读取截断：本次测试中，指定 AI 工具未能完整读取目录文件，返回内容出现截断，可能影响目录信息的完整获取和后续选页。
 P1

02｜可读 · 完整可读的内容

Markdown 核验 Checklist

#检查维度核验内容核验结果测评结果优先级
1 Markdown 文件可访问性 抽查目录指向的 Markdown 文件，检查能否正常访问并获取实际正文。 发现风险
抽样文件未能读取到正文：10 个样本均返回 HTTP 200，但响应内容为安全验证或 Cookie 验证页面，而非预期的 Markdown 正文。当前自动化访问方式无法获取这些文件的实际内容，可能影响 AI Agent 读取和利用相关技术资料。
 P0
2 Markdown 正文有效性 检查正文内容是否完整、可读，格式是否符合预期（是否为真实 Markdown，而非同壳 SPA / 渲染页）。 发现风险
.md 名实不符（读不顺 · HTML 适配不足）：以「什么是 Ascend C」为例，将地址改为 .md 仍走 Nuxt SPA，实测出现 [object Object]、锚文本丢失——扩展名不能当作「模型友好正文」依据。
双轨缺失、默认落渲染壳：人读渲染页约 224 KB；更纯净的 /doc_center/source/（约 4–11 KB）未在机器入口稳定声明，Agent 默认仍剥高噪声 HTML 壳层。
 P0

页面渲染 / 抓取 Checklist

#检查维度核验内容核验结果测评结果优先级
1 正文可提取性 检查页面正文能否被自动化工具提取，判断原始 HTML 是否包含有效正文，以及是否依赖 JavaScript 渲染才能获取内容。 发现风险
部分页面正文可正常提取：/cann、/document/caselibrary 及案例详情页均可提取有效文本。
部分技术文档正文读取受阻：/document/detail/ 相关页面在未执行 JavaScript 的请求中返回安全验证页，而非文档正文，无法据此判断正常浏览器渲染后的实际表现。
 P0
2 图片信息可读性 检查正文图片是否提供 alt、图注等文本说明，以及重要图示所表达的信息是否能通过文本获取。 发现风险
栏目页图片说明不足：抽查 /cann、/document/caselibrary 及案例详情页时，多数 <img> 缺少 alt，未见 figure/figcaption。
文档图意未入库（读不懂·图片语义）：以「什么是 Ascend C」为例，6 张信息型 PNG 在转文本管道中完全不进入 chunk；HTML 多见 zh-cn_image_xxx.png 文件名，无 alt 与图意转写，问「API 有几层」时知识库无对应内容。
 P0
3 颜色语义可读性 检查颜色、图标所表达的状态或提示级别（如注意 / 警告）是否有可读取文字，而非仅依赖视觉表现。 发现风险
提示正文可抓（读不懂·Note）：环境准备等页 notebody 正文可入库。
颜色 / 图标级别无文本：「注意 / 警告」等类型主要靠彩色图标 PNG 区分，无文本标签；问「有哪些注意事项」时难以按级别过滤检索。
 P1
4 表格结构可读性 检查表格是否具有明确的标题和表头、表头与数据对应关系是否清晰，以及单元格内容能否被提取。 发现风险
抽样表格的基本内容可读取：部分案例详情页使用 thead/th，单元格为文本，行列信息可提取。
规格表语义劣化（读不懂·表格语义）：以 Add 自定义算子「表 1 设计规格」为例，列布局混杂、空单元格与伪多行并存，接口列表与 OpType 从属易在 chunk 中断开；表题未写入 caption，难以锚定「表 1 含哪些 API」。
 P1
5 代码块语义可读性 检查代码块是否可提取纯净源码，是否混入行号，以及语言类型是否可识别。 发现风险
代码主体部分可抓（读不懂·代码语义）：HelloWorld 等页代码文本可获取，属「部分可抓」。
行号与源码混杂、语言未标注：highlighttable 将行号写入单元格，入库后出现 1 2 3… 前缀，复制后不能直接编译；缺少 language-xxx，bash / C++ / CMake 易混淆，HTML 实体未解码。
 P1
6 交互隐藏内容可读性 检查 Tab、折叠等交互区内正文是否进入默认抓取结果，而非仅标题可见。 发现风险
非激活 Tab 未入库（读不懂·Tab）：CANN 软件下载页多轴 Tab 选型，非激活面板可被 display:none 隐藏，默认抓取往往只入库当前 Tab 组合；问「Atlas 800 离线安装」时可能仅有在线安装说明。
折叠区步骤丢失（读不懂·折叠）：「我不知道硬件信息」默认收起，区内硬件确认步骤可能仅剩标题；与 Tab 叠加后，「不知硬件 → 如何选包」链路对 RAG 不可见。
 P0
7 轮播 / 运营位内容可读性 检查首页等多帧运营位文案是否可抓，以及是否适合作为可引用知识入库。 发现风险
多帧标题部分可抓（读不懂·轮播）：首页轮播源码可见「智能助手上线」「HCCL 通信库创新大赛」等帧文案，好于「只入库当前帧」。
营销噪声不宜当规格知识：帧内容偏活动/招募/认证引流；若整站首页进知识库，模型易把口号答成官方能力说明；图意与 CANN 文档落地页绑定弱。
 P2

03｜可理解 · 明确的内容语义

语义与结构化 Checklist

#检查维度核验内容核验结果测评结果优先级
1 链接与热区可识别性 检查链接文本是否能说明目标页面或用途；图片热区（usemap/area）是否另有可读文本链接，避免跳转语义只存在于像素坐标或占位符。 发现风险
多数栏目链接尚可读：抽查可读取页面中，多数链接使用栏目名、产品名或文档标题。
占位符锚文本劣化（读不懂·链接语义）：HelloWorld 页出现「完整样例请参考 LINK」——href 指向 GitCode，chunk 中仅保留「LINK」，问「样例仓库地址」时无法检索目标语义。
泛化锚文本仍存在：「查看详情」「了解更多」及无名称图标链接增加目标判断难度。
热区链接完全丢失（读不懂·热区）：以「什么是 Ascend C」成长地图为例，全页约 28 个热区；map/area 不进入 chunk，问「学习顺序 / 环境准备在第几阶段」时知识库无对应链接文本。
 P0
2 结构化数据（JSON-LD） 检查首包 HTML 是否包含 application/ld+json，字段是否完整，以及是否与页面可见信息一致。 发现风险
部分可读取页面已输出 JSON-LD：首页为 WebSite；/cann、/document/caselibrary 等为 WebPage，且出现在首包 HTML 中。
字段完整性与可用性不足：抽样栏目页 name 写成 URL；缺 headline、description、日期与作者等常见字段。
技术文档页暂无法充分核验：/document/detail/ 自动化请求常返回验证页，未能确认其 JSON-LD。
 P1

AI 回答中的品牌与可信

官方信源链路实测（Ascend C）

#检查维度核验内容核验结果测评结果优先级
1 检索阶段 · 社区官方占比 联网问答检索 URL 池中，hiascend.com 社区官方 URL 占比（非知识库 chunk 召回）。 发现风险
社区官方未过半：Claude 21%（19 条中 4 条）、DeepSeek 33%（27 条中 9 条）；千问界面未单独显示检索链接。
非社区信源占主导：Claude 第三方教程 79%；DeepSeek 华为系其他渠道合计约 56%——与「基于官方资料」约束错位。
 P0
2 生成阶段 · 社区官方引用占比 回答段末 URL / 脚注中，昇腾社区官方引用占比。 发现风险
社区主信源识别偏弱：Claude 35%、DeepSeek 22%、千问 67%；「基于官方资料」未能稳定拉高 hiascend.com 选材优先级。
「官方」归类失准：Claude 以第三方为主体（65%）；DeepSeek 以华为系非社区渠道为主体（约 69%）；三模型溯源构成差异大。
 P0
3 版本滞后 & 多版本并存 以 CANN 社区版 9.0.0（900） 为基准，核验检索池与生成溯源中的版本分布。 发现风险
未见主推版本：三模型检索与生成均未引用 …/900/… 社区版路径；多见 8.x / 850 / 83RC1 / 900beta / 9.1β 等旧版或预览版。
多版本并存：不同世代命令与 API 混在同一回答，按旧路径操作易与 9.0.0 产品面脱节。与下方「引用页面适用率」中「版本偏低」结论同向。
 P0
