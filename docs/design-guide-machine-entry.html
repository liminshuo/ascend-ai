AI入口可识别

原则概述

框架层

  • /llms.txt 宜在页脚用小字标出，便于查与审计。

页面层

  • 文档页头须有「复制 / 打开本页 Markdown」等可辨入口。
  • 「获取源码」须注明「本页 Markdown」，路径宜直取，不能单独替代文档级入口。

楼层层（强视觉内容的平行入口）

  • 架构图 / 平台栈：标题旁轻量 MD 徽标链到平行 MD，MD 中写层级关系；本页保留空间感与真链。
  • 规格表：若首包无完整 HTML 表，提供平行 MD 表。

对 AI 的好处

  • 通过 /llms.txt 发现站点文档清单
  • 直接取当前页结构化 Markdown
  • 规格参数按「参数名–数值」表对齐，不依赖首包缺失的 HTML 表

场景示例

框架层

示例 1 · 页脚标出站级机器入口

核心原则：站级机器可读清单（如 llms.txt）若存在，应在页脚次要信息区用可读文案标出，让人和审计能从版面跟到。文档页头「复制页面」各管一层，页脚只做轻量指路，不抢主路径。

例外情况：文档中心或关于页等已有同等清晰的站级入口时，页脚可不重复挂链。

页面层

示例 2 · 文档页头须有机器入口

核心原则：文档页头（标题旁工具区）须有可辨的本页 Markdown 入口（复制或打开）；对话可选。仅分享 / 收藏不够；仅「获取源码」跳到仓库也不够。

例外情况：整站 llms.txt + 稳定本页 .md 直链且页内能跟到时，文档页头可不重复堆按钮。巨型「AI」主按钮不必强加。

反面
  • 缺文本替代：页面有「分享 / 收藏」入口，但「获取 GitCode 源码」指向仓库中的 .md 文件，属于旁路跳转，文案未明确标注「本页 Markdown」，且无「复制本页」或「对话」入口。 查看示例来源

楼层层

示例 3 · 架构图用 MD 陈述关系

核心原则：强视觉架构图 / 平台栈可不在本页展开关系长文（以免破坏空间感）；标题旁挂轻量 MD 徽标，平行 Markdown 里陈述层级关系（谁在上、谁依赖谁）并链到各产品。本页保留分层视觉与产品真链。

例外情况：若产品名已是真链且另有概述页完整写清关系，图旁可不重复挂徽标；无平行 MD 时不要空挂。场景示例：首页结构楼层。

反面
  • 关系未机读：本页为保视觉不写关系长文，又无平行 Markdown；机器只能看到分层标签，跟不稳「谁依赖谁」。 查看示例来源

必有项

可选项

  • 图旁 MD 徽标：标题旁轻量 MD 徽标即可；勿在主视觉区加关系说明卡。

示例 4 · 规格表用 MD 并行

核心原则：技术规格表若浏览器可见但首包无完整 HTML 表，宜提供平行 Markdown，用 Markdown 表写清「规格项 | 数值」；标题旁挂轻量 MD 徽标作入口。主 CTA（项目咨询 / 固件）不变。

例外情况：首包已有完整可抓的 table/th/td 规格表时，徽标可省略；无平行 MD 源时不要空挂。场景示例：产品介绍页（如 Ascend 950PR）。

反面
  • 规格未机读：浏览器能见「Ascend 950PR 技术规格」表，但首包 HTML 无完整 table、也无平行 Markdown；机器跟不稳规格项与数值。 查看示例来源
