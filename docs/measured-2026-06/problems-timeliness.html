3. 问题洞察

  • 版本滞后：三模型检索与生成均未引用 …/900/… 社区版路径，多见 8.x / 850 商用 / beta 等旧版。
  • 多版本并存：不同世代命令与 API 混在同一回答，按旧路径操作将与 9.0.0 产品面脱节。

根因分析

版本滞后的核心原因是：页级版本未外显、主推版本未声明、入库缺 version 字段、溯源不带版本信号。

1. 页级版本未外显

渲染页头无 version 徽章，版本仅藏在 URL 路径——入库 chunk 缺字段，RAG 无法默认过滤 900；旧版文档也未标「已弃用」。

修改建议

页头展示 version 徽章；旧版章节标注「已弃用」并链到 900 替代文档（详见 亲和原则 · 版本外显）。

2. 主推版本未声明

llms.txt / sitemap 未声明 CANN9.0.0 为主推版本；910beta、8.x 与 900 同权收录，检索排序无优先级。

修改建议

在 llms.txt 或 sitemap 中声明 canonical 源与主推版本（900）；旧版降权或标注 deprecated（详见 机器发现层 · 根因分析）。

3. 入库缺 version 字段

机器层 Front Matter 未强制 version——三模型检索与生成均未引用 …/900/… 路径，多见 8.x / 850 / beta 等旧版 chunk 混召。

修改建议

双轨交付时在 Front Matter 写入 version；RAG 默认 filter(version="CANN社区版 9.0.0")（字段模板见 页级元数据）。

4. 溯源不带版本信号

段末 URL / 脚注仅输出裸链接，不含 version、doc_id——开发者无法从回答判断命令适用于哪一版 CANN。

修改建议

脚注附带 version、doc_id 及来源 URL；检索与生成默认过滤 900（详见 检索阶段 · 根因分析）。
