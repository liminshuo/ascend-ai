分析洞察

  • 发现层部署了 ≠ 被消费七个模型里 5 个全程未请求 robots.txt / llms.txt / sitemap；仅 Opus、DeepSeek 后续补读。
  • 发现层被消费 ≠ 落到入门章节Opus 因 llms.txt 过大被截断；DeepSeek 虽在 AI 白名单内且读到 llms，但读取器约在 41.9KB 处截断，所见仅为文首营销索引；完整文件后方有算子文档条目（与 Opus 同类，截断点更靠前）。
  • 人读 URL 常不可抓，且可被 curl 证实七个模型均撞 CSR / 200 空壳；GLM、DeepSeek 用裸 curl 证明空壳是站点架构，不是 WebFetch 独有缺陷；Kimi 横向换 6+ 类路径仍全空。
  • 搜索摘要成了事实正文源Grok / GLM / DeepSeek / Kimi 最终主要靠引擎索引的官方摘要交卷；Sonnet 读通的正文却在 Disallow: /doc_center/ 下——可读通路与门禁错位。
