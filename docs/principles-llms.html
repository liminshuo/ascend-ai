llms.txt

llms.txt 概述

llms.txt 是一个放在网站根目录、专门给 AI 看的知识地图：它不列全站页面，只挑出真正有知识价值的 Markdown 内容（文档、教程、概念、API 参考等），整理成一份路径索引。

知识多时还能分册——根目录指向各子目录的分册，分册再列自己领域的条目，像一本书的目录分出章节。这样 AI 不必读完整个网站，而是先看总目录，再按需翻到某一册、某一节，精准取用所需知识。

它是自愿参考文件，AI 模型没有读取义务，与具备事实约束力的 robots.txt 有本质区别。

解决什么问题

AI 访问网站时难以判断哪些内容是有价值的知识，只能遍历全站、从杂乱 HTML 中提取，既耗费上下文又易遗漏重点。llms.txt 相当于网站主动提供的一份结构化知识清单，标明重点与层级，让 AI 以最低成本获取所需知识。

核心原则

  • 内容精选，不穷举仅保留最能代表本站的知识条目。上下文有限，条目过多反而会稀释重点。
  • 结构固定，按需分册1）按固定 Markdown 顺序书写：# 名称（唯一必填）、> 简述（可选）、若干 ## 章节，每节挂链接列表。
    2）页数多、需二次选择的面，写成子路径分册；一页可读完的，直接给 .md。让 Agent 先看总览，再深入分册。
  • 路径自描述清晰条目写成 - [标题](地址)，后接一句说明该页实际包含的内容。阅读清单即可判断相关性，无需先打开页面。
  • 索引精简可决策1）首份清单需足够小，读完即可判定下一步读取哪一条目。
    2）分册可以更大，但需整份可扫完；页数多到无法扫完时，用页名清单 .md 外包，不再为同一域叠加一层 llms.txt。
    3）全文拼接交由 llms-full.txt 承载，不替代精选索引。

根 llms 交付示例

根 llms.txt 交付件拆解

站点名与描述

  • 站点名用 # 写站点或项目名，是提案中唯一必填项。
  • 描述紧跟 > 引用块，说明这份清单的用途及如何获取平行稿。该部分可省略；若存在，应先读完再继续选节。

节名与描述

  • 节名每节一行 ## 标题。先扫这些名字，再决定进入哪一节。
  • 切分按内容面切块（文档、官网、博客等），而非照搬站点导航。
  • 节描述## 与链接之间可有一段纯文字，可选。

链接

  • 链接格式挂在对应 ## 下，一条一行，写作 - [标题](地址)，可后接 : 说明。标题用页面或分册名，不用 URL。
  • 链接指向.md 为单页，llms.txt 为分册。说明宜短，可选。

机器如何找到 llms

方式一：试约定路径

1）找根清单：手里没有地址时，直接打开站点根 /llms.txt。
2）找分册：打开根清单里写明的子路径（如 /docs/llms.txt），不要另猜。
3）两份都在时，用离当前页更近的那份：文档页用 /docs/llms.txt，官网页用站根。这一步不依赖 robots.txt 或 HTML 里先写过地址。

方式二：读 robots.txt

1）可在 /robots.txt 末尾仿 Sitemap: 加一行 LLMs.txt:，指向根清单。
2）分册不必写在这里。该字段不是官方规范，只作路径补充；没有这一行时，仍按方式一打开 /llms.txt。

前四行是 Mintlify 实文件。注释里的 LLMs.txt: 是建议补上的声明，不是该站现网内容。

方式三：读 HTML 源码

1）在 <head> 用 <link> 声明本页 Markdown，以及覆盖本页的清单。
2）Mintlify 官网首页 head 未写这两项，清单靠方式四。文档页有 Markdown 平行稿，仍无清单声明。

1）rel="alternate" 指向本页 Markdown（文档页现网已有）。rel="describedby" 指向覆盖本页的清单，建议补上。
2）官网首页应指向根清单，文档页指向分册。非 HTML 可改写在 HTTP Link: 头。不能替代页内真链。

方式四：跟页内入口

1）在 <body> 最前放一条真 <a href>，指向覆盖本页的清单。可用 sr-only 对人隐藏，源码里仍能跟到。
2）官网链根清单，文档页链本面分册。

本例是 Mintlify 官网首页，链到根清单。文档页应改为 /docs/llms.txt。

价值收益

  • 进站更省先拿到短清单，不必遍历全站 HTML 再判断哪些值得读。
  • 选页更准主推面在前，每条有一句说明，减少误开营销页、漏掉文档。
  • 跟页更净下一跳是分册或单页 Markdown，不是带导航和楼层的渲染页。
  • 大站更全文档面走分册，根文件撑不爆；需要全文时用 llms-full.txt，不挤占精选索引。
