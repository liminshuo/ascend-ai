部署 llms.txt 索引目录

llms.txt 概述

llms.txt 是网站根目录或文档根目录下的机器可读文本文件，用于向大语言模型 LLM 和 AI Agent 提供知识索引入口、内容结构和使用说明，帮助其发现和使用网站知识。与 robots.txt 用于声明抓取规则不同，llms.txt 主要用于知识内容导航。

当网站包含多个子站、产品线或业务板块时，可采用分册方式组织：根目录 llms.txt 作为总入口，指向各主题或业务模块的分册文件，由分册进一步提供对应知识内容。

llms.txt 通常位于网站根路径 https://{域名}/llms.txt，遵循该约定的 Agent 可主动读取并根据其中的索引访问相关内容。该文件源于 2024 年社区实践，目前并非强制协议。

具体原则

  1. 在网站根目录或文档根目录提供可访问的 llms.txt，作为 AI Agent 发现、理解和访问网站知识内容的机器可读入口。
  2. 根据知识内容组织索引结构，精选核心文档、资源和使用说明，避免简单罗列全站 URL。
  3. 保持根索引轻量可扫描；当内容规模较大或覆盖多个内容模块、产品线、业务板块时，采用分册方式组织，由根目录 llms.txt 指向各主题分册，避免单文件过长导致关键信息分散。
  4. 索引条目采用 - [标题](地址) 格式，并补充内容范围和适用任务说明；各级 llms.txt 保留必要上下文，帮助 AI Agent 无需打开页面即可判断内容相关性和访问路径。
  5. 随网站结构和内容变化同步维护 llms.txt 索引关系，确保入口有效、链接可访问、内容描述一致。

元素拆解

网站名与描述

  1. 网站名用 # 写网站或项目名，是必填项。
  2. 描述紧跟 > 引用块，说明这份清单的用途及如何按任务打开分册。该部分可选；若存在，AI Agent 会先读完再继续选栏目。

栏目名与描述

  1. 栏目名每个栏目一行 ## 标题。AI Agent 先扫这些名字，再决定进入哪一栏目。
  2. 切分按内容面切块（技术文档、开发者、软件与 CANN 等），而非照搬网站导航。
  3. 栏目描述## 与链接之间可有一段纯文字，可选。

链接

  1. 链接格式挂在对应 ## 下，一条一行，写作 - [标题](地址)，可后接 : 说明。标题用页面或分册名，不用 URL。
  2. 链接指向llms.txt 为分册，页面地址为单页。说明宜短，可选。

- [CANN 概述]标题 (https://www.hiascend.com/cann)地址 : 了解异构计算架构时打开。描述说明

机器如何发现 llms.txt

方式一：试约定路径

  1. AI Agent 按照约定路径，直接打开 /llms.txt。
  2. AI Agent 打开网站根清单里写明的子路径（如 /cann/llms.txt）。

方式二：读 robots.txt

  1. 在 /robots.txt 末尾仿 Sitemap: 加一行 LLMs.txt:，指向网站根 llms.txt。
  2. 分册不必写在这里。该字段不是官方规范，只作路径补充。

方式三：读 HTML 源码

  1. 在 <head> 用 <link> 声明本页 Markdown，以及覆盖本页的清单。
  2. rel="alternate" 指向本页 Markdown；rel="describedby" 指向覆盖本页的 llms.txt。
  3. 官网首页指向网站根清单，栏目页指向分册。非 HTML 可改写在 HTTP Link: 头。

方式四：跟页内入口

  1. 在 <body> 最前放一条真 <a href>，指向覆盖本页的清单。可用 sr-only 对人隐藏，源码里 AI Agent 仍能跟到。

预期效果

  1. 帮助 AI 理解网站内容分布，更快定位与任务相关的板块和知识入口。
  2. 支持按需读取索引和分册内容，减少一次性加载大量无关信息。
  3. 帮助 AI 判断内容相关性，减少访问无关页面。
  4. 便于各子站或栏目独立维护内容，同时保持统一的发现入口。

注意事项

  1. 避免将 llms.txt 设计为全站 URL 列表，应聚焦核心知识内容和高价值入口。
  2. 控制索引规模，内容较多时通过分册组织，避免单文件过长。
  3. 保持索引描述与实际内容一致，确保 AI Agent 正确理解内容范围。
  4. 确保索引链接公开可访问，避免引用受限或无效资源。
  5. 明确 llms.txt 与 robots.txt、Sitemap 的职责边界，避免混用。
