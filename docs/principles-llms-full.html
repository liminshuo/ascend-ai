部署 llms-full.txt 完整正文

概述

llms-full.txt 用于将网站或文档站中的知识内容整理成便于 LLM 和 AI Agent 直接读取的文本，包括页面正文和理解内容所需的必要上下文。与侧重知识发现和定位的 llms.txt 不同，llms-full.txt 更强调集中提供完整知识内容，让 AI Agent 无需逐个访问页面即可获取相关知识。

llms-full.txt 更适合内容规模较小、知识结构相对集中的网站。对于内容规模较大的网站，可根据实际情况采用 llms.txt 配合 Markdown 页面按需提供内容，避免将大量知识内容集中到单一文件中。

llms-full.txt 通常以 https://{域名}/llms-full.txt 作为公开访问入口，也可以根据实际内容组织方式提供对应的内容入口。目前 llms-full.txt 属于社区实践，并非强制协议。

具体原则

  1. 根据内容规模和实际需求选择内容提供方式；内容规模较小时可通过 llms-full.txt 集中提供完整知识内容，内容规模较大时可通过 llms.txt 索引和 Markdown 页面按需提供，避免单一文件过长。
  2. 以实际知识内容为主体，保留页面正文、代码示例、参数说明及必要上下文，避免仅提供摘要、链接或与知识无关的页面元素。
  3. 以独立页面为基本内容单元，保留页面标题、原始 URL 及页面正文，并通过标题、章节等层级保持内容结构，帮助 AI Agent 理解页面内容及上下文关系。
  4. 保持内容与实际页面同步，及时更新新增、修改或删除的知识内容，避免 AI Agent 获取过期或不准确的信息。

友商分析

大型网站通常包含大量文档和知识内容，不宜通过单一 llms-full.txt 承载全部知识内容，否则会带来较大的文件规模、维护和读取成本。因此，可采用 llms.txt 进行分层索引，并通过 Markdown 页面按需提供完整知识内容。

对于内容规模较小、内容范围较集中的网站，可将指定范围内的完整知识内容集中提供，可参考 Mintlify 的 llms-full.txt 实践。

Mintlify 的 llms-full.txt（部分）

元素拆解

文件标题

标识网站名称和文件用途。

文件级上下文

说明文件内容范围及相关知识入口。

文件级上下文不是页面内容，而是这份 llms-full.txt 的范围说明。Mintlify 当前文件明确说明营销页面、博客、Library、Customer Stories 和产品文档分别如何组织，并不等同于域名下的全部 URL。

页面内容单元

  1. 页面标题标识一个独立页面内容单元。
  2. 页面地址提供对应原始页面 URL。
  3. 页面正文保留页面正文及必要的 Markdown 结构，使页面内容保持完整和可理解。

机器如何发现 llms-full.txt

方式一：试约定路径

AI Agent 可尝试访问网站根目录的 /llms-full.txt。

方式二：读 llms.txt

AI Agent 可从 llms.txt 中提供的完整知识内容入口获取 llms-full.txt。

方式三：读 HTTP 响应头

网站可通过 HTTP Link 响应头提供 llms-full.txt 的位置，作为补充发现方式。

预期效果

  1. 帮助 AI Agent 直接获取集中整理的完整知识内容，减少在多个页面之间反复访问和拼接上下文。
  2. 保留页面正文及必要结构，为 AI Agent 提供更完整的上下文信息，减少信息遗漏或误判。
  3. 为网站内容提供统一的文本入口，降低因页面动态渲染或内容分散导致的信息缺失。

注意事项

  1. 避免将 llms-full.txt 简单理解为全站内容的无差别汇总，应根据实际使用场景确定内容范围。
  2. 避免为了追求内容完整而大量堆叠低相关或重复内容，影响 AI Agent 对核心知识的理解。
  3. 对于超大规模知识库，不宜强制通过单一 llms-full.txt 承载全部知识内容，可结合 llms.txt 和 Markdown 页面按需提供知识。
  4. 注意 llms-full.txt 并非所有网站都必须提供的文件，应结合网站内容规模和 AI 使用场景决定是否部署。
