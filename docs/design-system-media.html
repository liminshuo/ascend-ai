音视频内容可转写

原则定义

音视频里的讲解、步骤、参数与结论如果只留在声音或画面中，AI Agent 往往无法完整获取。需要把核心知识写成默认可读取的文本（标题、摘要、主要观点）；教程类可再用时间定位建立文本与媒体的对应关系。

逐字稿与字幕为可选补充，不能替代默认可见的要点。应保证关键知识完整、准确；若提供字幕、章节或时间戳，须与要点同步更新。

视觉规则

  1. 1标题用可读文字命名该音视频主题，默认露出，不依赖口播或画面烧录字。
  2. 2摘要概括建设目标、场景或结论，保证不打开播放器也能读到核心信息。
  3. 3主要观点展开后露出；列出可学会的步骤或结论。正文须留在初始 HTML，禁止点击后才注入唯一正文。
  4. 4时间定位（可选）教程、课程类建议提供；宣传片等无明确章节时可省略。有则用时间戳指向具体片段。
  5. 5相关内容（可选）有可跟进的方案文档、案例、答疑时再放；无延伸入口可省略，不放社交分发。

交互规则

  1. 默认收起首屏只露出标题、元信息、摘要与「展开要点」；主要观点及可选区块默认折叠，避免长列表占满首屏。
  2. 一次展开点击「展开要点」后露出主要观点，以及已提供的时间定位、相关内容；展开后可不再提供「收起」，避免打断阅读。
  3. 时间定位跳转若提供时间定位：点击条目将播放器跳到对应时刻并继续播放；无真实播放器时至少保持可聚焦的时间锚点链接。
  4. 相关内容跳转若提供相关内容：点击后打开对应文档/案例/答疑页（新标签或站内均可），不在当前页用弹层代替正文。

前端规则

  1. 可见文本节点标题、摘要、主要观点写成 HTML/Markdown 正文；若有时间定位或相关入口一并写成文本。勿只放在懒加载空壳或仅媒体轨中。
  2. 时间锚点（可选）提供时间定位时，用可跳转锚点或带时间参数的链接；媒体地址不能替代文本要点。
  3. 折叠不删正文可用 hidden / CSS 收起；展开区正文须在初始 HTML 中，禁止点击后才异步注入唯一正文。

示例如下：

<p>深圳龙岗以「数据 + 算力」建设智慧城市 2.0。</p>
<ul><li>了解智慧城市 2.0 建设目标</li>…</ul>

适用边界

适用于案例视频、教程讲解、安装答疑、产品演示等需要被 AI 检索、理解或引用的音视频。

装饰性背景音、氛围画面，且旁侧要点已覆盖同一信息时，不必逐一转写媒体轨。

字幕与完整转写可作补充，但不能替代默认可见的标题、要点与结论；音视频更新后应同步检查摘要、章节、时间戳与相关链接。
