记录来源：新开一个不带本页前文的 Grok 4.6 研究会话独立运行。下表按该轮自报的真实请求顺序完整转录，失败与重试均保留。前几步用了站外搜索引擎，检索器还额外拉了部分全文——这些不是对 hiascend 的主动 GET，表内单独标明。

回答

  1. 定位：Ascend C 是 CANN 面向算子开发的编程语言，原生支持 C/C++；写好的算子经编译器和运行时调度，跑在昇腾 AI 处理器上。产品页把初学者路径写成：先完成矢量算子核函数，掌握基础 API 调用。
  2. 准备环境：安装驱动固件和 CANN，装完以 CANN 运行用户执行 source $INSTALL_DIR/set_env.sh（商用包示例 /usr/local/Ascend/cann，社区版示例 /usr/local/Ascend/ascend-toolkit）。教程还要求 CMake ≥ 3.16。没有昇腾硬件时可先在 CPU 仿真里开发。
  3. 跟 Add 样例走一遍：算子分析 → 写核函数（样例多为 add_custom）→ 先 CPU 模式验证，再 NPU 模式验证。矢量侧典型流程是 Global Memory → Local Memory（DataCopy）→ 计算（如 Add）→ 再搬回；任务间用 EnQue / DeQue，内存用 AllocTensor / FreeTensor。
  4. 官方给出的下一步：产品页是代码样例 → 快速入门文档 → 入门课程，再进到工程化开发、编程模型、调试。技术文章指向《Ascend C 编程指南》。

〔推断〕把 CANN 商用版 8.5.0 当成「当前该跟的文档线」，是因为搜索排序靠前，官方并未写成必须跟这个版本。产品页「快速入门文档」是否就是 atlas_ascendc_map_10_0006.html，也是据标题匹配的推断，产品页本身没给出该 URL。0002 / 0006 的部分句子来自搜索摘要，因文档站多次返回 SPA 空壳，完整 HTML 正文本次未拿到。

模型
Claude Opus 5（无前文上下文的独立复测）
日期
2026-09-02
约束
只给原始提问，不提示任何发现路径或推荐起点；只使用 hiascend 官方资料

记录来源：新开一个不带本页前文的 Claude Opus 5 研究会话独立运行。下表按该轮自报的真实请求顺序完整转录，失败、超时与重试均保留。并行发出的请求按其自报批次标注。

回答

  1. 先建立概念：Ascend C 是 CANN 面向算子开发的编程语言，原生支持 C/C++ 标准规范；提供语言扩展层 C API、基于 Tensor 的基础 API、高阶 API、算子模板库和 Python 前端 PyAsc。
  2. 搞懂硬件抽象：CPU 是 host、NPU 是 device，经 PCIe 协同。核心是 AI Core，内含 Scalar / Vector / Cube 三个计算单元和 DMA 搬运单元；Global Memory 共享，Local Memory 带宽高但只有几百 KB 到 1MB。
  3. 掌握流水编程范式：矢量编程固定为 CopyIn → Compute → CopyOut 三个任务，对应逻辑位置 VECIN / VECCALC / VECOUT，用 EnQue / DeQue 串起来，Pipe 统一管内存。多核走 SPMD，所有核跑同一份代码，靠内置变量 block_idx 偏移切分数据。
  4. 记住四类 API 与核函数写法：计算类、数据搬运类（DataCopy）、内存管理类（AllocTensor / FreeTensor）、任务同步类（EnQue / DeQue）；核函数声明为 extern "C" __global__ __aicore__，用 kernel_name<<<blockDim, l2ctrl, stream>>> 调用，入门先把 blockDim 设为 1。
  5. 动手：按《CANN 软件安装指南》装好环境，执行 source ${install_path}/set_env.sh；取官方 quick-start 样例骨架，写核函数和 host 侧 main.cpp；用孪生调试先在 CPU 侧以 ICPU_RUN_KF 宏配 GDB 单步，再到 NPU 侧验证；最后 bash run.sh add_custom ascend910 AiCore cpu，换 npu 再跑一遍，用 md5sum 比对结果。
  6. 继续深入：CANN 文档聚合页（当前 9.2.0-beta.1，更新于 2026/08/12）「编程语言」栏下是《Ascend C 编程指南》，「API 参考」栏下是《Ascend C API》，「学习与教程」栏下有 CANN-learning-hub 和 CANN-samples。

〔推断〕把上面六步串成一条连续路径，是该轮把主页的三段式学习路径与两篇技术文章合并后的编排，官方并没有把它们写成一条线。

该轮自述的局限：始终没有读到《Ascend C 编程指南》「快速入门」章节的正文，只拿到目录级的《什么是 Ascend C》。上面所有实操步骤都出自两篇发表于 2023/08/30 的官方技术文章，而 CANN 文档当前版本已是 9.2.0-beta.1（2026/08/12）；文中 ascend910、leakyrelu_custom 等具体细节是否仍与最新版本一致，未经验证。

逐步实际请求

以下是独立复测自报的全部 18 次网络请求。失败、超时与重试单独保留；对已下载文件做本地检索不计入。

本轮路径

起手不是发现层，而是自己猜落地页 /ascend-c（JS 渲染，正文空）和一个凭印象拼的文档路径（超时）。之后才读 robots.txt，再顺 LLM-Policy 取 llms.txt，此后几乎全部内容都来自 llms-content/ 镜像。18 次请求里 9 次失败：4 个猜错的镜像文件名 404、3 个 sitemap 全 500、llms-full.txt 两次超时。

本轮发现：同一篇《什么是 Ascend C》，人读 HTML 返回 200 但正文为空，llms-content 镜像有完整正文，两侧不等价。文档聚合页的镜像把链接地址剥掉了，只留「了解详情」字样，因此无法顺着栏目跳到《Ascend C 编程指南》——该轮转而去猜镜像文件名，四次全部 404。robots.txt 里列出的 sitemap 有三个实测返回 500。

记录来源：claude.ai 网页对话，由使用者转贴。本页作者未复核这些 URL，其中 /doc_center/source/ 系列在本项目环境中未做验证。

回答

本轮读到的是 CANN 社区版 8.5.0 的入门教程正文，给出的入门路径如下。

  1. 环境准备：按《CANN 软件安装指南》安装驱动固件（仅昇腾设备需要）和 CANN 软件包，装完执行 source ${install_path}/set_env.sh 设置环境变量。非昇腾设备可以先用 CPU 仿真环境开发调试。cmake 需 3.16 及以上。
  2. HelloWorld（最小样例）：核函数里调用 AscendC::printf 打印信息，Host 侧走完初始化、设备设置、<<<>>> 发起计算、释放资源的完整流程。可用 bisheng 命令行或 CMake 两种方式编译，运行后能看到 8 个核并行打印。
  3. Add 自定义算子开发（正式入门主线）：先做算子分析，明确数学表达式与输入输出的 shape / dtype / format，确定核函数名和要用的接口（DataCopy、Add、AllocTensor / FreeTensor、EnQue / DeQue）；再做核函数开发，设计 TilingData 做多核切分，实现 KernelAdd 类的 Init 与 Process，走 CopyIn → Compute → CopyOut 三段流水；最后做运行验证，Host 侧用 acl 接口做设备初始化、内存分配和 Host↔Device 搬运，用 <<<>>> 调核函数并比对结果。编译同样是 CMake + find_package(ASC)。
  4. 后续方向：不熟悉多核并行与流水编程，看「编程模型」章节 atlas_ascendc_10_0012.html；已跑通样例想深入，看「矢量编程」章节 atlas_ascendc_10_0032.html。这两条本轮未展开抓取。

逐步实际请求

本轮路径

完全没有碰发现层：robots.txt、llms.txt、llms-full.txt、sitemap.xml 一个都没请求。直接猜专区页地址进站，撞上 CSR 空壳后换到文档站，再换到 /doc_center/source/…，靠目录树逐级下钻到正文。四轮里唯一一轮拿到了官方入门教程的完整正文。

本轮发现：官方展示层（/ascend-c 与 /document/detail/…）都是纯 CSR，「快速入门」「成长地图」在页面上是图片形式的 image map，文字不可抓；只有换到 /doc_center/source/… 才拿得到可解析的目录树和正文。而 robots.txt 里恰恰写着 Disallow: /doc_center/——本轮唯一读得通的那条路径，是被显式禁止抓取的。

四轮对照

同一个提问，四个模型走出四条不同的路径。没有一条是「标准答案」，这里只如实并列。

三次独立复测（Grok 4.6、GPT-5.6、Claude Opus 5）都不是从发现层起手：Grok 先用站外搜索，GPT 猜 /document 及旧版文档路径，Opus 猜落地页 /ascend-c。四轮里只有 Opus 读了 llms.txt，且没拿到《Ascend C 编程指南》「快速入门」章节正文；拿到官方入门正文的两轮（GPT-5.6、Claude Sonnet 5）一次都没读 llms.txt。Grok 复测则卡在文档站 SPA 空壳，完整正文主要来自产品页和技术文章。四轮起手与落点各不相同，站点不能假设模型会遵循同一套发现路径。

复测还暴露了几处站点侧的实际故障：3 个 sitemap 地址返回 HTTP 500，llms-full.txt 连续超时，人读 HTML 多次返回 200 但正文为空或只剩 SPA 壳，llms-content 镜像把栏目链接地址剥成了「了解详情」。
