章节锚点可引用

为了帮助 Agent 定位到任务相关小节而非整页含糊引用，每一节须有可引用的独立 URL；页内锚点导航指向该节，标题旁可辨识锚点。

适用对象

名称 说明
节级锚点 正文每一节必须提供带有 hash（#）的可引用 URL；标题旁须有清晰可辨识的「#」入口。常规落点为 H2–H3 标题旁，确保 Agent 能精准定位到具体小节。
页内锚点导航 页内锚点导航，条目必须指向对应的节级锚点（含 hash 的独立 URL）。常规置于正文侧栏或篇首。

适用场景

优先级 页面类型 说明
必做 多节手册 / 教程正文页 Agent 最常按节引用的事实页。
建议做 官网能力详情、长 FAQ 有多节结构时，建议补节级锚点和页内锚点导航。

设计UI调整

调整建议

  • 锚点默认可见 正文 H2–H3 必须可设节级锚点；标题旁「#」或等价标识默认露出，禁止仅悬停才出现。篇名 H1 用页面 URL，不另做页内锚点；H4 及以下按需开启。
  • 点击可复制锚点 点击「#」或复制控件，须一键复制含 hash 的完整 URL，并给出成功反馈（如 toast「已复制链接」）。
  • 页内锚点导航须可点 页内锚点导航须覆盖所有可锚点标题（至少 H2–H3），条目须为可跟链文字，不得做成纯文本列表。

文档内容调整

调整建议

  • 标题可独立理解 节标题须能单独读懂主题，避免「如下」「续」「说明」等无主题标题；节名同时作为锚点文案来源。
  • 目录文案与标题一致 页内锚点导航项字面须等于对应节标题，禁止缩写或另起一套叫法。
  • 跨页写清节名 引用写成「篇名 · 章节名」，禁止「见上文」「点击这里」等无法落到具体节的泛词。

前端调整

调整建议

  • 页内锚点导航须为真 hash 链 每个 TOC 条目点击后须跳转到带 # 的独立地址（如 …/page#section-2），并使用 a[href="#id"]；严禁仅用 JS 实现「页面下移但地址栏 URL 不变」的假跳转——无独立地址则机器无法按节抓取与引用。
  • 稳定 id 与首包一致 标题带稳定 id，与目录 hash 一致；id 按统一 slug 规则生成或 CMS 指定，不随渲染顺序漂移。首包 HTML 即含标题 id 与目录链，禁止依赖 JS 才注入。
  • 复制锚点可得 标题旁「#」或复制链接须输出含 hash 的完整 URL，与首包 id 一致。
