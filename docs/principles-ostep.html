流程步骤说明可逐步抓取

公开流程/逐步说明块的标题与说明须为可见文本进首包；状态用文字或 aria 标注；配图内字须旁注或改文本交付。后台向导见下方场景判断。

场景判断

场景1·公开流程 / 逐步说明块要做亲和

安装·认证·Quickstart 步骤条，或「加入开发者计划」等逐步权益格：每步标题与说明须为可见文本进首包；流程型还须标「进行中 / 已完成」。配图内字须旁注或改为文本交付。
对应页面：开发者入口（对标 Mintlify Quickstart Steps）

场景2·后台 / 登录后向导不做亲和 · 入库剥离

控制台表单向导、多步提交进度条等，指向非公开操作流程。入库管道宜标 data-llm-exclude 或直接剥离，别当可引用文档。

设计UI调整 · 场景1

调整建议

  • 每步标题 + 说明出可见文案：稿面为每步预留标题与短说明文本位，勿把「实物礼品 / 开发资源」等字只画进配图里。
  • 状态勿只靠颜色：「进行中 / 已完成」用文字或可辨标记标出，不只靠高亮色或数字圈。
  • 全步骤文案一并交付：各步标题与说明都要进设计交付物，勿只标注当前步、其余步留给开发自拟。

调整示例

示例1. 流程步骤：仅数字圈 → 可见文案

✗ 错误示范 · 只有数字圈 / 高亮色

1 （无标题 / 说明）
2 （仅颜色区分，无「进行中」文案）
3 （无标题 / 说明）

稿面只有数字圈和高亮色，没有步骤标题与说明文本位，也无法用文字标状态。

✓ 推荐做法 · 每步可见标题 + 短说明

1

实物礼品

完成认证可领取开发套件…

2

开发资源 进行中

开放文档、样例与工具链…

3

身份荣誉

开发者认证与社区标识…

要点：每步标题 + 短说明为可见文本；状态用文字标出；各步文案一并交付。

文档内容调整 · 场景1

调整建议

  • 统一命名：步骤标题与 MD / 正文使用同一套文案（如「实物礼品 / 开发资源」），避免 UI 与文档各写各的。
  • MD 平铺步骤：Markdown 版逐步写出标题 + 短说明（可附链接），作为页面步骤的平行可达入口。
  • 过渡补位：页面步骤 HTML 未达标前，用 llms.txt 临时列出逐步标题与说明；达标后以页面为准，去掉重复维护。

前端调整 · 场景1

调整建议

公开流程 / 逐步说明块的每步标题与说明须写入首包 HTML；静态抓取（不执行 JS）仍能列全步骤，并读出当前步状态（对标：Mintlify Quickstart Steps）。

具体要求：

  • 全量步骤进首包：全部步骤标题 + 说明一次性输出；勿只渲染当前步、其余步等切换才注入（开发者入口实测：可见权益名，源码常缺逐步文本）。
  • 标题 + 说明为可见文本：每步须有可读的标题与说明节点；禁只留数字圈，也禁把说明只放在配图里。
  • 状态可机读：「进行中 / 已完成」用可见文本或 aria-current 标注，勿只靠高亮色；须能回答「当前进行到哪一步」。

调整示例

示例1. 开发者计划逐步说明

✗ 当前问题 · 只有数字圈 / 配图，无 step 文本

<div class="o-step">
  <span class="step-index">1</span>
  <span class="step-index">2</span>
  <img src="…gift.png"/><!-- 浏览器可见「实物礼品」，源码无标题说明 -->
</div>

首包只有圈号或配图，静态抓取列不出逐步标题与说明，也答不出当前步。

✓ 推荐做法 · SSR 全量步骤文本

<ol class="o-step">
  <li>
    <p class="step-title">实物礼品</p>
    <p class="step-content">完成认证可领取开发套件…</p>
  </li>
  <li aria-current="step">
    <p class="step-title">开发资源</p>
    <p class="step-content">开放文档、样例与工具链…</p>
    <span>进行中</span>
  </li>
  <li>…身份荣誉…</li>
</ol>

每步标题 + 说明均为文本；当前步有状态标注。静态抓取即可逐步复述。
