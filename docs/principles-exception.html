失败状态可处理

概述

Agent 执行任务过程中可能出现失败、无结果或异常情况。若页面仅展示错误提示或空状态，AI Agent 难以判断失败原因及后续处理方式，无法继续完成任务。

失败状态可处理原则旨在明确表达失败原因、影响范围和可执行的处理路径，帮助 AI Agent 识别问题并采取下一步操作。

具体原则

  1. 失败状态应说明具体原因，避免仅使用「失败」「异常」「错误」等无法判断问题来源的描述。
  2. 空结果、权限不足、参数错误、服务异常等不同情况应分别表达，避免使用统一提示。
  3. 失败信息应提供可执行的处理建议，如修改参数、检查配置、重新执行或联系相关人员。
  4. 错误提示、接口返回信息和页面展示内容应保持一致，避免 AI Agent 获取到相互矛盾的状态信息。

示例 1 · kernel侧获取Tiling信息不正确

kernel侧获取Tiling信息不正确

现象描述

通过算子在kernel侧实现代码中添加PRINTF打印发现kernel侧获取的Tiling信息不正确。

比如下文样例，增加的打印代码如下：

C++ 
PRINTF("tiling_data.totalLength: %d tiling_data.tileNum: %d.\n", tiling_data.totalLength, tiling_data.tileNum);

打印的Tiling数据如下，全为0：

Output 
tiling_data.totalLength: 0 tiling_data.tileNum: 0.

问题根因

kernel侧获取Tiling信息不正确的原因一般有以下两种：

  • host侧计算Tiling的逻辑不正确
  • kernel侧核函数的参数未按照正确顺序填写

处理步骤

  1. 1

    参考如下示例，打印TilingData的数据，确认host侧序列化保存的TilingData是否正确。如果此时打印值有误，说明Tiling的计算逻辑可能不正确，需要进一步检查host侧Tiling实现代码，排查计算逻辑是否有误。

    C++ 
    std::cout<<*reinterpret_cast<uint32_t *>(context->GetRawTilingData()->GetData())<<std::endl;
  2. 2

    如果上一步骤中打印的TilingData正确，需要排查kernel侧核函数的参数是否按照正确顺序填写。参数按照「输入、输出、workspace、tiling」的顺序排布。

    C++ 
    #include "kernel_operator.h"
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling) {
    GET_TILING_DATA(tiling_data, tiling); // 获取Tiling参数
}

Markdown 书写

  • 1. 写清现象、根因与处理步骤；失败不只标红，给出可执行排查。

前端源码书写

  • 1. 现象、根因与处理步骤写进可见文本节点，给出可执行排查。

空结果明确说明原因

无结果状态应区分「确实不存在」「筛选条件过严」「数据暂不可用」等不同情况。

预期效果

  1. 帮助 AI Agent 判断任务失败原因，选择正确的恢复路径。
  2. 减少因错误状态信息不完整导致的误判和重复操作。
  3. 提升异常场景下任务处理的连续性。

注意事项

  1. 失败提示应描述实际问题，不应使用无法判断原因的笼统状态。
  2. 错误信息应避免仅依赖颜色、图标或状态码表达。
  3. 对可恢复的问题应提供下一步操作，对不可恢复的问题应明确说明限制原因。
  4. 不同失败场景应保持稳定、统一的状态命名，避免同类问题使用不同描述。
