失败状态可处理

解决什么问题

Agent 在空结果、报错或回执短词上停住或臆造下一步（如：结果区只有「-」、失败只标红点、只写「成功 / 失败 / 加载中」）。

核心原则

空因可写清，失败可处置

空列表、无匹配、无权限须写成可见文案：缺什么、为何空、下一步改什么；禁止空白或「-」单独表意。错误 / 失败须有含义、原因与官方下一步，不单靠颜色或图标。回执写成完整句（对象 + 结果；失败附处置；加载写正在做什么）。无官方结论时写「暂无官方处理说明」。怎样算做对见 任务结果可确认。

典型示例

空态写成可行动文案

区分无数据、无权限、筛选过空；写清缺失内容与可执行改法。

示例 1 · 筛选无结果

反面

CANN 软件包下载

芯片型号

Atlas 800T A2 Atlas 200I Atlas 300I

软件版本

8.0.0▾

筛选结果

-

  • 常见疏漏：只有「-」，无法识别空因与下一步。
正面

CANN 软件包下载

芯片型号

Atlas 800T A2 Atlas 200I Atlas 300I

软件版本

8.0.0▾

筛选结果

暂无匹配的软件包。请更换芯片型号或版本后再筛选。

  • 正确做法：写清「暂无匹配」与可执行改法。

示例 2 · 安装失败

反面
依赖安装
  • 常见疏漏：仅色点，无法识别失败含义与处置路径。
正面

依赖安装失败

  • 含义软件包校验和不一致。
  • 原因下载不完整或镜像损坏。
  • 下一步重新下载软件包后重试安装。
  • 正确做法：可见文案写清含义、原因与官方下一步。

  • 常见疏漏：只有「成功 / 失败 / 加载中」，后续动作不可读。

环境检查成功：驱动版本与 CANN 8.0.0 匹配。

依赖安装失败：校验和不一致。请重新下载软件包后重试。

正在拉取 CANN 8.0.0 软件包。

价值收益

  • 空结果可改条件Agent 知道缺什么、下一步筛什么，不会停在空白区。
  • 失败可引用官方路径含义与下一步可抓取，减少臆造排障。
