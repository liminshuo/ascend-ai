延伸指导

列表如何翻页

人刷到的，不等于 AI 默认拿到的；深页要有地址或等价入口。

场景说明

设计师要做一页同构多条目的公开列表：卡片墙、资源墙、案例墙或文档目录。条目超过一屏后，常见三种画法——底部分页、滚动续载且带「加载更多」按钮、或滑到底只有 loading 自动出卡。

对人来说，无限滚动可以只有转圈；对 AI / 静态交稿来说，稿面必须标出「第 2 批怎么到达」——页码 / 下一页，或默认可点的「加载更多」。仅有 loading、无可点控件，深页不可被稳定发现与引用。

  • 任务：同构多条目浏览
  • 页型：卡片列表、资源墙、案例墙、文档目录

方式选型

同一任务下三种拼法，按推荐程度自上而下。

公开列表优先方案 A。方案 B 只有在「加载更多」点进去是真的下一页地址、打开就能看到下一批卡时，机器才看得到；若只是点一下用脚本往本页塞卡，和方案 C 差不多。

亲和说明

亲和选型

  • 方案 A（推荐）：分页，第 2 页有自己的地址，打开就能看到卡
  • 方案 B（可接受）：样子可以是「加载更多」，但必须链到下一页真地址；不能只靠脚本往本页塞卡
  • 方案 C（不推荐）：只有往下滚 + 转圈，机器通常看不到后面的卡
  • 后台 / 个人中心列表可按可不做亲和
