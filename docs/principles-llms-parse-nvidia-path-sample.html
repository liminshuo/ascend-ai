安装与编程模型

Agent 回答问题时从根 llms 进：选站进文档分册，选产品进 CUDA 分册，再打开任务 .md。第二件事不在同一页，也不退回上一本 llms，只在产品分册里再开一页。两页 .md 拼齐后停。

本图问句：「Linux 上怎么装 CUDA，装完 thread、block、grid 怎么组织？」两件事不在同一页。

根 llms

  1. 1集团名用 # 写集团叫什么。
  2. 2集团说明用 > 交代这份清单是什么、下一步跟哪。
  3. 3站点名用 ## 按站点切块，先扫站名再进节。
  4. 4站点 llms 分册地址写成 - [标题](地址): 说明。本行链到下一本清单，不是正文。

文档站 llms 分册

  1. 1站点分册名用 # 写这份文档分册叫什么。
  2. 2站点分册说明用 > 说明这是各产品 llms.txt 的总册。
  3. 3产品名用 ## 按产品线切块，先扫产品名再进节。
  4. 4产品说明用 > 写这一条产品线是什么。
  5. 5产品 llms 分册地址写成 - [标题](地址)。本行链到 CUDA 产品册，下一跳还是清单。

文档站下 CUDA 的 llms 分册

  1. 1产品分册名称用 # 写本产品分册叫什么。
  2. 2产品分册说明交代这本产品分册覆盖哪些任务。
  3. 3节名用 ## 按任务切块，先扫节名再进节。
  4. 4文章写成 - [文章名称](文章地址)，地址以 .md 结尾，下一跳才是正文。本例是 Linux 安装页。

打开后 · 节级锚点

Agent 打开正文后，节级地址让引用落到哪一篇的哪一节，不必把整页当一条证据。

  1. 1页地址到 .html 为止是整页，标明引用出自哪一篇。
  2. 2节锚点URL 里 # 之后是节 id，用来落到这一节。和 ③ 同节，通常不是同一串字。
  3. 3节名人看见的节标题。引用落到这一节，不是整页，也不是某一段落。
  4. 4复制点标题旁 #，把带节 id 的完整地址交出去，下一轮从这一节读起。「已复制链接」只告诉人已经进剪贴板。
  • 节不进 llmsllms 目录只列到页面，不铺到节。页内的节，打开后再认。
  • 打开后有节址一篇里常有前言和要做的步骤。有节级地址，才能引用要做的那一节，而不是整篇。
  • 三处同节节标题、标题旁链接、页内目录指向同一个节 id。人读标题与 # 后的 id 对应同一节，不必字面相同。
  • # 号可复制点井号复制带节 id 的完整地址，可贴进对话。下次从该节读起，而不只拿到整页。

内容层级结构化

信息层级关系更易理解。Agent 无法仅凭字号、缩进或分割线理解章节的从属与并列关系。

方式一：文档源定义 H1–H5 标题

字号仅作视觉呈现，不承担结构语义。结构写在文档源里：Markdown 用 #，HTML 用 H1–H5。

主要场景

文档站、产品说明。页内任务树写在标题级别里。

Markdown 书写

HTML 书写

原则

用连续的 # / ## / ###，或真实的 H2 / H3，标明从属。级别连续，不跳级；不与编号叠用。

方式二：编号定义标题

结构由编号体现（1 / 1.1），不依赖缩进。

主要场景

安装手册、操作规范等长文。标题里写出 1 / 1.1，人和机器都能直接看见从属。

Markdown 书写

HTML 书写

原则

用 1 / 1.1 写出从属。1.1、1.2 同属「1 安装前准备」；不靠缩进，不与标题级别叠用。

  • 源里写结构从属写在标题级别或编号上，不靠字号、缩进或分割线。
  • 级别或编号文档站用 H1–H5（或 #）；手册用 1 / 1.1。两种选其一。
  • 不叠用不跳级不在 H3 上再写 1.1。标题级别连续，不在 H1 下直接挂 H4。

代码块语义化

执行类代码须标明语言、正文不含行号，并提供预期输出，以便识别、复制与核对。

  1. 1语言类型标明代码语言，供人与 Agent 识别。
  2. 2操作提供复制，及「咨询智慧助手」以针对该段代码提问。
  3. 3预期输出给出执行成功后的可见结果，供核对。
  4. 4移除代码行号正文不含行号，复制与入库不被污染。

常见问题

  • 块顶未标明语言，识别语言额外消耗 token。
  • 行号写入代码正文，抓取结果被污染。

亲和原则

  • 块顶标明语言写出 Bash 等语言名，避免额外推断。
  • 行号不进正文行号仅作对照，复制与入库不含行号。
  • 配预期输出写明执行成功后的可见结果。

图片语义理解

信息型图片须拆成可检索文字层与背景图，图意不独自存在于像素。

=
+
  • 文案独立成层角标、标题、入口写在 DOM / Markdown 正文，不烧进 PNG。
  • 背景不承载事实氛围图可空 alt；活动名与入口以文字入库。
  • 合成只给人看视觉上叠在一起，抓取时按文字 + 图分开读取。

robots.txt

根路径的许可声明，用来划定知识面抓取边界：放行该抓的，拦截不该抓的。没有强制准入力，部分 Agent（如 GPTBot）根本不请求。

遵循 RFC 9309：遵守该协议的爬虫进站直接请求根路径 /robots.txt，路径由协议固定，不靠站内链接或搜索。

Agent 回答流程机制图

  1. 1. 逐层进入

    先从根 llms.txt 进入，再按站点、产品逐层进入分册，最后打开具体 .md。

  2. 2. 整篇拿全

    读取时，一篇要一次拿全，不跳段、不截断。

  3. 3. 索引跳读

    在索引中跳读——只看模块标题和标题描述，对上的相关内容整段读取。

  4. 4. 循环补齐

    若回答不完整，回到 llms 索引找下一篇 .md，直到能完整回答为止。
