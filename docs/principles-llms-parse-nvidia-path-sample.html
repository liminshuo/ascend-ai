优化 robots.txt 许可声明，确保路径可达

场景

基于 RFC 9309 标准，爬虫请求根路径 /robots.txt，按许可声明访问可抓路径、避开不可抓路径，并跟随指引查找索引目录。

具体原则

  1. robots.txt 放行 Agent
  2. 写明允许与禁止访问的路径。
  3. 声明路径清单 Sitemap。
  4. 声明机器亲和 llms 访问路径。

核心价值

robots.txt 是机器进站的门禁与路标：既决定谁能进、谁能抓，也告诉进来的机器下一步该往哪走。

补充段落级锚点，提升定位精准度

场景

正常路径下，Agent 经 llms.txt 打开 .md，按标题跳读。

部分 Agent 不走索引、直接打开 HTML，此时靠段落级锚点才能读到指定段落。

具体原则

  1. 每个段落有稳定锚点 id，页内不重复。
  2. URL 中 # 后的片段与段落 id 对应且一致，指向同一段落。
  3. 页内右侧锚点导航指向同一段落 id。

核心价值

段落级锚点让 Agent 从「整页引用」变成「按段引用」——引用更准、扫描更少、续读更方便。

段落级锚点示例

以 MindIE 文本生成推理快速入门为例。打开正文后，URL 带 # 即可从这一段起读。https://www.hiascend.com/document/detail/zh/mindie/latest/quickstart/docs/zh/user_guide/quick_start.md#环境要求

  1. 1页地址告诉 Agent 引用知识来自于哪篇文章。
  2. 2段落锚点#环境要求 与该段标题同名，告诉 Agent 从这一段起读。
  3. 3段落名正文标题「2. 环境要求」，须与地址栏 # 后同名，Agent 才能落到这一段。
  4. 4锚点符标题旁的 #，把段落名写进 URL，机器从这一段起读。

HTML 第一次请求即含正文，不靠脚本事后写入

场景

Agent 打开人读页时，只能读到第一次请求返回的 HTML。脚本事后写入的那部分，对 Agent 来说就会缺失。

具体原则

  1. HTML 第一次请求即含正文。
  2. 不依赖脚本事后写入。

核心价值

让内容在第一次请求就完整到手——抓得到、不丢失、不等待。

场景

人读页上「查看详情」只给人点，也看不出要打开哪一篇。机器要跟进去，链接名称要写出去向，并带上绝对地址。

具体原则

  1. 链接写明锚文本，不用「查看详情」这种空名。
  2. 地址与人读页同一跳转目标，用绝对路径。
  3. 链接写在正文里，不靠脚本事后挂上。

核心价值

用标题写出文本结构

场景

人读页上标题靠字号和位置。机器要认出章节从属，必须在 Markdown 里看到 # / ##。

具体原则

  1. 页标题写成 #，章节写成 ##，与人读页同一层级。
  2. 不用加粗或字号冒充标题。
  3. 标题写在正文里，层级连续、不跳级。

核心价值

标题写成层级，机器才能切段、引用，不把正文当标题。

用标题层级写出章节从属

场景

Agent 读页面时，字号、缩进、分割线本身不表示章节从属。从属与并列只能从标题层级或编号里读到。

具体原则

UI设计原则

定义 H1–H5 标题格式，通篇文章统一。

Markdown 书写原则

章节从属以 # 的个数写入 Markdown。

源码书写原则

章节从属以标题标签或编号文本写入源码。

核心价值

执行类代码可识别、可复制、可核对

场景

Agent 拿到代码时，要识别语言、复制干净正文，并对照预期输出核对。行号若写进正文，复制和入库都会被污染。

具体原则

UI设计原则

代码块标明语言、提供复制，并给出预期输出。

Markdown 书写原则

代码以围栏语言标记写入 Markdown，正文不含行号。

源码书写原则

代码以带语言的代码块写入源码，正文不含行号。

核心价值

把可执行代码变成可识别、可复制、可核对的证据——让机器跑得动、对得上、不误判。

代码块示例

语言、复制和预期输出给人核对，干净正文给机器执行。

  1. 1语言类型标明代码语言，供人与 Agent 识别。
  2. 2操作提供复制，及「咨询智慧助手」以针对该段代码提问。
  3. 3预期输出给出执行成功后的可见结果，供核对。
  4. 4代码行行号写进代码正文，复制与入库被污染。
常见问题
  • 代码块顶未标明语言，Agent 查询语言耗费 token
  • 代码行有数字标记，导致代码抓取混乱
