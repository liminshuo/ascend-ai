示例路径可照抄参照

为了帮助 Agent 与用户都有可照抄路径，须提供与当前版本对齐的可复制标准示例（命令、请求、关键参数），并写清适用场景与前置条件。

适用对象

名称 说明 常见落点
标准示例块 可复制的命令、请求、关键参数；与当前文档版本严格对齐。 教程步骤旁、API 参考
场景与前置 写清适用场景、前置条件与预期结果，避免误套到错误环境。 示例块标题 / 说明行

适用场景

优先级 页面类型 说明
必做 安装 / 配置教程、API 调用说明 Agent 最常照抄命令与请求；缺示例则无法落地。
建议做 排障手册、参数对照页 给出可复现的最小示例，并标明适用版本。
可不做完整改造 纯概念说明、无命令的架构概述 无执行路径时，链到带示例的教程页即可。

设计UI调整

调整建议

  • 示例区块可扫读区分 示例区块必须位置固定、样式可扫读；须与正文步骤、验证区块视觉区分。严禁命令仅混在散文中而无独立示例块。
  • 适用与前置须可见 示例块必须写清适用场景与前置条件（可含预期结果）。严禁只写「按实际路径修改」却不给出默认可照抄底稿。

文档内容调整

调整建议

  • 给出可复制标准示例 提供命令、请求或关键参数的完整可复制示例，避免「按实际修改」却无底稿。
  • 版本对齐并写清前置 示例与当前文档版本严格对齐，随发布更新；说明适用场景与前置条件。

前端调整

调整建议

  • 示例正文默认可抓 首包必须输出完整示例正文；禁 JS 时仍可抓取。严禁依赖弹层或客户端拉取后才展示可照抄内容。
  • 多版本同源更新 多版本文档中示例随版本切换同源更新，避免串版命令。
