问题列表

  1. P0 未声明 Sitemap 绝对 URL。 robots.txt 中无 Sitemap: 行；公开页面缺少稳定发现入口。
  2. P1 未声明任何 Allow 规则。 仅有 10 条 Disallow，无 Allow:；放行范围未显式写出，只能依赖默认「未禁止即可抓」。
  3. P1 未声明 LLMs.txt 路径。 文件中无 LLMs.txt: 行；若需服务 AI Agent，缺少机器可读索引入口。
  4. P1 疑似误屏蔽公开内容路径。 /zhishi/、/guide/、/topic/、/theme/、/special/ 均被 Disallow，需确认是否本应对外发现。
  5. P2 Disallow 写法不统一。 部分行为 Disallow:/path/（冒号后无空格），影响可读与维护，但不影响多数解析器识别。

Part2. robots.txt 的优化建议

下列模板在保留「明确噪声路径」的前提下，补齐 Sitemap 声明与显式放行；知识向路径改为待确认注释块，避免在未拍板前继续硬屏蔽。绿色为建议新增，紫色为建议保留，黄色为待确认后决定是否放开。

建议模板（可直接作为改稿基线）

修改说明

  1. 新增 Allow: /：显式声明放行范围，再与 Disallow 对照。
  2. 新增 Sitemap: 绝对 URL：补齐公开页面发现入口。
  3. 统一 Disallow 空格写法：全部改为 Disallow: /path/。
  4. 保留噪声路径 Disallow：/common/、/tips/、/test/、/activity/share/、/s/。
  5. 知识向路径改为待确认：/zhishi/、/guide/、/topic/、/theme/、/special/ 先注释，确认后再决定是否放开。
  6. LLMs.txt 先注释：待索引可访问后再写入声明。
  7. 可选增加 Content-Signal：示例为 search/ai-input 开放、ai-train 关闭，取值需另行确认。

待确认事项

  1. 待确认 是否采用显式 Allow: /，再以 Disallow 收窄？
  2. 待确认 /zhishi/、/guide/、/topic/、/theme/、/special/ 是否应对外发现？若是，应取消 Disallow。
  3. 待确认 Sitemap 绝对 URL 应声明为哪一条（建议稿：https://www.huaweicloud.com/sitemap.xml）？
  4. 待确认 是否提供可访问的 /llms.txt？若是，再在 robots.txt 中声明。
  5. 待确认 Content-Signal 中 search / ai-input / ai-train 的取值策略。
  6. 待确认 主站与 support.huaweicloud.com 的开放策略是否需对齐，避免互相矛盾。
