代码块语义可读

概述

代码块是网页展示命令、配置和示例程序的重要载体，但视觉上完整的代码不一定能被 AI Agent 准确识别和直接执行。

代码源码可复用原则旨在明确代码语言、使用场景、源码边界及运行条件，使 AI Agent 能够准确获取代码，并生成可复制、可验证的回答。

具体原则

  1. 为代码块标注编程语言和使用场景，避免无语言标识或仅凭高亮样式判断代码类型。
  2. 将行号、复制按钮和提示文案等展示元素与源码分离，避免混入可复制内容。
  3. 正确处理 HTML 实体和转义字符，确保复制后的命令、配置或程序内容准确。
  4. 执行类示例应提供必要的运行条件，并根据需要补充预期输出或验证方式。
  5. 装饰性伪代码或仅用于说明的片段应明确其示意性质，避免被误认为可直接执行的源码。

示例 1 · 语言标注

代码块应明确标注语言，确保代码类型可识别，并便于正确复制。

反面

npu-smi info ascend-dmi -a

  • 常见疏漏：
  • 1. 块顶未标明语言
  • 2. 无法判断是 Bash 还是 Python
正面
Bash

npu-smi info ascend-dmi -a

  • 正确做法：
  • 1. 用围栏或 language-xxx 标明语言
  • 2. 不以高亮样式代替语言标识

Markdown 书写

  • 1. 围栏写清语言。
  • 2. 必要时注明文件名与场景。

正面

源码书写

  • 1. 使用 pre > code.language-xxx。
  • 2. 不要靠高亮样式猜语言。

示例 3 · 行号分离

行号仅作界面展示；复制结果不应包含行号。

反面

Bash

1 npu-smi info 2 ascend-dmi -a

  • 常见疏漏：
  • 1. 行号混入命令正文
  • 2. 复制后变成「1 npu-smi info」
正面
Bash

npu-smi info ascend-dmi -a

  • 正确做法：
  • 1. 复制结果不含行号
  • 2. 行号由前端渲染，不进文本节点

Markdown 书写

  • 1. 源稿不要手写「1 command」行号。
  • 2. 行号交给前端渲染。

正面

源码书写

  • 1. 行号用 CSS，不进文本节点。
  • 2. 禁止 highlighttable 绑行号。

预期效果

  1. 帮助 AI Agent 准确获取代码源码，减少语言识别错误、行号混入和特殊字符失真。
  2. 提供必要的运行条件及验证依据，提升代码回答的可复制性、可执行性和可验证性。

注意事项

  1. 代码截图或图片不能替代可复制的源码文本。
  2. 行号可以用于定位，但不应混入复制内容；提示文案和操作控件也应与源码分离。
  3. 高亮样式不能替代语言标注，应通过代码块的语言标识明确代码类型。
  4. 代码示例应区分可执行源码、伪代码和省略片段；必要时说明前置条件、占位符及省略内容。
  5. 预期输出应与实际执行结果一致；代码或运行环境发生变化时，应同步更新相关说明和验证结果。
