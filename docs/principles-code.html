代码源码可复用

解决什么问题

Agent 拿不到可执行的源码，只能看到被污染或残缺的示意。

核心原则

源码须干净可运行

代码块须标注语言与场景、分离行号、还原 HTML 实体；执行类示例配预期输出。装饰性伪代码且正文已覆盖同一事实时，可只作示意。

典型示例

语言、输出与行号分开

示例 1 · 语言标注

反面

npu-smi info ascend-dmi -a

  • 常见疏漏：
  • 1. 块顶未标明语言
  • 2. 无法判断是 Bash 还是 Python
正面

Bash

npu-smi info ascend-dmi -a

  • 正确做法：
  • 1. 块顶写成「Bash」等语言名

Markdown 书写

  • 1. 围栏写清语言
  • 2. 必要时注明文件名与场景
反面
正面

前端源码调整

  • 1. pre>code.language-xxx
  • 2. 不要靠高亮猜语言
反面
正面

示例 2 · 预期输出

反面

Bash

npu-smi info

  • 常见疏漏：
  • 1. 仅有命令，未配输出文字块
  • 2. 无法识别成功时长什么样
正面

Bash

npu-smi info

Output

NPU 状态为 OK，设备列表可见。

  • 正确做法：
  • 1. 预期输出写成可选中的独立文字块

Markdown 书写

  • 1. 块后提供预期输出文字
  • 2. 勿只写「见截图」
反面
正面

前端源码调整

  • 1. 输出块与命令同页首包
  • 2. 文本节点可选取
反面
正面

示例 3 · 行号分离

反面

Bash

1 npu-smi info 2 ascend-dmi -a

  • 常见疏漏：
  • 1. 行号混入命令正文
  • 2. 复制后变成「1 npu-smi info」
正面

Bash

npu-smi info ascend-dmi -a

  • 正确做法：
  • 1. 可复制内容不含行号
  • 2. 对照报错时行号须与正文分离

Markdown 书写

  • 1. 源稿不要手写「1 command」
  • 2. 行号交给前端渲染
反面
正面

前端源码调整

  • 1. 行号用 CSS，不进文本节点
  • 2. 禁止 highlighttable 绑行号

正面

价值收益

  • 命令可复制执行入库文本是干净源码，回答里的命令不会夹行号或未知语言。
  • 成功可核对预期输出写成文字后，Agent 能引用「成功时长什么样」。
