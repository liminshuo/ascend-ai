组件亲和

卡片

卡片是容器；标题、短述、真链要在卡面上，不靠整卡神秘可点。

原则概述

信息呈现

  • 分类：按排版分为文字卡、图标+文字卡、插图+文字卡、纯图卡；信息不得只活在图形里。
  • 三要素：卡面须有标题、一句话短述、可跟链目标，避免只有图 + 标题。
  • 明示：关键说明须默认可见；悬停展开仅作辅助，不得作为唯一信息出处。

交互实现

  • 真链：可点击卡片底层须为真实链接 a[href]，禁止整卡 onclick 或空壳注入后再填文案。

适用场景：适用于论文卡片、入口卡片、资讯公告等场景，标题与简短描述即可传达信息，无需图标或插图。

纯图卡片

纯图卡片卡面只有图形。是否做亲和，看它是否承载信息或可点击：会跳转或表达含义则要做；纯装饰则不必做。

要做亲和

适用场景：可点击的伙伴整机 / 产品图形入口、用图表达入口或状态但卡面无字的卡片。

原因：机器无法从像素推断「是什么、去哪」；无可见文案则无法入库。

1

解构

  1. 1图形：不得作为唯一信息出处；须补 alt。
  2. 2可见文案（必要）：卡面补标题（及短述）；不得只写在 alt / aria-label 里。
  3. 3真链（必要）：可点击处须为真实链接 a[href]。

修改

  • 补可见文案：卡面写伙伴名，不得只画在 Logo 里。

适用场景：纯装饰底图、不跳转、不表达独立语义的图形块。
