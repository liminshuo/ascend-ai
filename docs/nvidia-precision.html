NVIDIA · 找的准（版本·元数据）

召回时能否选对版本与时效。拆成三件事看：版本外显、失效显化、Schema——各自有适用场景；Schema 是手段之一，不是「找的准」的全部。

三个方面

01

版本外显

何时需要

产品世代与文档版次并行时：CUDA / 驱动 / 硬件世代、docs 多版本、SDK 发布说明。召回后要能一眼判断「是不是这代、是不是这版」。

友商观察

NVIDIA 产品线页偶见世代/版本措辞；文档级 SemVer 外显不统一，常靠路径或正文散落出现，缺页头统一徽章。

怎么做

规格与文档叶：页头给出可读版本/世代；多版本文档标明现行；与「找的到」互补——找得到还要找得准版本。

02

失效显化

何时需要

生命周期结束或接口弃用时：EOS / EOL、deprecated API、迁移公告。旧规格仍可被索引命中时，必须阻止当现行引用。

友商观察

部分规格/开发者页能检出弃用相关措辞，但并非处处有页顶废弃条；信号需结合具体规格页，不能假设全站统一。

怎么做

弃用与 EOS 页：首包顶条 + 替代/迁移入口；归档知识保留 URL 时，失效标记比静默删除更利于消歧。

03

Schema

何时需要

大站分面多、同名实体多时：用结构化类型（Product、TechArticle、FAQ）和版本/日期字段帮机器过滤，而不是只堆 ImageObject / Organization 壳。

友商观察

覆盖面相对大，但多数偏薄（站点壳、ImageObject）；含 Product / FAQ 等业务类型才算厚。找的准看厚度与版本字段，不看有无打勾。

怎么做

优先给知识/产品叶补业务 Schema 与版本相关属性；营销壳页有薄 Schema 不必当深度亲和证据。
