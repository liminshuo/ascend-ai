页面 HTML 可读

Agent 取到 HTML，并不等于读到正文。断点有四处：响应侧换脸或拦截、正文靠 JS 后注入、事实藏在 iframe / canvas / 图片里、声明缺失或整页过大被截断。任一处失守，模型只能退回搜索摘要。 本页界定人读 HTML 这一轨的可读契约；平行 Markdown 另见 机器消费轨道。

HTML 可读的契约要求

读表：表1 是契约总表；表2 是原则沙盘。「HTML · MD 共通」两边都要做；「仅 HTML」是人读 UI 形态。入口显化管「找得到」，不列入本沙盘。适用页面优先级见下节「适用场景」。

核心原则

  • 匿名可读不按 UA、地域或 Cookie 切换内容；正文页不得被收录策略或跳转拦在门外。
  • 首包完整禁用 JavaScript 时正文即完整可读；需入库的枚举内容随首包默认可见，深页用分页承接。
  • 承载可抓正文落在主文档文本节点里，不以 iframe、canvas、图片或 CSS 生成内容承载事实，也不做取词拦截。
  • 声明与体量显式声明 charset 与 lang；长文分篇，避免读取器中途截断。
  • 可校验以禁用 JS 的抓取结果为准绳；关键节点缺失即阻断发布。

适用场景

优先级 页面类型 说明
必做 文档站正文页、手册 / 教程页 Agent 核心事实源，须保证首包完整可抓。
建议做 文档列表、官网规格 / 能力详情页 存在可引用正文/规格表时，须保证首包语义化输出。
可不做完整改造 纯交互工具台、无入库正文页 须在收录策略（如 robots.txt）中明确划界，严禁越界收录。

典型做法

首包上 · 正文随 HTML 直出

最小合格示例 · 空壳 vs 首包正文

反面 
<body>
  <div id="app"></div>
  <script src="/bundle.js"></script>
</body>
  • 常见疏漏：正文由 JS 注入，静态抓取拿到空壳。
正面 
<body>
  <h1>Ascend C 算子开发</h1>
  <p>本文介绍算子开发基本流程…</p>
  <pre><code>…</code></pre>
</body>
  • 正确做法：标题、正文、代码块均在首包，无需执行 JS。

深页用分页，禁止无限滚动

反面
MindSpore Transformers
大模型套件
CANN
异构计算架构
ATC 模型转换
工具

向下滚动加载更多

  • 常见疏漏：关键条目只在滚到底后才注入，机器无法在首包枚举结果。
正面
MindSpore Transformers
大模型套件
CANN
异构计算架构
ATC 模型转换
工具
123
  • 正确做法：首包默认可见若干条目；深页用分页，不靠无限滚注入。

关键文字禁止懒加载

反面 
<section data-lazy-load="steps"></section>
<script>fetchSteps().then(render)</script>
  • 常见疏漏：步骤、警示由 JS 异步注入，静态抓取为空。
正面 
<ol>
  <li>下载 CANN 安装包</li>
  <li>执行安装脚本</li>
</ol>
<div class="note">注意：需 root 权限</div>
  • 正确做法：步骤与警示随 HTML 直出；图片可保留懒加载。

长表禁止虚拟滚动

反面 
可见行：第 1–15 行
（共 200 行，其余未挂载 DOM）
  • 常见疏漏：虚拟滚动仅渲染视口行，爬虫拿不到完整表。
正面 
<table>
  <tr><th>name</th><th>shape</th>…</tr>
  <!-- 全部 200 行完整输出 -->
</table>
  • 正确做法：所有行节点存在于首包 HTML，行列关系可完整提取。

执行要点

  • 主体服务端渲染标题、正文、代码、表格进首包；不依赖客户端注入主体。
  • 文字不懒加载步骤、警示等文字禁止异步注入；图片可保留 loading="lazy"。
  • 深页用分页禁止无限滚动与虚拟滚动只渲视口行；分批时每页 URL 可独立抓取。
  • 匿名可取不带 Cookie / Referer 的 GET 须返回 200 与完整正文；跳转不得落到登录页。

承载上 · 节点可抓、声明可校验

最小合格示例 · 事实不在抓不到的容器里

反面 
<iframe src="/spec-viewer?id=910"></iframe>
<canvas id="arch-diagram"></canvas>
<img src="/specs.png" alt="规格表">
  • 常见疏漏：规格与架构说明只存在于 iframe、canvas 或图片里，主文档抽不出字。
正面 
<table>
  <tr><th>算力</th><td>…</td></tr>
</table>
<figure>
  <img src="/arch.png" alt="">
  <figcaption>架构：主机侧下发任务…</figcaption>
</figure>
  • 正确做法：规格用真表；图示旁给等价文字。

最小合格示例 · 文档声明

最小合格示例 · 发布前禁 JS 校验

执行要点

  • 不跨文档承载正文不放进 iframe；确需嵌入时主文档另给文字版。
  • 不用绘制层承载canvas、图片文字、CSS content 不作事实源；图意转译见 图片内容转译。
  • 声明字符集与语言charset / lang 显式写出；弹层不把正文置 hidden。
  • 禁 JS 校验进门禁发布前校验 H1、正文字数、表格行数与代码块；缺失即阻断。

价值收益

  • 正文可被完整入库禁用 JS 也能读到标题、步骤与表格全部行，抽取结果与页面一致。
  • 抓取一次到位不必等渲染、滚动或点开，单次请求即可取全，漏抓与超时风险下降。
  • 改版不会悄悄退化可读性写进发布门禁后，模板升级会被回归校验挡住。
