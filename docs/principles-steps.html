步骤可按序列表执行

为了帮助 Agent 按序执行操作，有序步骤须用有序列表呈现，每项对应一个可执行动作，且对象指称须明确可消歧；禁止用散文、「步骤一：」段落、无序列表模拟顺序，或「它 / 上述」等模糊指代。

适用对象

名称 说明 常见落点
有序操作步骤 须用有序列表（1. 2. 3.）呈现；每项一个可执行动作，序号清晰可见。 安装、配置、排障教程
步骤内附件 代码块、表格与所属步骤 DOM 邻接，不跨块插入无关元素。 步骤下的命令 / 表
伪列表散文 禁止用「步骤一：」独立段落或无序列表假装有序；机器难还原顺序。 散文体操作说明

适用场景

优先级 页面类型 说明
必做 安装 / 升级 / 排障教程正文 Agent 最常按序执行；散文步骤易错序或漏步。
建议做 快速入门、能力试用向导 短路径同样用有序列表，便于 checklist 化。
可不做完整改造 无先后约束的并列检查项 无序检查可用无序列表；勿伪装成步骤编号。

设计UI调整

调整建议

  • 步骤必须用有序列表呈现 有序操作必须渲染为可见的 1. 2. 3. 列表，序号即执行顺序。严禁用「步骤一：」独立段落、散文堆叠或无序列表冒充有序步骤。
  • 每项只写一个可执行动作 列表每一项必须对应一个可独立执行的动作。严禁在同一项内串联多步（如「配置环境后再运行验证」）；多动作必须拆成多项。

调整示例

有序步骤用编号列表呈现

反面

步骤一：先安装 CANN Toolkit。

步骤二：然后配置环境变量，再运行验证脚本。

  • 常见疏漏：散文 / 「步骤一」段落，机器难稳定抽出顺序与单项动作。
正面
  1. 安装 CANN Toolkit。
  2. 配置环境变量。
  3. 运行验证脚本。
  • 正确做法：有序列表渲染；一项一动作，序号即执行顺序。

文档内容调整

调整建议

  • 稿面必须用真实有序列表 有序操作必须用 Markdown 1. 2. 3.（或等价有序列表）编写。严禁「步骤一：」独立段落或散文冒充顺序。
  • 每步写清对象、动作与预期结果 每项必须写明操作对象与动作；命令 / 表格必须落在所属步骤内并邻接。关键步须给出可核对的预期结果。严禁命令游离在步骤外。
  • 禁止模糊指代 步骤与邻接说明中，严禁用无法唯一确定对象的代词或短语（如「它」「这个」「上述」「前者」「类似地」）；必须写成明确名词或名词短语。

调整示例

有序列表自包含：命令与预期写在步内

反面 
步骤一：安装 Toolkit。

步骤二：配置环境。

source set_env.sh
  • 常见疏漏：「步骤一」伪列表；命令游离步骤外，切片难绑定「第几步执行哪条命令」。
正面 
1. 安装 CANN Toolkit。
   预期：安装目录存在。
2. 配置环境变量：
   ```bash
   source set_env.sh
   ```
   预期：无报错输出。
3. 运行验证脚本。
   预期：返回 success。
  • 正确做法：真实有序列表；一项一动作；命令与预期写在所属步内。

前端调整

调整建议

  • 首包必须输出真实 ol / li 有序步骤必须渲染为 <ol><li>；步骤内代码 / 表格必须嵌套在对应 li 内。严禁用连续 <p> 或平铺 <pre> 冒充步骤结构。
  • 伪列表必须检出告警 管道必须检测以「步骤一 / 第一步」等开头的连续段落伪列表；检出则告警并阻断或标记不达标。
  • 模糊指代宜告警 发布检测可维护禁用词表（它、这个、上述、前者、类似地等），在步骤正文中定位告警，提示改为明确名词。
  • 切片不得打断列表项 切片必须以整段 ol 或整项 li（含内嵌代码）入库；严禁在列表项中间切断，导致命令与步骤脱节。

调整示例

真实 ol：代码嵌在所属 li 内

反面 
<p>步骤一：配置环境。</p>
<pre>source set_env.sh</pre>
<p>步骤二：验证。</p>
  • 常见疏漏：伪列表段落 + 代码平铺；非 ol，切片易切断顺序与归属。
正面 
<ol>
  <li>配置环境变量：
    <pre>source set_env.sh</pre>
  </li>
  <li>运行验证脚本。</li>
</ol>
  • 正确做法：真实 ol；命令嵌在所属 li；切片保整项入库。
