操作可按序照抄

解决什么问题

Agent 无法按序执行，也抄不出可落地的命令（如：用「步骤一」散文冒充顺序、命令飘在列表外、只写「按实际路径修改」却没有默认可复制的完整命令）。

核心原则

有序可执行，命令可照抄

有先后的操作须用有序列表呈现，一项一个动作；命令、表格、警示嵌在所属步骤内。须另给与当前版本对齐的可复制示例（默认路径 / 请求 / 关键参数），并写清适用与前置。禁止用散文假冒步骤，也禁止只有「按实际修改」而无完整命令。无先后的并列检查可用无序列表。在线试跑见 可交互示例。

典型示例

有序步骤用编号列表

序号即执行顺序；一项一个动作。对象写成明确名词，不要「它 / 上述」。

示例 1 · 安装步骤

反面

步骤一：先安装 CANN Toolkit。

步骤二：然后配置环境变量，再运行验证脚本。

  • 常见疏漏：散文 / 「步骤一」段落，机器难稳定抽出顺序与单项动作。
正面
  1. 安装 CANN Toolkit。
  2. 配置环境变量。
  3. 运行验证脚本。
  • 正确做法：有序列表渲染；一项一动作，序号即执行顺序。

示例 2 · 步骤内附件

  2. 配置环境变量。
  3. 运行验证脚本。

注意：升级前请备份。

给出默认可复制命令

写成能直接粘贴运行的完整命令（含默认路径），并写清适用 / 前置。不要只写「请按实际路径修改」。这不是预期结果；做完如何核对见 任务结果可确认。

安装和环境配置

编程开始前请配置毕昇编译器环境变量，路径请以实际安装为准。

source …/set_env.sh

  • 常见疏漏：只写「按实际路径」；无默认可照抄命令与适用 / 前置。

价值收益

  • 顺序可执行Agent 能抽出第几步做什么，命令绑在所属步骤上。
  • 命令可照抄有默认可运行的完整命令，不必猜测安装路径或「按实际修改」。
