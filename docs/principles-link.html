链接去向可自描述

为了帮助 Agent 在切片中仍能识别跳转目标与用途，链接与可点入口须用描述性锚文本写出去向，站外来源须可识别；禁止 chunk 里只剩「LINK」「点击这里」。

适用对象

名称 说明 常见落点
操作作用域 相同操作不同作用域须从文案区分（如「删除全部」与「删除此行」），禁止两处都只写「删除」。 表格操作、批量操作
导航入口 菜单、下拉、页脚须写出栏目或对象全称，禁止「简介」「更多」或纯图标。 侧栏、顶栏下拉、页脚
行动入口 链接与按钮须写出文档或任务名，禁止仅写「了解更多」「查看详情」。 卡片链接、主按钮
站外 / 下载链 跨域链接标注来源；下载链写明文件类型、平台或用途。 正文引用、资源列表

适用场景

优先级 页面类型 说明
必做 文档正文、教程步骤中的跳转与下载 切片最常带走锚文本；泛词会丢去向。
建议做 侧栏 / 顶栏菜单、页脚、产品卡片 CTA 导航与行动入口脱离上下文也须能判断目标。
可不做完整改造 页内锚点目录、已有完整标题的邻篇链接 目标名已在邻近标题写出时可适当缩短，但仍忌「点击这里」。

设计UI调整

调整建议

  • 入口字即去向 可点处的字须写出对象、作用域或栏目；整卡可点时，卡面上仍须有去向字。
  • 泛词不可独自表意 禁止仅写「删除」「了解更多」「更多」等泛词；脱离上下文也须能判断点去哪里。

设计专项完整说明见 链接去向自描述。

文档内容调整

调整建议

  • 描述性锚文本 可点击文本须能独立描述目标或操作；禁止「点击这里」「更多」「链接」作锚文本。
  • 站外来源与用途说明 跨域链接标注来源域名；下载 / API 链可附文件类型、大小或用途。

调整示例

描述性锚文本

反面 
完整样例请参考
[点击这里](https://gitcode.com/…)。

← chunk 只剩「点击这里」
  • 常见疏漏：泛词锚文本，切片无法识别跳转目标。
正面 
完整样例请参考
[HelloWorld 完整样例（GitCode）]
(https://gitcode.com/…)。

← 目标名可自描述
  • 正确做法：锚文本写出文档 / 样例名；可附来源。

站外标注 + 下载用途

反面 
- [示例仓库](https://gitcode.com/…)
- [下载](https://…/toolkit.run)

← 无域名 / 无用途
  • 常见疏漏：站外与下载链无来源、平台或体积说明。
正面 
- [示例仓库（↗ gitcode.com）](…)
- [CANN Toolkit 离线包
  （Linux x86_64，约 3 GB）](…)

← 来源 + 用途可抓
  • 正确做法：站外标域名；下载写清对象、平台与体量。

前端调整

调整建议

  • 锚文本写入 a 标签 正文 <a> 内须有描述性文字；下载 / API 链可在旁附用途说明，不替代锚文本本身。
  • 站外自动标识 跨域链接注入外部标识、rel="noopener noreferrer" 与 data-external="true"，供切片识别。
  • 切片拼接锚文本与 URL chunk 收录「锚文本 → 绝对 URL」；站外标注域名；裸 URL / 泛词锚文本降权。

调整示例

a 标签完整语义

反面 
<a href="/helloworld">点击这里</a>

← 泛词 + 相对路径
  • 常见疏漏：锚文本无意义，切片难还原目标。
正面 
<a href="https://gitcode.com/…/helloworld"
  data-external="true"
  rel="noopener noreferrer"
  target="_blank">
  HelloWorld 完整样例（GitCode）
</a>

← 锚文本 + URL 可直读
  • 正确做法：描述性锚文本 + 绝对 URL；站外带 data-external。
