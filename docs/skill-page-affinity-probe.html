页级亲和探针

Skill ID：page-affinity-probe · 依据：全量原则25项

核心命题

对单个文档/产品 URL 做 AI 亲和实测：以全量原则 25 项为准，有子原则则分项判定；只测本页实际出现的组件。输出含状态表与 problems 同构块的 HTML 报告。不是全站 25 项清单审计，也不使用旧「35 条」口径。

下载 Skill 查看示例报告

输入

字段必填说明
页面 URL是（主）文档页或产品页
站点 / 产品名建议写进报告页眉
关注组件可选如图、表、代码、Tab、折叠；缺则按页上实际出现的测
本地 HTML条件抓不全 / 需登录时

检查与判定

  1. 映射本页组件 → 相关原则/子原则；无关标「不适用」。
  2. 状态仅用：达标 / 待改进 / 缺失 / 不适用；子原则单独行。
  3. 可证伪证据来自 DOM/属性/平行资源可达性，不编造未出现组件。

工作流

  1. 输入：页面 URL（优先）+ 建议产品名；可选关注组件或本地 HTML。
  2. 拉取与识别：列组件清单；对照全量原则 25 项与子原则。
  3. 实测：图/表/代码/锚点/警示/步骤/验证/平行 md·llms 等碰到什么测什么。
  4. 成稿：状态表 + 若干问句/证据/洞察/根因块；导出 PDF。
  5. 落盘：双写 docs/ 与 report-serve/。

报告结构

  1. Part1：组件清单 + 子原则状态表。
  2. Part2：problems 同构实测块（问句→证据→洞察→根因）。
  3. Part3：优先改法。

边界

  1. 不替代 robots-txt-audit / sitemap-audit / llms-txt-generate / html-to-md。
  2. 全站 25 项清单审计若另有 Skill，与本 Skill 分工：本 Skill 只做单页。

如何使用

  1. 下载 Skill 包，解压到 Cursor 的 .cursor/skills/page-affinity-probe/（或个人 skills 目录）。
  2. 准备文档/产品页 URL；可选注明产品名与关注组件。
  3. 在对话中调用，例如：按 page-affinity-probe 探针 https://support.huaweicloud.com/qs-codeartsagent/codeartsagent_qs_0002.html。
  4. 输出 HTML 报告并双写；可对照示例：CodeArts VS Code 快速入门探针。
