什么是双轨交付

双轨交付：同一套事实，两份交付——人读 HTML，机器读 Markdown。

解决什么问题

Agent 打开人读 HTML 时，常因 CSR 空壳或复杂排版无法提取结构完整的事实正文，只能拿到碎片化、不可验证的片段。人读页可保留视觉设计，但机器侧需提供一份可直取、且与人读同源的事实正文。

核心原则

  • 同源同文人读页与机器基于同一套事实，随发布同步更新。HTML 首包已含可解析正文时，平行 Markdown 作为增强项；人读页为 CSR 空壳时，须提供机器可读正文。
  • 机器可直取取事实以机器为准。打开即可读到正文，不依赖人读页渲染，也不设登录或浏览器门槛。

双轨交付示例

Markdown 交付件拆解

机器轨只写事实正文，对照 Mintlify editor.md：不写导航和营销楼层，与人读页同一套事实。

页顶索引

## Documentation Index 指向「文档目录」这一导引区块。完整清单见下一行：https://www.mintlify.com/docs/llms.txt。先浏览全站有哪些页面，再继续阅读本篇。

标题与导语

对照左侧人读页：# Editor overview 是页面主标题，两轨使用同一句文案，不为机器另起名字。标题下的引用块对应导语段落。下方的 <Card> 代表「开始教程」入口：人读页是带毕业帽图标的卡片，机器轨则直接写出卡片标题、跳转地址 href 以及卡片内说明。这样，Agent 无需读取图标，也能识别出教程入口及其学习内容。

章节正文

对照左侧人读页：## How the editor works 对应章节标题。四条要点都用加粗句起头，后面跟完整说明，和人读段落一一对应。绿色提示框写成 <Tip>，框内的 Reset editor 仍是可跟链接，不藏在展开或悬停里。

图意转写

## Editor layout 为章节标题。机器轨保留布局图可抓取地址，alt 写出图中要素；下方列表用句子说明 Top bar、Sidebar、Home、Publishing 的功能。Agent 无需读图即可理解分区。

相关链接

Related topics 三条链接在机器轨中以 ## Related topics 呈现，href 指向对应 .md（Editor overview、Glossary、术语表）；文案与人读页一致，图标不作语义载体。

Agent 如何找到机器轨

方式一：从 llms.txt 发现

Agent 尚未落到单页时，会先打开站级 llms.txt，按清单逐一获取各页 Markdown。清单中需写明对应 .md 的地址。

若清单指向分册而不是单页，再打开分册，按其中条目获取各页 Markdown。下面这一条对应 Editor overview。

方式二：试路径

Agent 已经拿到人读 HTML 的地址时，会在同一路径后面加上 .md 去试。这是站点私有的路径约定，Mintlify 即此做法：两份地址只差一个后缀。

方式三：读 HTML 源码

Agent 也会读人读页的 HTML 源码。建议在 <head> 里声明平行 Markdown，让源码里就能跟到，不必只靠猜后缀。

canonical 确认本页人读地址；rel="alternate" 标出平行 Markdown。这是源码声明，不能替代下面的页内真链。

方式四：跟页内入口

HTML 正文中提供「打开 Markdown」入口，指向本页平行稿。此为内容层兜底，细则见页级 Markdown。rel="alternate" 可并存，不单独作入口。

价值收益

  • 人读与机器兼得人读页可以继续做视觉设计；机器仍能打开一份干净正文，不等人读页渲染。
  • 引用对得上两边同一套事实。模型无论走摘要还是抓正文，引用都能对上、也能回查。
  • 入库更干净只收可核对的事实正文，导航、海报和转化楼层不进问答。
