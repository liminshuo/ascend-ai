双轨同源可消费

Agent 打开人读 HTML 时，常因 CSR 空壳或复杂排版拿不到正文。为解决此问题，需遵循双轨同源的内容契约：机器轨（Markdown / 纯净正文）供 Agent 直读，HTML 轨供人类浏览，两边事实必须一致。 入口挂载详见 Agent 入口显化，本页仅界定机器侧的内容。

双轨消费的契约要求

核心原则

  • 同源同文人读页与机器轨基于同一套事实，随发布同步更新；不按 User-Agent 身份（UA）切换内容。
  • 先判可抓性HTML 首包已含可解析正文或语义化表格时，平行 Markdown 作为增强项；若人读页为 CSR 空壳，机器轨为必做项。
  • 选型与入口分工整页事实对应页级 Markdown；单块架构图 / 规格表对应块级 Markdown；需绕开鉴权时，提供免鉴权的静态镜像。入口挂载方式见 Agent 入口显化。
  • 声明对齐页内地址、llms-content 与 llms.txt 条目，均与真实文件同管道生成，避免出现「跟声明走却 404」（GPT 实测见 七模型详情 · GPT）。
  • 可直取机器源支持 HTTP GET 直接获取正文；仓库页、登录墙及需 Referer 的网关，不计入已获取机器轨。

典型做法

何时必须开机器轨

  • 反面 · 只有人读轨
  • 人类浏览 /document/detail/…/*.html
  • 机器直读 缺失 · CSR 空壳
  • 正面 · 同源双发
  • 人类浏览 /document/detail/…/*.html
  • 机器直读 /doc_center/source/…/*.md

执行要点

  • 空壳即必做发现层实测中，七个模型均撞人读 CSR 空壳（见 发现层实测 · 表2，频次 7/7）。此时没有机器轨，Agent 只能拼搜索摘要。
  • 机器轨可直 GET路径须免鉴权、免滑块；不要把「页面上能看见」当成「机器能取到」。

何时可免平行文件

  • 反面 · 首包已可抓仍强行双写
  • 风险 两份正文易漂移，维护成本高
  • 正面 · 人读轨即机器可用
  • 首包 HTML <table> / 正文可解析
  • 平行 MD 可省略；需要时再加增强轨

执行要点

  • 可免的是第二份文件不是「可读事实」。事实必须仍在首包里。
  • 可免的是入口控件，不是机器源本身发现层已收录且可跟到该页时，页内不必重复堆入口控件。若首包 HTML 本身已是可解析事实源，它就是机器可用的那一轨，仍须同源同文；只有另立平行文件时，才谈得上「省略这份文件」。

执行要点

  • 同一来源导出改人读正文必须同步机器轨；构建对比事实正文，不一致则阻断发布。
  • 命名对齐页内 llms-content、发现层条目与磁盘文件名一致（同上，参见「声明与文件对齐」）。
  • 机器轨只写事实导航、分享、营销楼层不进 Markdown / 纯净正文。

与入口页的衔接

  • 整页平行稿如何在页头露出「打开 Markdown」→ 页级 Markdown
  • 架构图 / 规格表如何在块标题旁挂 MD 徽标 → 块级 Markdown
  • 整站清单如何从单页接回 llms.txt → 站级导读

价值收益

  • 空壳不再断粮人读展示可以继续用 CSR / 强视觉；Agent 仍有可 GET 的事实正文。
  • 一套真相同源同文避免「摘要派」与「正文派」各执一词，引用可复核。
  • 入口与轨道解耦入口组负责找得到，本页负责找得到的东西等价可消费；改造时可分轨推进。
