双轨交付

同源双发——人类访问 HTML 渲染页，机器读取由同一来源导出的 Markdown / 纯净正文，并在页面提供可见的「机器可读版本」入口。 可达 · 页面可发现 · 序号 12 · 对应 问题论证 · 交付载体不适配 · 设计专项见 机器可读入口可发现。

对象

对象 描述
HTML 渲染页 人类浏览轨：由同源内容渲染的文档页（如 .html）。
Markdown 源文件 机器读取轨：由同一来源导出的 Markdown / 纯净正文（如 /doc_center/source/），可直接访问、不被鉴权拦截。
「机器可读版本」入口 人类页上的可见文字链接，指向对应 Markdown / 纯净正文，禁止仅用图标暗示。

设计UI调整

调整建议

  • 页级 Markdown 入口：文档页头提供复制 / 打开本页 Markdown 的入口，文案写清动作；仓库源码链不能单独替代。
  • 内容块平行 MD：架构图、规格表等强视觉块须配平行 Markdown；标题旁轻量 MD 徽标只作入口，不替代正文。
  • 可免场景：整站 llms.txt + 稳定本页 .md 直链可跟到、或首包已有完整可抓 HTML 表时，可不重复堆徽标。

前端调整

调整建议

  • Markdown 源文件对外可访问：/doc_center/source/ 路径下的 Markdown 文件必须可直接访问和下载，不做鉴权拦截，配合 robots.txt 放行和 llms.txt 索引。
  • 两轨内容一致性校验：构建流程中对比 Markdown 源文件与生成的 HTML 内容，检测是否存在渲染层单独修改导致的内容不一致，不一致则阻断发布。
  • Markdown 文件元数据同步：Markdown 文件头部的 frontmatter（版本号、日期、状态等）与 HTML 页面 <head> 中的 meta 和 JSON-LD 字段保持自动同步，由构建管道统一处理，不依赖人工双向维护。
  • HTML 源码优化：不使用 .md 的渲染页面，采用 .html 渲染页面，需尽量在前端输出，不通过服务端动态渲染。

调整示例

1. 同源双发链路

Before · 仅 HTML 渲染页

/document/detail/…/operator_dev.html
← 唯一入口，带导航/样式，不适合机器直读

After · 同源双轨

        ├──► 人类：/document/detail/…    渲染页（带导航/样式）
        └──► 机器：/.../operator_dev.md  管道导出 Markdown

2. 机器可读入口与 Markdown frontmatter

Before · 无 Markdown 源

  <!-- 无机器可读入口 -->
</footer>

  <a href="/doc_center/source/…/operator_dev.html">
    机器可读版本（source HTML）
  </a>
</footer>
