轮播帧语义噪声 部分可抓 · 不宜入库

轮播帧语义噪声指 OCarousel / Banner 多帧运营位上的标题、摘要与图意——对人读是发现入口，对 RAG 则常混入活动招募与营销口号，不宜当作产品规格知识。 以 昇腾社区首页 为例：静态 HTML 中多帧 banner-title 已可抓（好于只渲染当前帧），但内容偏活动/认证引流，图意与规格未转写为可引用正文。

问题实测

1. 向模型提问

我在看 昇腾社区首页（www.hiascend.com/zh），首屏轮播最近几帧分别在讲什么？哪一帧和 CANN / 算子开发最相关，点进去应该去哪一页？

3. 问题洞察

大模型的回答指向 4 点结论：

  • 多帧标题可抓全：6 帧 indicator 与 banner-title 已在静态 HTML，未切换也能复述。
  • 内容是运营噪声：问卷调查 / 创新大赛 / 认证 / 社区任务等是活动引流，不是 CANN API 规格。
  • CTA 跟不了链：「了解更多 / 前往认证」多为 button，源码无 href；友商 NVIDIA 轮播 CTA 带可跟链接。
  • 半成品：能列口号，答不出「点进去应去哪篇文档」。

根因分析

视情况：白名单产品 / 文档入口帧须标题 + 摘要 + 链接；运营 / 活动口号帧默认剥离。详见 亲和原则。

轮播帧语义噪声的核心原因：人在浏览器和「查看网页源代码」里都能看见首页 6 帧 banner-title，但这些是活动 / 认证 / 招募口号，和产品规格混在同一抓取层；CTA 又是无 href 的 button——能复述口号，却当不成可靠规格，也给不出文档深链。

1. 运营帧与规格混层入库

问题：打开社区首页，用「查看网页源代码」核对：6 帧 indicator（参与8月问卷调查 / 昇腾AI创新大赛2026 / 高校专业赛 / 推理开发者认证 / CANN社区任务 / 昇腾智能助手上线）与各帧 banner-title 都在。Agent 能复述标题，但这些是活动引流与认证入口，不是 CANN / 算子 API 规格。探针问「哪一帧和算子开发最相关、应去哪一页文档」时，易把认证口号答成产品能力，或给不出文档深链。

修改建议

轮播根节点默认加 data-llm-exclude="true"，不入 llms / 知识库白名单；规格事实落到可引用文档页，轮播只做人读发现。若保留个别产品入口帧，须单独白名单并附一句话事实摘要。

证据 · 能抓到 ≠ 该当规格

帧角色分流（示意）

<!-- ✗ 运营帧：可抓，宜剥离 -->
<p class="banner-title" data-llm-exclude>昇腾AI创新大赛2026</p>

<!-- ✓ 产品入口帧（若保留）：标题 + 摘要 + 文档链 -->
<a href="/document/…/cann/">CANN 开发指南</a>
<p>异构计算架构安装与算子开发入口。</p>

看得见的 Banner 标题，不等于可以当规格 chunk。

2. CTA 是 button，跟不出落地 URL

问题：各帧 CTA（了解更多 / 立即查看 / 前往认证 / 立即参与等）源码是 button.o-btn.banner-actions-item，带 data-ha-clickid，没有 href；跳转靠脚本。探针问「点进去应该去哪一页」时只能复述按钮文案。友商 NVIDIA 首页轮播帧带可跟 a[href]，禁 JS 仍能给出落地链。

修改建议

跳转型 CTA 改为 a[href] + 可见锚文本；或在轮播旁提供「本页推广入口」文本清单（标题 → URL），不依赖滑动与点击。

证据 · CTA 本来应该长这样

期望写进网页的帧 CTA（示意）

<p class="banner-title">昇腾AI创新大赛2026</p>
<a class="o-btn banner-actions-item" href="/activity/…">了解更多</a>
<!-- ✗ <button type="button" class="o-btn">了解更多</button> -->

标题能抓到，落地 URL 也要能跟；否则发现入口半成品。

3. 缺帧角色标记与平行清单

问题：6 帧在 HTML 平铺，管道无法区分「活动 / 招募帧」与「产品入口帧」；配图口号也无 alt / 图注转写。一律入库即噪声。若 llms.txt 也没有「帧标题 → 角色（运营|规格）→ URL」对照，AI 没有退路核对「这一帧是什么 / 不是什么」。

修改建议

信息帧补有区分度的 alt 或帧下短说明；策展按帧类型分流。临时可在 llms.txt 列出各帧角色与落地 URL；页面 SSR 达标并以文档页承载规格后，以页面 / 文档为准。
