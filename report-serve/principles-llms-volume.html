分册 llms.txt

什么是分册 llms

分册 llms.txt：某一面（文档站、博客、资料库）自己的目录。从根 llms 链过来，文件名仍是 llms.txt，只摊开这一面的条目。叶子是各页 .md，不再套一层 llms。

解决什么问题

文档站、博客页数多，若全部写进根 llms.txt，根文件会过大、中途截断。分册把这一面的目录单独放，根文件只保留一条入口。

核心原则

  • 由根文件显式挂接分册地址写在根 llms.txt 里，Agent 顺着打开。不要让 Agent 去猜 /docs/llms.txt 是否存在。
  • 只摊这一面一本分册对应一个产品线或一个站点面。只写标题、地址、一句说明，不含文章。
  • 这一面也要读得完分册比根长可以，因为只摊一面。仍须整份能扫完节名和条目。页多到扫不完，用页名清单 .md 外包（如 _llms/…md），不要在分册里写正文。
  • 一层为止分册里列各页 .md，不再链下一本 llms.txt。页里再链其他 .md 是正文相关链接，不是发现层。
  • 直接可达分册 URL 打开即可读，不设跳转或登录门槛。

文末 Indexes

语言或产品线的页清单仍用 .md 索引，不用第三层 llms.txt。llms.txt 只负责换面（根 → 分册）；分册内部再切语言/页清单，跟全站平行稿一样用 .md，避免 Agent 把「同一面的页表」误读成「又一本要选的分册」。

约定路径

分册跟它所服务的那一面走，地址必须写进根 llms.txt，不能只靠猜测。

价值收益

  • 根文件读得完大面不堆进根清单，避免截断。
  • 分册扫得完只摊本面目录；再长则外包页名 .md，不写正文。
  • 这一面找得到页分册里每条都能跟到 .md。
  • 不再猜路径分册地址只出现在根文件里，Agent 顺着打开即可。
