手册如何分栏

跨页跳转用菜单；同页章节用锚点——别混用一种壳做两件事。

场景说明

文档阅读壳常见是左侧目录 + 右侧正文（FAQ、开发指南、产品手册）。侧栏看起来都叫「目录」，其实在干两件不同的事：换一篇文档（换 URL），或仍在本页滚到某一章。

对人来说，点一下都能到；对机器来说，要分清「跟链去另一页」还是「同页锚点」。跨页用菜单真链；同页章节用锚点（可与菜单并存）。同页多块切换用树可以，但各块文字要默认可读，别点了才注入。

  • 任务：文档阅读壳
  • 页型：左侧目录 + 正文；FAQ / 开发指南 / 产品手册

方式选型

同一壳下三种用法，按推荐程度自上而下；选哪一种，先问侧栏项是「去另一页」还是「滚到本章」。

换文档优先真链菜单。本篇章节用锚点，可与菜单一起用。看起来像目录、实际无链接或点了才出正文，机器跟不动。

点侧栏之后，脚本才把正文塞进来。静态抓取时侧栏跟不动，正文也读不到。

或：侧栏既不像换页菜单（没真链），也不像本篇锚点（没章节 id）——一种壳硬做两件事，两边都不达标。

侧栏每一项要说得清：是「去另一页」还是「滚到本章」。伪菜单、泛词、点了才注入，机器枚举不了手册。

亲和说明

亲和选型

  • 方案 A（推荐）：换一篇文档 / 换 URL → 侧栏菜单真链；项名与目标页标题对齐
  • 方案 B（可接受）：仍在本页切章节 → 锚点（可与 A 并存）；同页多块切换 → 树，各块默认可读
  • 方案 C（不推荐）：看起来像目录、实际无真链；点了才注入正文；一种壳两边都不达标
  • 交稿时先标清：每一项是「去另一页」还是「滚到本章」
