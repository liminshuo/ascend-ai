更新日期可外显确认

为了帮助 Agent 判断内容是否过期、可否优先引用，页头与列表须把「最近更新日期」写成可抓取文字（如 YYYY-MM-DD），禁止仅靠「新」色标或排序暗示时效。版本号与生命周期见 版本号可外显确认。

适用对象

名称 说明 常见落点
页头更新日期 正文页须展示最近更新日期（YYYY-MM-DD）；可与版本号同排，但日期不得缺失。 文档页头元信息区
列表时效字段 文档列表 / 搜索结果条目须写出更新日期；禁止仅用「新」角标或置顶顺序暗示。 文档列表、栏目页
机器可读日期 可见日期须与 dateModified / <time datetime> 同源，供切片与 Agent 直读。 Frontmatter、meta、JSON-LD

适用场景

优先级 页面类型 说明
必做 文档站正文页、手册 / API 页 引用池事实页；无更新日期则难判是否过期。
建议做 文档列表、搜索结果、栏目索引 条目级日期便于 Agent 排序与择新。
可不做完整改造 纯静态政策页、极少变更的法律声明 可写首次发布日；变更极少时注明「长期有效」即可。

设计UI调整

调整建议

  • 日期写成字，不靠色标 页头与列表须展示可读更新日期；「新」角标可保留，但不得替代日期文字。
  • 日期与版本同排可辨 若同时展示版本号，用分隔符同排（如 v8.0.0 · 更新 2026-03-12），避免只留版本、省略日期。

文档内容调整

调整建议

  • 稿面写明最近更新日期 Frontmatter / 页头文案使用 ISO 日期（YYYY-MM-DD）；禁止「近日更新」「最新」等不可比较表述。
  • 可见文案与机器字段同源 页头「更新 2026-06-15」须与 dateModified / 发布流水一致，避免人机两套日期。

前端调整

调整建议

  • 用 time / meta 交付日期 可见日期用 <time datetime="YYYY-MM-DD">；同步写入 dateModified meta 或 JSON-LD。
  • 切片抽取旁路文字 入库切片抽取页头 / 列表中的日期文本，不依赖仅视觉编码的「新」色标。

调整示例

页头日期用 time 与 meta 同源

反面 
<h1>算子开发入门
  <span class="badge">新</span>
</h1>

← 无 datetime / meta
  • 常见疏漏：色标不可机读，切片拿不到可比日期。
正面 
<meta name="dateModified"
  content="2026-06-15">
<time datetime="2026-06-15">
  更新 2026-06-15
</time>
<h1>算子开发入门</h1>

← 可见 + 机读同源
  • 正确做法：time datetime 与 meta 同源输出最近更新日期。
