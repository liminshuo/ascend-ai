验证区块可独立执行

为了帮助 Agent 形成执行闭环，任务型内容须提供独立的验证 / 检查章节或用例，给出可对照的输入与输出；验证方法尽量使用命令或代码块，拒绝「观察结果是否正确」等模糊描述。判据写法见 预期结果可对照确认。

适用对象

名称 说明 常见落点
验证 / 检查章节 独立 H2/H3 或固定区块，视觉与普通正文区分，可被单独定位。 安装指南末尾、配置完成后、排障收尾
验收用例 给出可对照的输入与输出（或命令与样例回执），形成闭环入口。 冒烟清单、Quickstart 验收、回归用例
可执行验证方法 优先命令 / 代码块；禁止仅写「观察是否正确」等无法执行的描述。 CLI 检查、API 探测、健康检查脚本

适用场景

优先级 页面类型 说明
必做 操作类教程、安装部署、排障手册 缺独立验证入口时，Agent 无法闭环核对。
建议做 API Quickstart、配置变更、能力开通页 配置独立「验证」节或用例，附输入 / 输出。
可不做完整改造 纯概念、架构说明、无执行路径的概览 可链到操作页的验证节；一旦有任务步骤仍须补入口。

设计UI调整

调整建议

  • 「验证」作固定章节 使用固定 H2/H3 标题（如「验证」「检查结果」），样式与普通正文区分，便于扫读定位。
  • 输入与输出成对呈现 验证块内命令 / 请求与样例回执相邻展示，形成可对照的视觉单元。

文档内容调整

调整建议

  • 提供可执行验证方法 用命令或代码块写出检查步骤；附成功 / 失败判断标准，拒绝模糊「观察是否正确」。
  • 输入与输出成对给出 每个验证用例写清输入（命令 / 请求）与输出样例或关键判据，与步骤列表联动。

调整示例

验证节用命令而非模糊描述

反面 
## 后续

请观察结果是否正确，
确认无误后进入下一章。

← 无法执行 / 无法核对
  • 常见疏漏：无验证入口、无可对照 I/O，闭环断裂。
正面 
## 验证

**输入**
```bash
curl -s localhost:8080/health
```

**输出（成功）**
```json
{"status":"ok"}
```

← 可对照闭环
  • 正确做法：独立验证节 + 命令 + 成功样例。

前端调整

调整建议

  • 验证块进入首包 验证章节在 SSR / 首包输出，禁 JS 仍可读；可结构化导出为 checklist 字段。
  • 语义标注验证区 可用 data-verify / data-checklist 等标注，并与步骤列表联动。

调整示例

验证区可机读标注

反面 
<div class="note">
  确认环境正常即可。
</div>

← 无验证语义
  • 常见疏漏：切片无法识别验证入口与 checklist。
正面 
<section data-verify
  data-checklist="health">
  <h2>验证</h2>
  <pre>curl -s .../health</pre>
  <p data-expected>{"status":"ok"}</p>
</section>

← 可切验证 chunk
  • 正确做法：首包输出；data-* 标验证与预期联动。
