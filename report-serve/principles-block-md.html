块级 Markdown

当用户只要某一层架构或某一张规格表时，这些关系与表值往往锁在图或复杂排版里。从渲染页拿内容，容易只看到截图、丢失结构。 Agent 处理这一页时——不管是 Cursor 这类工具的单次调用，还是企业内部 RAG 的批量摄取——整页 Markdown 太粗，解析渲染 HTML 同样难切到这一块。

Agent 是如何取到块级 Markdown 的

Agent 取某一层或某一张表的纯净正文有三个层级，按理想尝试顺序排列：

通用发现层（主路径）

按行业通用约定，直接探测根目录或文档站子路径下的 llms.txt，从中 Fetch 该块地址。这是跨站点通用的社区惯例，优先级最高。

站点私有发现层（需声明）

按站点私有约定的块级稳定 URL 取稿（如将 page.html#architecture 改写为 page-block.md）。前提：此规则属于私有约定，Agent 没有凭空尝试的理由，必须已在 llms.txt 或站点公开规范中明确声明后才会生效。若无公开声明，此路径置信度降级，不能作为确定主路径。

内容层（兜底入口）

已抓到这篇 HTML 时，直接跟从楼层标题旁「打开块 Markdown」的真链取稿。落点在楼层标题同一行，写在 main 里。

这一层是唯一不依赖任何前置声明的确定路径：无需探测 llms.txt，无需知道站点私有改写规则，只要这篇 HTML 落到了 Agent 手里，真链就一定在。

核心原则

  • 优先级与确定性是两回事跨站通用的 llms.txt 是理想主路径（优先级最高）；站点私有块级 URL 规则仅在公开声明后才具备高置信度。但只有「打开块 Markdown」内容层是唯一确定成立的路径：它不依赖任何前置声明，只要拿到 HTML 就能发现，绝不能用整页 Markdown（见页级 Markdown）代替这一块。
  • 打开是真链「打开块 Markdown」必须画在楼层标题旁，且是 main 里的真实 <a>。# 锚点、无字图标、页级入口和仓库源码链都不能单独替代这条真链。

执行要点

  • 指向约定路径href 必须指向该块平行 .md 的绝对地址及精确锚点（如 …/platform-stack.md#ascend-platform），不能只写指向整页的 # 锚点。
  • 名称写在链上有文字位就写成「打开块 Markdown」或「打开 Markdown」。只用图标时，在 <a> 上写 aria-label="打开块 Markdown"（可兼 title），img 的 alt 留空。避免「更多」「MD」「AI」冒充打开。
  • 保持首包真实机器不点这条链，可跟的是源码里的真 href。必须落在首包 main 已有的 <a> 内，不要用 CSS background-image 画图标，不要悬停才插入 DOM。

价值收益

  • 人能打开该块干净稿楼层标题旁可见「打开块 Markdown」，点开即是这一层或这一张表的平行 .md，不必在整页长文里翻找。
  • 未改写块级 URL 也能接住入库主路径仍是约定块级地址或 llms.txt。已经抓到 HTML、不会猜块路径时，main 里的真链仍能跟到该块 .md，保证跨层、跨表问答不断裂。这层兜底无需 Agent 认识任何私有规则，是稳定生效的物理锚点。
