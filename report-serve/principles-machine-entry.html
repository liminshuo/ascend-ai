站级导读

尽管 /llms.txt 是行业惯例，但并非强制协议。实测中，多数 Agent 会绕开它，直接从搜索命中或外链落到人读 HTML。如果页内没有回站级清单的线索，模型就会被困在单篇正文里。 标题旁蜜蜂只做一件事：打开本页镜像 Markdown（与页级 Markdown同一事件）。站级导读另走两条：本页稿最前的 Agent 导读，以及源码里对人眼隐藏、指向 llms.txt 的真链。

Agent 是如何发现入口的

主路径 · 发现层

按约定直接获取根目录或子路径的 llms.txt。

兜底入口 · 内容层

未走发现层时，从本页稿最前的 Agent 导读、或 HTML 里隐藏的 llms.txt 真链回到清单，再批量抓取邻篇。标题旁蜜蜂不承担这件事，它只指向本页 Markdown。

核心原则

  • 蜜蜂只打开本页稿H1 旁图标与页级 Markdown、块级 Markdown 同一事件：真 <a href> 指向本页（或本块）镜像 Markdown。
  • 站级清单另给 Agent本页稿最前写导读，源码首包用 sr-only 真链指向 llms.txt（对齐 Mintlify）。二者都不绑在蜜蜂上。发现层主路径见发现层部署。

价值收益

  • 人眼拿到本页稿标题旁蜜蜂始终打开当前页镜像 Markdown，不必猜站级清单。
  • Agent 仍能回到目录绕过 /llms.txt 落到单页时，稿面导读和隐藏真链仍能接回发现层，再扩抓邻篇。
