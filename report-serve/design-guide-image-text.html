视觉层

图意文本化

图中的结构与结论须写成可抓的文字；图只辅助。

原则概述

原则：信息不烧图

  • 图是背景，文字是信息主体。承载语义的关键信息（标题、状态、字段名、入口文案）须以 DOM 文本呈现，禁止仅烧入图片。装饰性图形可例外，纯氛围图且已有文字入口时可不做文本化。
  • 图中层级关系、模块名、结论等结构性信息，须通过文字链接或图注交付；alt 可作为等价替代，但不替代图注的展示功能。图注应提炼图中结论，而非描述画面本身。

对 AI 的好处

  • 语义信息落在可抓取文字上，AI 无需从像素中猜测含义；关键字段和入口可直接跟链入库，避免整块内容不可解析或被误读。

场景示例

示例 1 · Banner信息须文本化

核心原则：图是背景，文字是信息主体，别把字烧进图里。

例外情况：只作首页氛围图，且活动页或列表页已另有文字入口时，可不做文本替代。

反面
  • 缺文本替代：标题、角标均烧入图片，源码中无可读文本，且无独立描述层。 查看示例来源
正面

鲲鹏创新大赛

鲲鹏高性能计算全球挑战赛

立即报名

必有项

  • 标题：须为叠于 Banner 上的 DOM 文案，禁止烧入图片。
  • 链接入口：按钮或链接均可，文案与跳转去向须在 DOM 中明确，禁止烧入图片。

可选项

  • 角标：纯装饰可烧图；若承载信息（如活动名称、状态标签），则须为 DOM 文本。
  • 描述：如有副文案，须为 DOM 文本，禁止烧入图片。

示例 2 · 官网结构图须文本化

核心原则：层名、产品名、入口须为可抓取的文字链接；层级关系写进 alt。

例外情况：旁白已写出同一套结构，或图只装饰时，可不做文本替代。

反面
  • 缺文本替代：仅有图片，无可抓取文字与链接。 查看反面来源
正面
  • 文字链接：层名、产品名、入口须为可抓取的文字链接，而非图片热区。 查看正面来源
  • 图像替代文本（不在UI层体现）：alt 写入：「自上而下为行业应用、应用使能、AI框架、硬件使能（CANN）、昇腾系列硬件。应用使能含 MindSDK、MindCluster / MindSpeed、MindEdge / MindIE；框架层并列。MindStudio、CCAE 纵向贯穿各层。」。

示例 3 · 文档架构图须文本化

核心原则：图名和图注写成独立文字，结论不要只烧进图。

反面

图 Kernel 调度示意图

  • 缺文本替代：图下无图注，图中结论仅存于像素，不可抓取。
  • 有歧义：图内标注烧入图片，机器无法获取「Host 下发」与「分核」之间的关联关系。
正面

图 Kernel 调度示意图

图注：Host 进程运行在 CPU，负责发起计算任务。任务下发到 NPU 后，先进入任务调度器，再由调度器分配到 AI Core 0、AI Core 1 … AI Core N-1；各核承接子任务并并行执行，核数可按 N 扩展。

必有项

  • 图名：须以独立图题形式呈现，禁止仅以文件名代替。
  • 图注：须以图下文字形式交付图中结论，禁止仅烧入图片。

可选项

  • alt：若图注已完整传达信息，alt 可与图注一致或简略概括。
