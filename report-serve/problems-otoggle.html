Toggle 版本矩阵首包缺失 视情况

查看测试页面

Toggle 版本矩阵首包缺失指下载/版本页 Toggle 若映射 OS、架构、安装方式等选型，完整 option 矩阵须在首包可读；纯 UI 筛选则宜 exclude。 视情况：映射下载包 / 版本落地页的选型 Toggle（型号 / 架构 / 安装方式等）须把完整 option 矩阵写进首包，本页根因分析主要针对这类；纯表单筛选、不承载包表的 Toggle 入库宜标 data-llm-exclude 或剥离。 以 固件与驱动 为例：产品型号 / 架构 / 安装方式 Toggle：浏览器可见，首包无全量 option，选中态靠 ?ids= 与 __NUXT_DATA__。

友商测试

友商案例被测对象html 可抓取原因
NVIDIACUDA 下载OS/架构 Toggle 矩阵React props可抓全Operating System / Architecture Toggle 的完整 option 树（含 Distribution、Version、Installer Type 与 releases 下载 href）嵌在静态 HTML 的 data-react-props JSON；target_os / target_arch 映射选中态，禁 JS 可解析全量矩阵。
昇腾社区固件与驱动版本矩阵无静态列表动态筛选抓不全浏览器可见产品型号/架构/安装方式 Toggle 与包列表，但静态 HTML 无完整 option 矩阵；选中态靠 ?ids= 与 __NUXT_DATA__ 恢复，禁 JS 抓不全。

根因分析

视情况：映射下载包 / 版本落地页的选型 Toggle（型号 / 架构 / 安装方式等）须把完整 option 矩阵写进首包，本页根因分析主要针对这类；纯表单筛选、不承载包表的 Toggle 入库宜标 data-llm-exclude 或剥离。

Toggle 版本矩阵首包缺失的核心原因：人在浏览器里能看见固件与驱动页的型号 / 架构 / 安装方式 Toggle，但「查看网页源代码」里没有完整 option 矩阵——只有 ?ids= 与 __NUXT_DATA__ 恢复当前选中态，AI 列不全全部选项与对应下载 URL；友商 NVIDIA CUDA 下载页虽按钮靠 React 画，但 OS/Architecture 嵌套树已写在首包 data-react-props。

实测证据 · 昇腾无全表 vs 友商首包有树

友商 NVIDIA：浏览器可见的选型 Toggle

左图友商 Toggle 人眼可见，且全树在源码 JSON；昇腾侧源码只有当前 ids，没有全表。

「查看网页源代码」对照

<div data-react-class="NestedOptionSelector"

       "Linux":{"x86_64":{…},"arm64-sbsa":{…}},
       "Windows":{…}},"releases":{…}}'></div>

1. 选型 option 矩阵没有写进网页源码

问题：打开固件与驱动页，用「查看网页源代码」核对：看不到产品型号 / 架构 / 安装方式的完整 option 文本列表。浏览器里能点切换，但选项要等脚本按当前 ?ids= 恢复——禁 JS 时枚举不了矩阵，也答不出探针要的「各选项对应下载 URL」。友商 NVIDIA CUDA 把 Operating System / Architecture 及嵌套 Distribution→Version→Installer 写在 data-react-props，禁 JS 仍可解析。

证据 · 矩阵本来应该长这样

期望写进网页的选型矩阵（示意）

<div class="download-toggles">
  <button type="button" data-ids="…">型号 A</button>
  <button type="button" data-ids="…">型号 B</button>
  …架构 / 安装方式同理…
  <a href="…/firmware-drivers?ids=…">当前组合包表</a>
</div>
<!-- 或首包 JSON：{options:[…], packages:[…]} -->

未选中项可以藏起来，但全量选项与映射必须还在首包。

修改建议

SSR 全量 Toggle option（可读 label + ids 或落地 href）；或像 NVIDIA 一样把完整矩阵 JSON 写进首包 data-*，并文档化解析方式。

2. ?ids= 只表达当前选中，形成半成品

问题：URL 上的 ?ids=d802,…,AArch64,online_apt_get 能恢复「此刻选了什么」，甚至 __NUXT_DATA__ 里可能带当前包片段；缺的是「还有哪些型号 / 架构 / 安装方式可选」的全表。所以 Agent 或许能描述当前组合，却列不出完整选型空间——发现层半成品。NVIDIA 用 target_os / target_arch 映射选中态，同时 structure 里仍有全树，两边齐全。

证据 · 当前 ids ≠ 全量矩阵

实测选中态摘录

?ids=d802,…,AArch64,online_apt_get
<!-- ↑ 当前组合编码 -->
<!-- ✗ 首包无：还有哪些型号 / 架构 / 安装方式？各对应哪张包表？ -->

能恢复选中态，不等于选型矩阵可发现。

修改建议

每项 option 附带人类可读 label 与 canonical URL（或 ids→包表映射）；勿只用编码 ids 承载信息架构。

3. 也没有备用的版本矩阵清单

问题：Toggle 读不全时，如果 llms.txt 或下载说明 MD 里也没有按「型号 × 架构 × 安装方式」列出选项与包 URL，AI 就只剩当前 ids 片段，没有退路补齐选型发现层。

修改建议

在 llms.txt 或平行 MD 临时平铺版本矩阵（选项名 + ids/URL）；页面 option SSR 或首包 JSON 达标后以页面为准。
