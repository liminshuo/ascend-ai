常见异常可说明处置

为了帮助 Agent 在失败、报错与排障时不凭空臆造，须给出可抓取的含义说明与官方下一步；无结论时显式写「暂无官方处理说明」。空态默认见 缺省空态可文案处理。

适用对象

名称 说明 常见落点
失败 / 报错态 错误与失败须有可见文案区，不单靠红色或图标表意。 安装回执、任务结果、控制台
错误码说明 错误码 / 报错原文旁附可引用的解释与处置步骤，与当前版本对齐。 错误码表、排障手册
官方下一步 「含义 → 原因 → 下一步」可扫读；无官方结论时显式声明，禁止暗示可猜。 排障入口、异常条目

适用场景

优先级 页面类型 说明
必做 排障手册、错误码参考、安装失败回执 Agent 最易在结果不明时臆造；须官方含义与下一步。
建议做 API 错误响应说明、任务失败态文案 错误旁附解释与处置；与版本对齐。
可不做完整改造 纯成功路径演示、无错误分支的概念页 可链到排障手册；出现失败态时仍须文案。

设计UI调整

调整建议

  • 失败态须有可见文案 错误 / 失败态须有可见文案区，不单靠红色或图标表意。
  • 含义 → 原因 → 下一步可扫读 排障入口位置固定；层级结构清晰，便于人机扫读与抓取。

调整示例

失败态写出含义与下一步

反面
依赖安装
  • 常见疏漏：仅色点 / 图标，机器无法识别失败含义与处置路径。
正面

依赖安装失败

  • 含义软件包校验和不一致。
  • 原因下载不完整或镜像损坏。
  • 下一步重新下载软件包后重试安装。
  • 正确做法：可见文案写清含义、原因与官方下一步。

文档内容调整

调整建议

  • 给出官方处理路径 常见异常写清含义与下一步；错误码旁附可引用解释与处置，与当前版本对齐。
  • 无结论时显式声明 若官方尚无结论，写明「暂无官方处理说明」，禁止暗示可猜或编造步骤。

调整示例

错误码旁附官方处置

反面 
错误码：0xA0001

← 无含义 / 无下一步
  • 常见疏漏：仅抛错误码，Agent 易凭空臆造处置。
正面 
**错误码** `0xA0001`（CANN 8.0）

**含义**：驱动与 CANN 版本不匹配。
**原因**：驱动未升级到配套版本。
**下一步**：按《驱动安装指南》
安装配套驱动后重试。

← 可引用处置
  • 正确做法：含义 / 原因 / 下一步可抓取；与版本对齐。

前端调整

调整建议

  • 错误文案进入首包 失败说明在 SSR / 首包输出，禁 JS 仍可读。
  • 语义标注失败态 可用 data-result="failure" 等标注，便于切片识别失败块。

调整示例

失败块可机读标注

反面 
<div class="alert-red">
  <i class="icon-x"></i>
</div>

← 无文案 / 无语义
  • 常见疏漏：仅样式表达失败，切片拿不到含义与下一步。
正面 
<aside data-result="failure"
  data-error-code="0xA0001">
  <p>含义：驱动与 CANN 不匹配。</p>
  <p>下一步：安装配套驱动后重试。</p>
</aside>

← 可切失败 chunk
  • 正确做法：首包含文案；data-* 标失败与错误码。
