设计背景

AI 亲和的含义

AI 亲和（AI-Friendly）指的是让产品界面、代码结构与文字内容更容易被 Agent 稳定发现、完整读取并正确理解的一套设计原则。它不是为 AI 牺牲人的体验，而是把 Agent 当作一类特殊的信息消费者，让内容对人和 Agent 同样友好。发现、读取与理解构成基础层；在此基础上，内容还需支撑可操作与可验证的进阶层，后续章节将逐一展开。

简单比喻：就像为视障用户做无障碍设计，AI 亲和是为 Agent 这类“机器用户”做无障碍设计。如果一个页面没有标题层级、按钮没有语义、图片没有描述，Agent 就很难理解内容结构，也无法为用户提供准确的摘要、问答或自动化操作。

设计对象的转变

过去，内容的读者是人。我们为眼睛设计，在意视觉层级、交互反馈、文案语气。人通过这些信号快速理解结构，也能靠经验补全信息的缺失。

生成式 AI 改变了这条路径。用户不再逐一打开链接，而是把问题交给 AI 助手，由它调度 Agent 去读、去比较、去整合，最后给出答案。页面可能从未被用户访问，但内容已经被 Agent 读过、引用过，成为答案的一部分。内容的真实读者，已经不只是人，还包括 Agent。

读者变了，阅读方式也跟着变了。Agent 不需要视觉引导、动效或交互反馈，这些为人类阅读服务的设计，对 Agent 来说不是不能用，而是不经济。它依赖结构、语义和元数据来判断“这是什么、能否被引用”。把大量面向人类的内容原样交给 Agent，只会带来额外的上下文负担，消耗更多推理资源。

所以，设计对象的转换已经发生：我们不再只为人设计，而是同时为人和 Agent 设计。给 Agent 设计，关心的不是它“看起来怎么样”，而是它“能不能被高效读懂”。原来的基础设施在面对 Agent 这个新读者时已经不够用了，需要针对它重新设计内容被获取和阅读的方式。

AI 亲和的价值

随着大模型在日常工作与学习中的普及，用户越来越习惯直接向它要答案。内容若无法被 Agent 稳定发现、完整读取并正确理解，模型就会用训练记忆填补缺口，产生幻觉或过时指引，损害信任。关注 AI 亲和，就是让内容在人与 Agent 共构的信息环境中持续被看见、被使用。

对 Agent 友好的内容，对人也更友好。清晰的结构、明确的语义、统一的术语，本身就是更好的用户体验。AI 亲和不是额外的工作，而是让内容在 AI 主导的信息环境中，依然能被准确使用的基础。

与相关概念的关系

与 GEO 的关系

GEO（Generative Engine Optimization，生成式引擎优化）是让内容在 AI 生成答案时被优先引用和推荐的优化方法。AI 亲和解决“让 AI 理解内容”，GEO 解决“让 AI 引用内容”。理解是引用的前提——如果 AI 无法准确解析内容的结构和语义，就谈不上在生成答案时优先引用它。AI 亲和提供了内容被 Agent 稳定发现、读取和理解的基础条件，GEO 则在这一基础上，进一步优化内容与用户问题的匹配度、信息呈现方式和可信度。

与 RAG 的关系

RAG（Retrieval-Augmented Generation，检索增强生成）是让 AI 从企业自己的知识库中检索相关内容，再基于这些内容生成回答的技术架构。它常用于智能客服、内部知识助手等场景。RAG 的效果上限取决于知识库内容能否被准确检索和匹配。如果文档结构混乱、语义不清、术语不统一，AI 就找不到正确的片段，回答自然偏离事实。AI 亲和为 RAG 提供了内容可被 Agent 准确解析和检索的基础。
