元素拆解

根索引保持轻量，分册保持可发现，详情页保持完整。不建议给分册加 YAML、标签等多余元数据；一行 Markdown 条目即可。

1. 三级职责

  1. 根索引：只列分册入口与分册类型说明；不写详情页摘要，避免与分册重复维护。
  2. 内容分册：按业务类型列详情页；每条含标题、Markdown 绝对链接、一句说明。
  3. Markdown 详情页：完整内容、目标、规则与资源；索引不替代详情页。

2. 分册一行格式

  1. 写法：- [内容标题](https://www.hiascend.com/llms-content/learning/分册路径/xxx.md): 一句说明
  2. 内容标题：与详情页 Frontmatter title 完全一致。
  3. Markdown 链接：HTTPS 绝对地址，直达 .md 正文；勿用人读页、栏目首页或中间跳转页。
  4. 一句说明：概括核心主题、覆盖范围或适用场景，帮助 Agent 判断是否打开详情页；须与正文一致，勿超范围、勿堆关键词、通常一至两句。

条目一行

- [内容标题](https://www.hiascend.com/llms-content/learning/…/xxx.md): 一句说明

3. 分册分类边界

  1. growth：完整学习路径（多阶段、多资源串联）。
  2. courses：单门课程详情。
  3. developer-certification：正式开发者认证科目。
  4. certification：微认证（范围更窄、常以课程章节为内容核心）。
