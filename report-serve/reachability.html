Ascend 社区分析

昇腾社区实测与改造路径：学 NVIDIA 分面管道，守 Mintlify 策展边界。表内「AI亲和 Level」是实测档位，不等于策展目标。

实施建议

一、策略：工程可达 × 策展边界

  • 学 NVIDIA 管道，守 Mintlify 收口。分面发现保效率；窄目录背书保可信。
  • 只把愿背书的知识面推到深度亲和。llms 收录 + Markdown 可读；其余止于基线（Sitemap + HTML）。
  • 格局：分面管道 + 窄目录。不做全站镜像流水线，避免叙事与事实混仓。

二、准入：谁进深度，谁停基线

  • 深度亲和（知识域）。文档中心、FAQ、故障案例、可核对指南 / API——客观、稳定、可溯源的事实叶子页。导航能点到 ≠ 该进 Agent 目录。
  • 基线亲和（分发层）。产品 / 方案故事、博客新闻、招聘等：Sitemap 可发现 + HTML 可读即可；不进 llms、不产出平行 MD。
  • 明确剔除。论坛发帖、活动报名、工单、法务协议不进 Agent 检索；论坛精华须先沉淀为官方 FAQ 再准入知识域。

三、顺序：闸门先于工程

  • 背书闸门前置。不愿为 AI 原样引用负责 → 锁定基线及以下，技术可行也不能升。
  • 知识面分面建设。文档 / FAQ / 案例各自 Sitemap + llms；根站只做枢纽；锁定权威 locale（如 /zh/）。
  • 发布同轨。知识叶子页发布即同步 MD 并写入 llms，杜绝「目录有、MD 404」；壳页只作入口，不强求平行 MD。
  • 可读性先行。知识域入口若正文缺失，先保证 HTML 可读，再推 llms / Markdown。
