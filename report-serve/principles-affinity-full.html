全量亲和原则 34 项

按侧栏「可达 / 可读 / 可理解 / 可操作 / 可验证」分组，沿用全量表模板整合原有原则并补齐侧栏条目；覆盖文档内容、设计 UI、前端三个交付维度。

2 面包屑 全链路同名：
面包屑层级名、侧栏手册树、页内 H1、正文适用条件以及 sitemap / MD 路径，必须保持全局统一的命名与版本号。严禁出现「看得见但对不上」的割裂感，或同一页面被识别为多个入口的歧义。
过渡期路径补位：
页面面包屑未达标前，须在 llms.txt 或平行 MD 源中显式写出祖先链作为补位；页面 HTML 达标后，以 HTML 为准，并及时移除冗余的重复维护。		 路径默认可见：
面包屑必须呈现真实站点层级路径（含产品线 / 手册名 / 版本等上级层）；末级为当前篇名，采用不可点击的纯文本样式。
版本须写进路径：
版本号作为路径中的一级写出；页眉下拉可保留，但不得以只写「版本」的控件替代路径层，默认态须能读到具体版本。		 真实可跟链：
每一级祖先须为带真实文档地址的 a[href] + 可见文案；当前页用纯文本，勿做成自链。href 须指向手册祖先页，不得链到 sitemap XML 等无关地址。
首包即含全量路径：
首包 HTML 输出与可见 UI 一致的完整祖先路径；中间级不得缺失，也不得只写在 __NUXT_DATA__ 或前端脚本里、等 JS 跑完才补全。
结构化可选：
在可跟链与首包达标后，可再补 BreadcrumbList / isPartOf 等结构化数据；不得用 JSON-LD 代替首包路径。		 — —
3 邻篇导航 篇名与正文一致：
邻篇文案必须与目标页 H1、侧栏目录用语完全一致；严禁另起一套叫法导致「看得见但对不上」或同一篇被识别成多个入口。
顺序与手册对齐：
上一篇 / 下一篇的顺序必须与手册目录 / 教程序列严格对齐；严禁凭版式随意跳接无关页。		 邻篇默认可见：
上一篇 / 下一篇入口须默认可见，文案必须包含真实篇名；严禁仅写「上一页 / 下一页」或纯箭头。
关系词写清：
须使用「上一篇 / 下一篇」等明确文档关系词，严禁使用「返回 / 继续」等无法判断邻接目标的泛词。		 真实可跟链：
邻篇必须使用带真实文档 URL 的 <a href> 标准链接，锚文本必须包含篇名；严禁仅用 button 或无地址的伪点击态冒充链接。
首包即含邻篇：
首包 HTML 须直接输出上一篇 / 下一篇的可跟链；严禁仅依赖客户端路由或脚本注入后才出现。		 — —
4 章节可访问 标题可独立理解：
节标题须能单独读懂主题，避免「如下」「续」「说明」等无主题标题；节名同时作为锚点文案来源。
目录文案与标题一致：
页内锚点导航项字面须等于对应节标题，禁止缩写或另起一套叫法。
跨页写清节名：
引用写成「篇名 · 章节名」，禁止「见上文」「点击这里」等无法落到具体节的泛词。		 锚点跳转的视觉反馈：
用户或大模型通过锚点链接跳转后，目标段落需要有高亮或滚动定位的视觉提示，让用户确认落点正确，避免跳转后找不到对应内容
锚点链接入口：
每个标题或内容块旁提供可点击的锚点图标（如 # 符号），hover 时显示，方便用户复制引用链接		 锚点 ID 的稳定性保证：
锚点 ID 必须基于内容语义生成（如标题文本的 slug），而非基于渲染顺序或随机值。内容未变动时 ID 不变，避免大模型缓存的引用链接失效
锚点 ID 覆盖粒度：
不能只有页面级 URL，H1-H5 标题、关键段落、列表块、表格、图片都需要有锚点 ID，保证大模型可以精确引用到内容块而非只能指向整页
锚点在 SSR 首屏 HTML 直出：
id 属性必须在服务端渲染时写入 DOM，不能由客户端 JS 动态生成，否则爬虫拿不到锚点信息
锚点与页面大纲接口联动：
“标题明确”原则已有大纲接口，此处需将锚点 ID 作为必要字段输出，供大模型直接获取可引用的精确地址。		 — Barnett FP3
5 双轨交付 同源同文：
Markdown / 纯净正文与 HTML 渲染页必须由同一来源导出；严禁给人看一套、给机器看另一套，或按 UA 动态换皮。
入口文案写清动作：
入口须使用「复制 Markdown」「打开 Markdown」「机器可读版本」等可独立理解的短语；严禁只写「MD」「源码」等含糊缩写而无动作说明。		 文档页级：
Markdown 入口 文档页头必须提供可见的「打开 / 复制 Markdown」入口，文案须写清具体动作；严禁仅用仓库源码链替代。若整站 llms.txt 已收录稳定的本页 .md 直链，可免重复堆按钮。
内容块平行：
MD 架构图、规格表等强视觉块必须配备平行 Markdown；标题旁轻量 MD 徽标仅作快捷入口，严禁替代正文。若首包已包含完整可抓取的语义化 HTML 表，徽标可省略。
入口默认可见：
机器可读入口必须为可见文字或明确动作控件；严禁仅用无字图标暗示存在 Markdown 版本。		 Markdown 源文件对外可访问：
/doc_center/source/ 路径下的 Markdown 文件必须可直接访问和下载，不做鉴权拦截，配合 robots.txt 放行和 llms.txt 索引。
两轨内容一致性校验：
构建流程中对比 Markdown 源文件与生成的 HTML 内容，检测是否存在渲染层单独修改导致的内容不一致，不一致则阻断发布。
Markdown 文件元数据同步：
Markdown 文件头部的 frontmatter（版本号、日期、状态等）与 HTML 页面 <head> 中的 meta 和 JSON-LD 字段保持自动同步，由构建管道统一处理，不依赖人工双向维护。
HTML源码优化：
不使用 .md 的渲染页面，采用 .html 渲染页面，需尽量在前端输出，不通过服务端动态渲染。		 实测诊断 Barnett FP1

可读

原则名称 文档内容调整 设计UI 调整 前端调整 原则来源 理论依据
6 页面 HTML 可读 文档内容必须确保传统的搜索引擎爬虫和AI爬虫能够通过静态HTML或服务端渲染（SSR）的方式获取到完整的、不依赖客户端执行JavaScript的内容。具体禁止：
无限滚动、动态渲染（页面主要内容不能完全依赖JavaScript客户端渲染）、虚拟滚动、关键内容的懒加载。		 禁止设计无限滚动交互：
文档页面不使用无限滚动加载更多内容的设计模式，内容分页或一次性完整展示		 SSR 完整输出页面主体内容：
所有文档正文、标题、代码块、表格必须在服务端渲染到首屏 HTML，禁止依赖客户端 JS 渲染主体内容
禁止关键内容懒加载：
图片懒加载可以保留，但文字内容（正文、步骤、警示块、验证区块）禁止懒加载，必须随页面 HTML 直接输出
禁止虚拟滚动：
长列表、长表格禁止使用虚拟滚动组件，必须完整输出所有行的 DOM 节点。
爬虫可达性验证：
在 CI/CD 流程中加入静态 HTML 完整性检测，禁用 JS 后抓取页面，对比关键内容节点是否完整存在，不完整则阻断发布		 实测诊断阳狮团队已识别 Barnett FP1
7 图片内容转译 对于包含可点击区域（ImageMap，既带有<map>和<area>标签的图片），图片下方必须提供给一个完整的、无序列表样式的链接清淡，清单中列出所有热区对应的跳转目标。每个清淡项必须包含：
热区所代表的描述性文字，以及完整的跳转URL。禁止在清单中使用“区域1”、“链接2”等无意义的描述。		 图表格式规范：
所有流程图、时序图、架构图，在交付给研发时优先提供 Mermaid 源码，而不是导出 PNG/JPG。如果 Mermaid 表达不了，提供 SVG 源文件。
图片排版预留 figcaption 位：
每张图片下方在设计稿中预留 figcaption 注释区域，作为内容转写的展示位，纳入排版规范，不能设计成没有这个位置的图文布局。
复制链接按钮设计：
在 figcaption 段落旁设计"复制链接"按钮，以及点击后的 toast 轻提示样式（文案如"已复制链接"，持续约 2 秒后消失）。这个按钮需要出现在每个 figcaption 区域。
使用装饰性图片识别：
在设计交付标注中，明确标出哪些图片是装饰性的（图标、分割线等），告知研发这些元素标记 aria-hidden="true" 或使用 CSS 背景图实现，不需要 alt 文字。
设计交付时，针对每一个 <area> 热区，同步提供：
a.描述性文字：热区代表的阶段名、文档名或功能名，禁止用"区域1""链接2"等无意义文字
b.alt 文案：填入 <area alt>，一句话描述该热区的跳转目标
c.title 文案：补充热区的上下文说明
热区链接清单设计：
在图片下方的 figcaption 区域内，预留热区链接清单的展示位，样式为无序列表，每项包含描述性文字和跳转目标，与 figcaption 图意转写并排或紧随其后。		 HTML 结构实现：
每张图片用 <figure> + <figcaption> 包裹，<img> 上填写设计侧提供的 alt、title、data-llm-transcription 三个字段。每个 <figure> 需要有唯一 id 作为锚点。
复制链接按钮功能：
figcaption 旁实现"复制链接"按钮，点击后将当前图片的锚点 URL 写入剪贴板，同时触发 toast 提示"已复制链接"，2秒后自动消失。每个 <figure> 需要有唯一的 id 作为锚点。
Mermaid / SVG 渲染支持：
研发侧引入 Mermaid 渲染库，支持在文档内容中直接嵌入 Mermaid 代码块并渲染为可交互图表。SVG 图表直接内联到 HTML 中，而不是作为 <img> 引用，保证文本可提取。
Chunk 切片管道：
在内容切片逻辑中，将每张图片的 alt + figcaption 文字 + 图片前后的正文段落拼接为一个连续文本块，作为该图片的语义 chunk 供向量化索引使用。装饰性图片（aria-hidden="true" 或 role="presentation"）跳过，不参与切片。
装饰性图片标记：
纯装饰性元素（图标、分割线）改用 CSS background-image 实现；若必须使用 <img>，标记 alt="" 加 role="presentation" 或 aria-hidden="true"，确保不被内容提取管道处理。
<area> 标签补全：
每个 <area> 必须填写 alt 和 title，href 必须为绝对 URL，禁止使用相对路径。
<nav> 文本链接清单实现：
在每个带有 <map> 的图片下方，用 <nav> 包裹一个无序列表，覆盖全部热区目标，<a> 标签内必须有描述性锚文本，href 为绝对 URL。与 figcaption 图意转写组合展示。
绝对 URL 转换：
构建管道中自动将 <area href> 和 <nav> 内 <a href> 的相对路径转换为绝对 URL，确保机器可直接引用和跳转。
Chunk 切片管道：
在上一轮切片逻辑基础上，针对热区图片额外提取 <nav> 内的链接清单文本，与 data-llm-transcription、figcaption、周围正文拼接为一个完整 chunk。		 实测诊断 Barnett FP1/FP3

8 图标语义锚定 文案与图标语义一致：
文案含义须与图标一致（如「告警」不要配成功勾）；字段名、类型名写入正文，不依赖读者识图。
列表勿只放图标列：
表格或列表中承载语义的列须有文字表头与单元格文案，禁止仅以图标列区分状态或类别。
指标数字附名称：
统计数字须附指标名或单位（如「收藏 228」），禁止裸数字或仅靠图标暗示量纲。		 图标不独自表意：
图标承载的字段、类型或量纲须配可见文字；图标可保留但不得作唯一载体；数字须附单位或指标名。
提示图标配名称：
公告、说明等提示图标旁须有可见文字名称；日期须标明发布时间或更新截止时间。
品牌：
Logo 可识别 Logo 旁显示名称，或写入源码非空 alt，二选一；每项可跟链。旁白已列同一名单时，Logo 可只作装饰。		 信息图标可访问名称：
信息型图标提供可见旁路文本或 aria-label；装饰图标用 aria-hidden="true" 或空 alt。
入库抽取旁路文字：
切片管道抽取图标旁文案 / aria-label，不依赖 icon font 字形或纯 SVG path；装饰项跳过向量化。
Logo：
名称可检索 品牌 Logo 须非空 alt 或旁路可见名称；首包即含该文字，禁止仅客户端补全。		 — —
9 颜色语义转写 级别前缀统一 正文统一使用「警告：
」「注意：」「提示：」等前缀写法，避免同义混用或只写颜色词。
勿用「红：
/ 绿」指代 表格、图例与正文中的含义用词须写类别或状态名，禁止用「红色表示失败」等指代。		 颜色不独自表意：
状态、禁用、图例等含义须配可见文字；颜色可保留但不得作唯一载体。
警示写级别词 告警条须写出「警告：
」「注意：」「提示：」等前缀，禁止只靠红 / 橙 / 蓝色块区分。
图例写分类名：
图表图例须写分类文字（如「训练」「推理」），禁止仅有色点与数字。		 级别词写入 DOM 文本 「警告：
」等前缀须为真实文本节点；可加 data-admonition-type 等属性辅助，但不得替代可见文字。
禁止 CSS 伪元素独占语义 勿用：
:before / ::after 单独生成唯一级别词或图例名；静态抓取读不到伪元素内容。
首包即含语义词：
警示前缀、禁用文案、图例分类名须在首包 HTML 中；禁止仅客户端注入。		 — —
10 音视频要点伴随 要点与口播一致：
用条目概括操作步骤、命令与预期结果；旁侧要点须与口播关键事实一致，勿另写一套营销摘要。
页内须有足够摘要：
可链完整讲义 / Markdown，但页内须有足够步骤与结论摘要，禁止「详见视频」作为唯一出处。		 媒体不独自表意：
讲解、步骤与结论不得仅存于音视频；须配旁侧可抓取标题与要点。画面烧字与口播均不视为文本替代。
要点概括即可：
旁侧文字概括关键步骤、参数与结论即可，无需逐字转写口播；布局上要点默认可见，勿藏进需点击才展开的唯一入口。		 要点在首包：
HTML 旁侧标题与要点须随首包输出；禁止仅靠 XHR / 点击后加载字幕或摘要作为唯一文本。
字幕不作唯一替代：
可提供字幕轨，但关键步骤仍须以可见正文 / 要点块交付；勿假设爬虫会解析媒体轨。
装饰媒体勿入库：
装饰性背景视频 / 氛围音标记跳过向量化；信息型媒体旁的要点块须参与切片。		 — —
11 表格语义化 符号替换：
表格单元格中禁止使用仅靠形状表达含义的符号，如✅、❌、-、N/A等，所有状态必须使用完整的文字表达，如 是/否、支持/不支持。
结构化标题：
表格必须使用 <caption> 标签提供表格标题/摘要；列名称必须使用 <th> 标签。
作用域：
<th> 标签应尽可能指定 scope="col" 或 scope="row"。		 符号替换规范：

19 标题按层级标注 要求：
所有标题（H1-H5）必须使用描述性、面向用户具体操作型任务或概念的短语，而非泛泛而谈的、模糊的标题。标题应作为一个独立的语义单元，精确反映其下方内容的意图。禁止使用仅概括章节类型的通用标题（如“概述”、“介绍”、“详情”、“步骤1”）。标题的层级结构应能够反映内容的结构，显示父主题、子主题之间的关系。		 层级视觉差异化：
H1-H5 必须在字号、字重、颜色、间距上有明确的梯度区分。当前H4、H5 难以区分。		 严格的 HTML 语义标签使用：
强制 H1-H5 按层级顺序使用，不允许因为样式需求跳级（如页面没有 H2 直接用 H3），层级顺序由 linting 规则或 CMS 约束保证
标题内容 SSR 首屏直出：
标题文本必须在首屏 HTML 中存在，否则爬虫根本拿不到标题，原则对大模型完全失效
禁用词自动校验：
在发布流程中拦截通用标题，这是保证内容侧原则真正落地的工程兜底，否则完全依赖人工自觉
页面大纲接口：
提供页面级的标题大纲数据接口，输出结构化的标题树（含层级、文本、锚点 ID），供大模型或搜索引擎直接消费，而不必自行解析 HTML 。		 — Barnett FP5

27 链接语义化 描述性锚文本可索引：
内容引用超链接采用描述性、可见文字显性标注跳转目标，实现AI可访问性和搜索索引性。
描述性锚文本：
超链接的可点击文本必须能够在不依赖上下文的情况下，独立描述链接的目标内容或操作。禁止使用“点击这里”、“更多”、“链接”作为锚文本。
站外来源标注：
对于指向其他域名的链接，应在锚文本旁添加显式标识，如[外部]或图标+目标域名
内联上下文：
链接应嵌入在具有上下文的句子中，而不是孤立地列出
用途说明：
对于下载链接、API参考链接等，可在链接后附带括号说明文件类型、大小或用途。		 建立链接文案规范，纳入内容审核流程，同时覆盖正文链接和热区链接：
a.锚文本必须能独立描述跳转目标，脱离上下文也能理解
b.禁止使用"点击这里""更多""链接""查看详情"作为锚文本
c.下载链接、API 链接在锚文本后附带括号说明文件类型、大小、用途
d.热区的 area alt / area title 文案同步提供，禁止使用"区域1""链接2"等无意义文字		 描述性锚文本实现：
正文 <a> 标签内必须有描述性文字，href 为绝对 URL。下载链接和 API 链接在锚文本后附带 <span> 说明用途，不影响链接本身的语义.
站外链接自动标识：

热区 <area> 标签补全：
每个 <area> 填写描述性 alt 和 title，href 为绝对 URL。
在已有切片逻辑基础上，针对链接语义追加提取规则：
a.提取每个 <a> 的锚文本 + href，拼接为"锚文本 → 绝对URL"格式，纳入所在段落的 chunk;
b.站外链接（data-external="true"）在 chunk 中标注来源域名;
c.热区链接从 figcaption 内的 <a> 提取，格式与正文链接一致;
d.裸 URL（无锚文本的 <a>）标记为低质量，降低索引权重。		 实测诊断 Barnett FP3/FP4
