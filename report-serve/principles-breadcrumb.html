面包屑路径可定位

为了帮助 Agent 精准定位任务上下文并建立站内知识树坐标，面包屑必须展示真实的层级路径：祖先层级可点击，当前层级用纯文本。

适用对象

名称 说明
面包屑 当前页在站点中的层级路径导航。

适用场景

优先级 页面类型 说明
必做 文档站正文页、手册 / 教程栏目页 Agent 最常引用的事实页。
建议做 官网产品 / 能力详情页 规格、能力说明等会进入引用池的页面。
可不做完整改造 纯营销落地页、活动页 须在收录策略中明确划界。

设计UI调整

调整建议

  • 路径默认可见 面包屑必须呈现真实站点层级路径（含产品线 / 手册名 / 版本等上级层）；末级为当前篇名，采用不可点击的纯文本样式。
  • 版本须写进路径 版本号作为路径中的一级写出；页眉下拉可保留，但不得以只写「版本」的控件替代路径层，默认态须能读到具体版本。

文档内容调整

调整建议

  • 全链路同名 面包屑层级名、侧栏手册树、页内 H1、正文适用条件以及 sitemap / MD 路径，必须保持全局统一的命名与版本号。严禁出现「看得见但对不上」的割裂感，或同一页面被识别为多个入口的歧义。
  • 过渡期路径补位 页面面包屑未达标前，须在 llms.txt 或平行 MD 源中显式写出祖先链作为补位；页面 HTML 达标后，以 HTML 为准，并及时移除冗余的重复维护。

前端调整

调整建议

  • 真实可跟链 每一级祖先须为带真实文档地址的 a[href] + 可见文案；当前页用纯文本，勿做成自链。href 须指向手册祖先页，不得链到 sitemap XML 等无关地址。
  • 首包即含全量路径 首包 HTML 输出与可见 UI 一致的完整祖先路径；中间级不得缺失，也不得只写在 __NUXT_DATA__ 或前端脚本里、等 JS 跑完才补全。
  • 结构化可选 在可跟链与首包达标后，可再补 BreadcrumbList / isPartOf 等结构化数据；不得用 JSON-LD 代替首包路径。
