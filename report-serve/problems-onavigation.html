主导航链接可发现性 部分可抓

查看测试页面

主导航链接可发现性指顶栏/主导航中的信息架构入口是否以真实链接写入 HTML；语言、主题等纯交互可弱化入库。 以 社区首页 为例：社区首页顶栏为 o-nav-* 体系；右侧「文档 / 在线开发 / 下载」为高频导流。

根因分析

主导航链接可发现性的核心原因：人在浏览器里能看见顶栏「产品 / 文档 / 在线开发 / 下载」等入口，但「查看网页源代码」里多数一级项是没有 href 的 div；「在线开发」「下载」也跟不到官方地址——AI 看得见文案，列不全可跟链清单。

<a class="develop-btn" target="_blank"><span>在线开发</span></a>
<!-- ↑ 无 href -->
<div class="app-header-download-val">下载</div>

1. 一级入口多为 div，没有 href

问题：打开社区首页，用「查看网页源代码」核对：o-nav 里「产品」「解决方案」「开发者与合作伙伴」是 div.o-nav-item-link，只有「支持与服务」→ /support。浏览器看得见文案，禁 JS 时跟不到落地页——友商 Mintlify Documentation / Get started、NVIDIA Shop / Drivers 在源码里就是 a[href]。

证据 · 一级入口本来应该长这样

期望写进网页的一级导航（示意）

<nav class="o-nav-head">
  <a href="/product">产品</a>
  <a href="/solutions">解决方案</a>
  <a href="/developer">开发者与合作伙伴</a>
  <a href="/support">支持与服务</a>
</nav>

文案可以保留；底层必须是可跟的 a[href]，不能用 div 冒充。

修改建议

每一级站点入口一律用 OLink / a[href] 输出，文案与目标地址同时写进首包 HTML。

2. 高频导流半成品：文档可跟，开发 / 下载不行

问题：探针问「文档 / 开发者 / 下载」时，源码里「文档」已有 a[href=/zh/document]，但「在线开发」是无 href 的 a、「下载」是 app-header-download-val 的 div。三件套对不齐，只能答出文档一条——形成半成品发现层。

证据 · 右侧三项实测对照

实测源码摘录

<!-- ✓ --> <a class="doc-btn" href="/zh/document">文档</a>
<!-- ✗ --> <a class="develop-btn" target="_blank">在线开发</a>
<!-- ✗ --> <div class="app-header-download-val">下载</div>

有一项可跟不算达标；探针要的三件套须都能跟到官方地址。

修改建议

「在线开发」「下载」改为带真实落地 URL 的顶栏 a[href]；若下载是下拉，面板内每一项也须首包写出完整链接，不要等点击才挂。

3. 也没有备用的站点入口清单

问题：顶栏读不全时，如果 llms.txt 或站点地图里也没有列出「文档 / 开发者 / 下载」等官方入口链接，AI 就只剩当前页零散文案，没有退路补齐发现层。

修改建议

在 llms.txt 显式列出顶栏关键入口（文案 + URL），与顶栏 SSR 双轨互证；页面达标后以页面为准。
