主导航链接可发现性 部分可抓

查看测试页面

主导航链接可发现性指顶栏/主导航中的信息架构入口是否以真实链接写入 HTML；语言、主题等纯交互可弱化入库。 以 社区首页 为例：社区首页顶栏为 o-nav-* 体系。

友商测试

友商案例被测对象html 可抓取原因
Mintlify文档站顶部主导航navbar可抓全文档站顶栏 navbar：Documentation / API reference / Changelog / Talk to us / Get started 一级链均带真实 href；Learn 下拉子项（Customers / Blog 等）亦在首包 HTML。
昇腾社区社区首页顶部主导航部分可抓抓不全顶栏 o-nav 一级项（CANN / 产品 / 解决方案 / 开发者与合作伙伴）文案在首包可见，但多数 o-nav-item-link 为 div 无 href，仅「支持与服务」→ /support；右侧「文档」在折叠 panel 内有 /document，「在线开发」「下载」为 button/div 无稳定 href。

根因分析

主导航链接可发现性的核心原因：顶栏主导航在浏览器里一目了然，但许多一级入口没有写进网页源码里的可点链接，AI 看得见「产品 / 文档 / 下载」等文案，却跟不到官方地址。

1. 一级入口缺少 href

问题：社区首页顶栏 o-nav 里「产品」「解决方案」「开发者与合作伙伴」等多为 div.o-nav-item-link，没有 href；友商 Mintlify 文档站 Documentation / Get started、NVIDIA Shop / Drivers 等一级入口在「查看网页源代码」里即可跟链。

修改建议

每一级站点入口一律用 OLink / a[href] 输出，文案与目标地址同时写进首包 HTML。

2. 关键导流项缺少可跟链接

问题：顶栏右侧的「在线开发」「下载」是人最常找的入口：前者在源码里没有网页地址，后者只是下拉框，不展开就不知道链到哪。问「从首页怎么进官方文档 / 开发者 / 下载中心」时，往往只能答出一两条，清单对不齐——友商同类入口在「查看网页源代码」里就能直接跟链。

修改建议

把文档、开发者、下载等高频入口改成带真实网址的顶栏链接；下拉面板里每一项也在首屏 HTML 里写好完整 a[href]，不要等点击才出现。

3. 下拉子链与工具控件混排

问题：CANN 推广位、搜索、登录图标和「产品 / 文档」等导航挤在同一顶栏；部分子菜单要鼠标悬停或跑脚本后才挂出来，首包 HTML 里 o-nav-head 甚至可能为空。友商 Mintlify navbar、NVIDIA mega menu 的下拉子链，大多一开始就写在源码里，禁 JS 也能抓全。

修改建议

下拉菜单在服务端一次性输出完整链接树；搜索、换肤、语言切换等纯操作控件标注 data-llm-exclude，入库管道勿当正文知识。
