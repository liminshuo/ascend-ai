robots.txt 配置诊断

Skill ID：robots-txt-audit · 依据：配置 robots.txt 许可声明

核心命题

robots.txt 是 Agent / 爬虫读取的许可声明。本 Skill 只回答：规则是否可获取、开放/禁止范围是否写清、发现入口（Sitemap / 可选 llms）是否在文件内声明。

下载 Skill 查看示例报告 华为开发者示例

检查范围

要查 robots.txt 本体与轻量关联探测；不评估 Sitemap 文件本体质量，不做全站内容审计。

检查项 通过标准
入口可达 https://{域名}/robots.txt GET → 200，正文可解析
Allow 有显式 Allow:（建议至少 Allow: /），否则记为问题
Disallow 列出全部路径；标记疑似误屏蔽的公开/知识向路径
Sitemap 声明 文件内有 Sitemap: / sitemap: 绝对 URL
LLMs.txt 声明 若服务 AI Agent：有声明；未部署则待确认，勿指向不可达地址

诊断工作流

  1. 输入：站点根域名或完整 robots URL；可选是否需要 AI Agent / llms 场景。
  2. 拉取 robots.txt：解析 User-agent、Allow、Disallow、Sitemap、LLMs.txt、Content-Signal。
  3. 轻量关联探测：统计声明条数；探测 /llms.txt 与候选 Sitemap 是否可访问（不评价清单质量）。
  4. 问题列表：P0 无 Sitemap 声明；P1 无 Allow / 无 LLMs 声明（场景需要时）/ 疑似误屏蔽；P2 写法不统一。
  5. 建议稿：补 Allow、Sitemap；知识向路径待确认；LLMs.txt 可访问后再声明。
  6. 输出 HTML 报告：Part1 当前配置分析 + Part2 优化建议；可导出 PDF。

报告结构

交付为白底 HTML，无侧栏；顶栏仅品牌与「导出 PDF」，并与正文 1000px 栏左右对齐。

  1. Part1. 当前配置分析：带标注的 robots.txt、关联探测表、问题列表。
  2. Part2. robots.txt 的优化建议：建议模板、修改说明、待确认事项。

标注块中 Sitemap、LLMs.txt、Allow、Disallow 各自独立，禁止嵌套。

如何使用

  1. 下载 Skill 包，解压到 Cursor 的 .cursor/skills/robots-txt-audit/（或个人 skills 目录）。
  2. 在对话中按名称调用，例如：按 robots-txt-audit 诊断 https://example.com/robots.txt。
  3. 按报告模板输出 HTML；在 GEO 仓库中同步到 docs/ 与 report-serve/。
