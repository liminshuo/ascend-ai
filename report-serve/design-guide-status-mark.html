状态如何写清

场景说明

能力清单、场景支持矩阵、路线图卡上，常用对号 / 时钟表示「已支持」或「等待中」，资源列再写一个蓝色「链接」。对人来说，扫图标很快；对机器来说，要读到的是状态文字和自描述去向——不是色点，也不是悬停才出现的「等待中」。

图标可以留，但默认稿面要有「支持 / 等待中 / 不支持」这类字。含义只写在 Hover tip 里，静态抓取等于没写。矩阵里的跳转不要只写「链接」。归类上对齐亲和分类「状态标识」：级别与进度用文字。

  • 任务：能力 / 兼容 / 进度状态可被枚举与引用
  • 页型：场景支持表、能力 Checklist、版本特性墙
  • 相关模式：状态完整标注

方式选型

同一任务下三种标法，按推荐程度自上而下。

优先可见状态文案。图标 + 文案并列可接受。只打对号、或时钟 Hover 才出「等待中」、资源列只写「链接」，都不合适。

亲和说明

亲和选型

  • 方案 A（推荐）：状态用可见文字（支持 / 等待中 / 不支持或 —）；资源跳转写自描述锚文本
  • 方案 B（可接受）：图标 + 旁侧可见文案并列；语义以文字为准
  • 方案 C（不推荐）：只打对号；时钟 Hover 才出「等待中」；获取列只写「链接」
  • Hover / tooltip 可给人提示，不能当唯一状态源
  • 对齐分类「状态标识」：级别与进度用文字，图标色只辅助
