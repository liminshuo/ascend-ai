页内结构模式化

概述

文档主体若写成自由散文，章节名称、顺序和内部格式因人而异，AI Agent 难以稳定识别「前提 → 操作 → 验证 → 示例」等任务块，检索与复述时易漏步骤或错配预期结果。

页内结构模式化原则要求单篇主体遵循一组有限、可预测的结构模式（Patterns）：每个模式有固定的章节名称、顺序与内部格式，模式之间用二级或三级标题清晰分隔，便于 Agent 按块解析与引用。全站多篇是否共用同一套模板，见「全站规范一致性」。

页内结构模式化原则

  1. 用有限模式组织本页主体，而非自由文本。 安装、配置、API、排障等任务页，本页内应按模式块展开，勿把前提、步骤、验证混写成一段散文。
  2. 每个模式有固定章节名、顺序与内部格式。 至少覆盖以下模式中的大部分：前提条件、步骤（有序列表）、验证（预期结果）、示例（代码块）、定义列表、故障排除（表格或列表）。
  3. 模式之间用二级或三级标题分隔。 标题文字与模式名一致（如「前提条件」「步骤」「验证」），勿仅用加粗段落或分隔线冒充章节边界。
  4. 模式内部格式保持稳定。 步骤用有序列表；验证写可核对的预期结果；示例放代码块；术语用定义列表；排障用「现象 / 原因 / 处理」表或对等列表。

常用模式与内部格式

任务页至少覆盖下列模式中的大部分；名称可统一用中文或英文，但站点内应保持一致。

  1. 前提条件 — 列表列出环境、权限、依赖版本等可核对条件。
  2. 步骤 — 有序列表，一步一事，顺序即执行顺序。
  3. 验证 — 写明可观察的预期结果（输出、状态码、界面现象）。
  4. 示例 — 可运行或可对照的代码块，与上文步骤对应。
  5. 定义列表 — 术语 / 参数用定义列表或「术语: 说明」，避免散文夹带定义。
  6. 故障排除 — 表格或「现象 / 原因 / 处理」列表，与主步骤分离。

预期效果

  1. 帮助 AI Agent 按固定模式块定位前提、步骤、验证与示例，降低自由文本带来的结构歧义。
  2. 提高同类任务页的结构一致性，便于跨页检索、对比与复述。
  3. 减少因章节混写导致的步骤遗漏、预期结果错配和排障信息淹没。

注意事项

  1. 不必每页堆满全部模式；按任务类型选用，但一旦采用某模式，章节名与内部格式应与站点约定一致。
  2. 模式分隔依赖真实标题层级，勿仅用视觉样式（字号、色块）区分章节。
  3. 本原则管单篇「块怎么切、块内怎么写」；多篇是否同名同序同格式见「全站规范一致性」。标题从属见「标题层级可识别」，推荐勿打断主流程见「推荐内容后置」。
