颜色语义可转写

为了帮助 Agent 识别级别与类别，颜色只作辅助；警告 / 注意 / 提示、成功 / 失败、已禁用、图例分类等须写成文字，禁止仅以色块表意。

适用对象

名称 说明 常见落点
警示色 警示级别须写成「警告」「注意」「提示」等词，禁止仅以颜色区分。 文档告警条
禁用色 不可用须写成「已禁用」等词，禁止仅以灰色表达。 禁用操作
图例色 分类须写成文字图例，禁止仅以色块区分。 图表图例

适用场景

优先级 页面类型 说明
必做 文档告警条、步骤注意块 级别常影响操作安全，须文字可检索。
建议做 图表图例、状态列表、禁用控件 分类 / 状态进引用池时，须写清文字含义。
可不做完整改造 纯装饰色条、氛围底色 不承载级别或类别时，勿硬写语义词。

设计UI调整

调整建议

  • 颜色不独自表意 状态、禁用、图例等含义须配可见文字；颜色可保留但不得作唯一载体。
  • 警示写级别词 告警条须写出「警告：」「注意：」「提示：」等前缀，禁止只靠红 / 橙 / 蓝色块区分。
  • 图例写分类名 图表图例须写分类文字（如「训练」「推理」），禁止仅有色点与数字。

调整示例

用级别词表达警示色

反面

请勿在生产环境使用未验证驱动。

更换驱动前请备份配置。

安装完成后请重启设备。

  • 常见疏漏：仅以色块区分级别，未配「警告 / 注意 / 提示」等文字。
正面

警告：请勿在生产环境使用未验证驱动。

注意：更换驱动前请备份配置。

提示：安装完成后请重启设备。

  • 正确做法：级别写成「警告：」「注意：」「提示：」；颜色只辅助。

文档内容调整

调整建议

  • 级别前缀统一 正文统一使用「警告：」「注意：」「提示：」等前缀写法，避免同义混用或只写颜色词。
  • 勿用「红 / 绿」指代 表格、图例与正文中的含义用词须写类别或状态名，禁止用「红色表示失败」等指代。

调整示例

级别与类别须写成词

反面 
红色条目为高风险操作。
绿色表示已通过校验。

← 机器看不到颜色语义
  • 常见疏漏：用「红 / 绿」指代级别，入库后语义丢失。
正面 
警告：高风险操作，请勿在生产环境执行。
成功：校验已通过。

← 级别词可检索
  • 正确做法：写成「警告」「成功」等词；颜色只辅助呈现。

前端调整

调整建议

  • 级别词写入 DOM 文本 「警告：」等前缀须为真实文本节点；可加 data-admonition-type 等属性辅助，但不得替代可见文字。
  • 禁止 CSS 伪元素独占语义 勿用 ::before / ::after 单独生成唯一级别词或图例名；静态抓取读不到伪元素内容。
  • 首包即含语义词 警示前缀、禁用文案、图例分类名须在首包 HTML 中；禁止仅客户端注入。

调整示例

级别词须在文本节点

反面 
.note::before { content: "警告："; }
<div class="note is-warn">请勿…</div>

← 级别词不在 DOM 文本里
  • 常见疏漏：唯一级别词只在 CSS 伪元素中，抓取不到。
正面 
<div class="note" data-admonition-type="warning">
  <strong>警告：</strong>请勿在生产环境使用未验证驱动。
</div>
  • 正确做法：级别词写入 DOM；属性仅作辅助。
