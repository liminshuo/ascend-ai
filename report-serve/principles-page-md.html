页级 Markdown

当用户在对话窗口中需要本页正文时，直接抓取渲染页容易混入导航和壳层噪声，也会丢失原有的层级结构。对于 Agent 而言，无论是像 Cursor 这样的单次工具调用，还是企业内部 RAG 的批量摄取，解析渲染 HTML 都会面临同样的难题：噪声多，且难以切分段落。 因此，需要为该页面提供独立的纯文本镜像（如 Markdown），让用户和 Agent 都能直接获取干净、结构完整的正文。

Agent 是如何取到页级 Markdown 的

Agent 取页级纯净正文有三条路径，按置信度从高到低排序：

主路径 · 通用发现层

按行业通用惯例，直接探测根目录或文档站子路径下的 llms.txt，从中 Fetch 目标页面地址。这是跨站点通用的社区约定，优先级最高。

条件路径 · 站点私有发现层

将当前页 URL 的 .html 替换为 .md。并非行业通用规则。站点需在 llms.txt 或其他公开规范中明确声明，Agent 才会尝试这条路径。

兜底入口 · 内容层

无需前置条件。已抓到 HTML 且前两条路径未获平行稿时，Agent 从 H1 旁（main 内）的「打开 Markdown」真链直接跟取 .md。

核心原则

  • 主次分明与置信度遵循「先通用、后私有、再兜底」的阶梯原则。跨站通用的 llms.txt 拥有最高优先权（主路径，详见发现层部署）；站点私有的「URL 改写」规则，只有在明确写入 llms.txt 等公开声明后才具备高置信度，否则应降级处理；页头「打开 Markdown」则作为无条件的内容层兜底。三者不互相替代，按明确的优先级依次递进。
  • 打开是真链「打开 Markdown」入口需固定在 H1 旁，且是 main 区域内的真实 <a> 标签。rel="alternate" 和仓库源码链不能单独替代这条链。

价值收益

  • 提供纯净正文入口页头增设「打开 Markdown」，供用户直接获取无导航噪声的平行 .md 文件。
  • 兜底抓取路径当站点未声明「URL 改写」规则，或该规则尝试失败时，main 内的真链可确保 Agent 稳定获取同一篇 .md，避免跨页检索中断。
