控件数值可文本读取

为了帮助 Agent 读取当前值并选择正确操作，滑杆、步进器、评分等控件的当前值与单位须写成可读文本，禁止仅以图形位置表达。

适用对象

名称 说明 常见落点
进度条 进度数值须写成百分比或「已完成 n/m」，禁止仅以条长表达。 训练进度、安装进度
滑块 当前值须写成数字加单位，禁止仅以滑块位置表达。 资源配额、参数调节
评分 评分须写成「x.x 分」等文字，禁止仅以星星颗数表达。 课程评分、内容评价

适用场景

优先级 页面类型 说明
必做 控制台进度、配额调节、安装 / 训练状态 Agent 需读准当前值再决策下一步。
建议做 官网课程 / 案例评分、产品参数滑块 数值进引用池时，须有可读文本。
可不做完整改造 纯装饰进度条，且旁侧正文已写同值 图形仅辅助、数值已在默认可读处时，可弱化控件侧文案。

设计UI调整

调整建议

  • 数值须写成字 当前值与单位须配文字（如「70%」「8 GB」「4.6 分」），禁止仅以进度条、滑块或星星作唯一载体；图形可保留，只作辅助。
  • 变更后文案同步 用户拖动或步进后，可见数值与单位须即时更新，勿只改图形位置。

调整示例

用文字表达进度数值

反面

  • 常见疏漏：仅有进度条，未写成百分比或「已完成 n/m」。
正面

训练进度 60% · 已完成 3/5 步

  • 正确做法：进度写成「训练进度 60% · 已完成 3/5 步」；进度条只辅助。

用文字表达滑块数值

反面

  • 常见疏漏：仅有滑块位置，未写成带单位的当前值。
正面

批大小 8 GB

  • 正确做法：当前值写成「批大小 8 GB」；滑块只辅助。

用文字表达评分数值

反面
★★★★☆
  • 常见疏漏：仅有星星，未写成分数与人数。
正面
★★★★☆

4.6 分 · 128 人

  • 正确做法：评分写成「4.6 分 · 128 人」；星星只辅助。

设计专项完整说明见 控件数值转写。

文档内容调整

调整建议

  • 示例值写全 文档中的示例值与单位写全；范围与默认值可查，勿只写「拖到合适位置」。
  • 截图配参数表 截图演示须配同等文字参数表，勿只贴进度条 / 滑块图。

调整示例

参数示例须写出数值与单位

反面 
## 批大小

将滑块拖到合适位置后开始训练。

← 无具体数值与单位
  • 常见疏漏：稿面无默认值 / 范围，机器无法复现操作。
正面 
## 批大小

默认：8 GB（可调范围 2–16 GB）

示例：批大小 8 GB

← 数值与单位写全
  • 正确做法：默认值、范围与示例同写；截图旁可再配参数表。

前端调整

调整建议

  • 值写入 DOM 当前值写入可见文本或 aria-valuetext；变更后文本同步。
  • 抓取可读 入库抽取可见数值，不依赖 canvas / 纯图形绘制。

调整示例

进度值须有文本节点

反面 
<div class="progress" style="width:60%"></div>

← 仅条长，无百分比文本
  • 常见疏漏：静态抓取读不到具体进度。
正面 
<p>训练进度 60% · 已完成 3/5 步</p>
<div class="progress" role="progressbar"
     aria-valuenow="60"
     aria-valuetext="60%"></div>

← 可见句 + valuetext；条只辅助
  • 正确做法：首包含可见数值句；图形只辅助呈现。
