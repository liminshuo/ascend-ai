弃用状态可显化确认

为了帮助 Agent 避免把历史版本当作现行事实引用，旧版、下线或已归档文档须在页面与元数据中显式标注弃用状态，并链到替代文档；接口级失效同理。

适用对象

名称 说明 常见落点
文档级弃用 整页旧版 / 归档文档须在 H1 上方显式标注弃用，并链到现行替代页。 历史手册、旧版 API 全文
接口 / 功能级弃用 已弃用 API、参数、配置须在最近标题下用警告块标明版本、范围与替代方案。 API 参考、配置说明
机器可读状态 status / deprecated-since / replacement-url 须可抓取，供切片降权与过滤。 Frontmatter、meta、data-*

适用场景

优先级 页面类型 说明
必做 仍可索引的旧版手册、已弃用 API 页 最易被误引为现行事实；须显化并给替代链。
建议做 部分接口已弃用的现行参考页 接口旁警告块标明 since / 替代，避免混用。
可不做完整改造 已从站外索引剔除、仅内网归档的只读副本 对外不可达时，元数据标注即可，不必强求页顶横幅。

设计UI调整

调整建议

  • 页顶弃用横幅固定可见 位置固定在 H1 上方，样式与正文隔离；含失效说明与指向新文档的醒目链接。
  • 接口级警告块可识别 功能 / 接口失效警告块统一视觉权重，与普通提示区分；须含可抓取文字，不只靠色块。

接口级弃用警告块

反面

aclrtSetDevice()

设置运行设备，适用于单设备场景。

  • 常见疏漏：仅正文描述，无弃用标注；易被引用到新场景。
正面

aclrtSetDevice()已弃用 · v9.0

自 CANN 9.0 起，请改用 aclrtSetDeviceEx()。旧接口仍可用但不再维护。

设置运行设备，适用于单设备场景。

  • 正确做法：标题旁徽章 + 警告块写清 since、替代链接与影响范围。

文档内容调整

调整建议

  • 文档失效须页顶声明 停止维护的版本 / 章节须说明「适用于已停止维护的 [产品] vX.Y」，并给出最新推荐文档链接。
  • 接口失效写清三点 警告块须写明：弃用时间点或版本、影响范围、代替方案（链到新文档）；禁止只写「不推荐」。

调整示例

失效状态与替代链接在稿面声明

反面 
---
version: "8.0.0"
---

# 旧版 API 说明

本文描述 CANN 8.0…

← 无弃用 / 替代
  • 常见疏漏：仅有版本号，无生命周期与替代链，易被当现行引用。
正面 
---
version: "8.0.0"
lifecycle_status: deprecated
deprecated_since: "9.0.0"
replaced_by: https://…/900/
---

> **警告**：适用于已停止维护的
> CANN 8.0，见 [9.0 替代文档](…)。

# 旧版 API 说明
  • 正确做法：Frontmatter 声明状态与替代；正文警告与之同源。

前端调整

调整建议

  • CMS 结构化失效字段 页面 / 块级增加 status（active / deprecated / sunset）、deprecated-since、replacement-url；与正文分离管理。
  • 警告块机器可读标注 废弃块加 data-status、data-since、data-replacement；meta 同步 lifecycle_status。
  • 页顶横幅由模板注入 status 为 deprecated 时，模板自动在 H1 上方注入提示框，不依赖内容侧手写，避免遗漏。

调整示例

机器可读的失效状态标注

反面 
<link rel="canonical" href="…">
<h1>旧版 API 说明</h1>

← 无 status / 替代
  • 常见疏漏：无结构化状态，切片无法降权或过滤失效页。
正面 
<meta name="lifecycle_status"
  content="deprecated">
<div data-status="deprecated"
  data-since="8.0"
  data-replacement="https://…/900/">
  …
</div>

← 可过滤 / 降权
  • 正确做法：meta + data-* 同源；大纲接口宜透传 status。
