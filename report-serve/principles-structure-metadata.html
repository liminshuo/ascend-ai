页级元数据可结构化

为了帮助 Agent 结构化检索并确认文档身份，每篇文档须补全身份、版本、适用产品、更新时间、上下篇关系等元数据，并在页头展示摘要与面包屑；机器字段与可见文案同源。

适用对象

名称 说明 常见落点
文档身份字段 标题、摘要、产品、版本、语言、关键词、作者 / 发布方等须可机读完备。 Frontmatter、CMS 字段
页头可见元信息 页头展示摘要、版本、更新日期与面包屑，人机都能快速定位上下文。 文档页头、面包屑区
结构化输出 优先 JSON-LD（TechArticle / HowTo / FAQPage、BreadcrumbList）写入 head，供检索与 Agent 直读。 <head>、大纲接口

适用场景

优先级 页面类型 说明
必做 文档站正文页、手册 / API 页 引用池事实页；缺元数据则难判身份与时效。
建议做 官网产品 / 能力详情、教程栏目页 进检索与引用池时，摘要与产品字段利于过滤。
可不做完整改造 临时活动页、无长期引用价值的通知 可仅保留 title + 日期；不必强求完整 JSON-LD。

设计UI调整

调整建议

  • 页头展示身份摘要 标题下方固定展示摘要、适用产品 / 版本、更新日期；信息写成字，不靠悬停或图标暗示。
  • 面包屑真实可定位 页头保留真实层级面包屑，与结构化 BreadcrumbList 同源。细则见 面包屑路径可定位。

页头展示摘要与元信息

反面

算子开发入门

  • 常见疏漏：页头只有标题，人机都难确认产品、版本与摘要。

算子开发入门

CANN · v9.0.0 · 更新 2026-06-01

面向已完成环境安装的开发者，介绍 Ascend C 算子开发基本流程。

  • 正确做法：面包屑 + 产品 / 版本 / 日期 + 摘要同屏可见。

文档内容调整

调整建议

  • Frontmatter 补全身份字段 至少声明 title、description、version、datePublished / dateModified、inLanguage、keywords、author、schema_type；与页头可见文案同源。
  • 摘要可独立成句 description 写清对象与范围（宜 150 字内），禁止空摘要或仅重复标题。

调整示例

Frontmatter 中补充完整元数据

反面 
---
title: 算子开发入门
version: "9.0.0"
---

← 缺摘要 / 日期 / 类型
  • 常见疏漏：字段过少，JSON-LD 无法自动填齐，检索难过滤。
正面 
---
title: 算子开发入门
description: "面向已完成环境安装的
  开发者，介绍 Ascend C 流程。"
version: "9.0.0"
date_published: "2026-01-01"
date_modified: "2026-06-01"
in_language: zh-CN
keywords: [Ascend C, 算子, CANN]
schema_type: TechArticle
---
  • 正确做法：稿面字段完备，供模板注入 JSON-LD 与页头展示。

前端调整

调整建议

  • JSON-LD 模板化输出 模板统一注入 JSON-LD，字段从 CMS 动态读取；覆盖全部文档页，不依赖人工逐页添加。
  • 必填字段发布校验 检测 @type、headline、description、inLanguage、datePublished、dateModified、keywords、author/publisher；缺失则阻断。
  • 同步 BreadcrumbList 可见面包屑与 BreadcrumbList JSON-LD 同源输出，含每层 name 与 URL。

调整示例

JSON-LD 结构化元数据

反面 
<head>
  <title>算子开发入门</title>
</head>

← 无结构化身份
  • 常见疏漏：仅有 title，Agent 无法结构化确认类型与时效。
正面 
{
  "@type": "TechArticle",
  "headline": "算子开发入门",
  "description": "…",
  "inLanguage": "zh-CN",
  "datePublished": "2026-01-01",
  "dateModified": "2026-06-01",
  "version": "9.0.0"
}

← 可直读检索
  • 正确做法：@type 按页面类型自动匹配；字段与 CMS 同源。

BreadcrumbList 与可见面包屑同源

反面 
<nav class="breadcrumb">
  首页 > 开发指南 > 算子…
</nav>

← 无层级 URL 结构
  • 常见疏漏：仅可见文字，无法推断每层 URL 与顺序。
正面 
{
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "position": 1, "name": "首页",
      "item": "https://…/" },
    { "position": 2, "name": "开发指南",
      "item": "https://…/dev/" },
    { "position": 3, "name": "算子开发入门",
      "item": "https://…/op.html" }
  ]
}
  • 正确做法：BreadcrumbList 含 name + item URL，与页头面包屑同源。
