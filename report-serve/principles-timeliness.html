版本号可外显确认

为了帮助 Agent 确认引用的是哪一版、是否仍为主推版本，渲染页与元数据须显式写出版本号、发布日期与生命周期状态，禁止仅靠「新」色标或列表顺序暗示时效。

适用对象

名称 说明 常见落点
日期与版本 更新日期与版本号（如 v8.0.0）须写成字；禁止仅靠列表顺序或「新」色标暗示时效。 文档列表、页头元信息
演进关系 取代、兼容、适用版本须用文字写明；版本号本身不能替代关系描述。 版本对照、变更说明
生命周期状态 当前稳定版、维护中、已弃用、EOS 等状态须可抓取，便于判断是否仍可引用。 页头徽章、Frontmatter、meta

适用场景

优先级 页面类型 说明
必做 多版本手册、安装 / API 文档正文 Agent 最易误引旧版；版本与日期必须外显。
建议做 文档列表、版本切换入口、变更说明 列表项与对照表须写出版本号、日期与演进关系。
可不做完整改造 无版本概念的概念页、纯营销页 无软件版本绑定的页面，写清「不适用版本」即可。

设计UI调整

调整建议

  • 新旧写成日期和版本 条目须标注可读的更新日期与版本号。角标可保留，但不得替代日期与版本文字。
  • 演进关系写成词 取代、兼容、适用版本须写成「已被 v8.0.0 取代」「兼容 8.0」等；版本号不能代替关系句。

调整示例

日期与版本须写成字

反面

CANN 安装指南 新

CANN 安装指南（旧版）

  • 常见疏漏：仅有「新」色标与「旧版」字样，机器无法识别更新日期与版本号。
正面

CANN 安装指南

v8.0.0 · 更新 2026-03-12

CANN 安装指南

v7.0.0 · 更新 2025-08-01

  • 正确做法：写成版本号（如 v8.0.0）与更新日期；「新」色标可留，只辅助。

演进关系须写成词

反面

CANN 安装指南

v8.0.0 · 更新 2026-03-12

CANN 安装指南

v7.0.0 · 更新 2025-08-01

  • 常见疏漏：版本与日期可抓取，但未写演进关系，无法判断是否仍适用、是否已被取代。
正面

CANN 安装指南

v8.0.0 · 更新 2026-03-12 · 当前稳定版

CANN 安装指南

v7.0.0 · 更新 2025-08-01 · 已被 v8.0.0 取代

  • 正确做法：演进关系写成「已被 v8.0.0 取代」「兼容 8.0」等。

设计专项完整说明见 版本信息外显。

文档内容调整

调整建议

  • 页头与 Frontmatter 声明版本 每篇文档须写明产品名、软件版本（SemVer）、发布日期、生命周期状态；人类可读与机器字段同源。
  • 版本差异用表条目化 跨版本差异用表格条目描述，禁止「最新」「大致兼容」等模糊散文。

调整示例

版本元数据在 Frontmatter 中声明

反面 
# 算子开发入门

本文介绍 Ascend C 算子开发基本流程…

← 无版本 / 日期 / 状态
  • 常见疏漏：正文无版本元数据，Agent 无法判断是否仍可引用。
正面 
---
product: CANN
version: "9.0.0"
release_date: "2026-06-01"
lifecycle_status: stable
---

# 算子开发入门

← SemVer + 日期 + 状态同源
  • 正确做法：Frontmatter 声明版本字段；页头可读文案与之对齐。

前端调整

调整建议

  • CMS 强制结构化字段 为页面增加 product-name、software-version（SemVer 校验）、release-date、lifecycle-status；缺失则阻断发布。
  • meta / JSON-LD 机器可读 版本信息写入 <meta> 与 JSON-LD（如 softwareVersion、datePublished），供 Agent 直接读取，不依赖正文解析。
  • 大纲接口透传版本 页面大纲 / 列表接口返回结果中包含版本元数据，消费方可直接获取版本上下文。

调整示例

元数据写入 head

反面 
<head>
  <title>算子开发入门</title>
  <!-- 无版本信息 -->
</head>

← 仅靠正文难判时效
  • 常见疏漏：head 无版本字段，抓取侧无法稳定确认时效。
正面 
<meta name="version" content="9.0.0">
<meta name="release_date" content="2026-06-01">
<meta name="lifecycle_status" content="stable">
<link rel="canonical"
  href="https://…/900/operator_dev.html">

← 字段可直读
  • 正确做法：版本、日期、状态写入 meta；与页头可见文案同源。

JSON-LD 声明 softwareVersion

反面 
{
  "@type": "TechArticle",
  "headline": "算子开发入门"
}

← 缺 softwareVersion /
  datePublished
  • 常见疏漏：结构化数据无版本字段，Agent 无法判断时效。
正面 
{
  "@type": "TechArticle",
  "headline": "算子开发入门",
  "softwareVersion": "9.0.0",
  "datePublished": "2026-06-01",
  "dateModified": "2026-06-15"
}

← 版本上下文可直读
  • 正确做法：JSON-LD 补齐 softwareVersion、datePublished 等字段。
