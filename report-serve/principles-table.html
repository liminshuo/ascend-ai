表格语义可结构化

为了帮助 Agent 切片后仍能还原「行名 × 列名」与表主题，表格须用 caption、th + scope 与合法合并表达标题与行列归属；格内嵌套列表独立成结构。状态词写法见 状态词可完整识别。

适用对象

名称 说明 常见落点
表头与标题 每表有描述性 caption；列 / 行名用 th + scope，禁止用样式伪表头。 规格表、参数表
合并与多级表头 colspan / rowspan 后每格仍能还原「行名 × 列名」；禁止只靠底色或框线表达分组。 分组规格表、兼容矩阵
嵌套内容 格内接口 / 要点列表用真实列表，不拆成伪数据行。 I/O 规格、能力说明格

适用场景

优先级 页面类型 说明
必做 文档站规格表、参数表、兼容矩阵 Agent 最常引用的结构化事实页。
建议做 官网产品对比 / 能力规格表 规格、能力说明会进入引用池的页面。
可不做完整改造 纯布局用表、无数据语义的两列排版 非数据表；勿强行 caption，收录策略中划界即可。

设计UI调整

调整建议

  • 每表须有描述性标题 每张表必须提供能说明主题的描述性标题（如「表1 Ascend C Add 算子设计规格」）。严禁使用「表格1」「数据表」等无法辨识主题的模糊命名。
  • 表头与数据区须语义化 表格必须明确标清哪一行 / 列是表头、哪是数据格，以及表头管辖的是整列还是整行。严禁仅靠视觉加粗充当表头，否则机器无法识别语义表头。
  • 合并归属须可还原 合并单元格必须声明跨行 / 跨列（如 rowspan / colspan），确保合并后的内容归属关系可被还原。分组严禁仅靠颜色或底色区分，须提供结构化标识。
  • 表内列表单独成块 接口参数、要点等内容必须作为独立列表呈现；严禁拆成假表格行，也严禁与相邻字段揉进同一格写成一大段。

描述性标题与语义表头须齐全

x (8,2048) float16
  • 常见疏漏：首行是 td；无 caption，切片后难当列名。

文档内容调整

调整建议

  • caption 与列名写全 稿面与 Markdown 表均有描述性标题；列名稳定、可当字段名，勿用「列1」「备注」等空泛词。
  • 合并在文稿可还原 Markdown 无 rowspan 时，优先拆行写全场景名，或注明「以下两行同属预训练」；勿留空首列指望读者脑补。
  • 状态词另遵状态页 格内「支持 / 不支持」等词义见 状态词可完整识别；本页只约束表骨架，不重复符号替换细则。

前端调整

调整建议

  • 输出完整语义结构 首包 HTML 含 caption、thead / th+scope、tbody；禁止用样式 td 冒充表头。
  • 合并须可切片展开 rowspan / colspan 后管道须能展开为「列名:值」且带上合并行头；空首列不得入库为独立行。
  • 嵌套列表同 chunk 格内 ul 与所属表 / 单元格绑定切片，不拆散成游离列表块。

调整示例

合并行头须用 rowspan

反面 
<tr><td>预训练</td><td>V3</td>…</tr>
<tr><td></td><td>Janus</td>…</tr>
  • 常见疏漏：空单元格、归属靠视觉；空 td 入库后场景名丢失。
正面 
<tr>
  <th scope="row" rowspan="2">预训练</th>
  <td>V3</td>…
</tr>
<tr><td>Janus</td>…</tr>
  • 正确做法：行头合并，切片可还原场景；行头 th + rowspan，管道展开时带回场景名。
