机器可达：AI 亲和的起点

机器可达是 AI 亲和体系的起点。本页聚焦发现层的四个基础配置文件，其分工逻辑为：robots.txt 作为准入前提，llms.txt 作为主要路径，llms-full.txt 作为导读配套，sitemap.xml 作为兜底清单。它们共同回答了「知识在哪里、先看哪篇、如何高效获取」的问题。

Agent 是如何发现内容的

流程验证

核心原则

  • 聚焦知识面本套机制只面向文档与官方事实，营销面内容不占用发现层入口。
  • 门禁作为准入前提robots.txt 承担发现层的准入角色，是其他入口能够合法触达的前提。
  • 导读作为主要路径存在 llms.txt 时，以此作为判断相关性优先级的主要依据；sitemap.xml 仅用于导读缺失时的回退，不替代导读职责。
  • 体量可控、允许分卷根目录的 llms.txt 应保持在可被读取器完整消费的范围内；当产品或文档站体量较大时，根文件只做总索引并链向分卷导读（如 /llms/cann.txt），避免单文件过大导致读取中途截断。
  • 全文包作为导读配套llms-full.txt 是 llms.txt 的配套组件，内容与导读保持同步，不脱离导读单独存在；分卷时，正文包跟随分卷走。

典型做法

1. robots.txt：准入门禁

进站时优先读取的准入文件，用于界定知识面的合法抓取边界。

约定路径

https://{域名}/robots.txt（该路径由协议固定，站点需按此约定放置）。

最小合格示例

执行要点

  • 放行知识面文档站、官网知识页、根导读 /llms.txt 及配套正文包 /llms-full.txt 保持可访问（不设 Disallow）；如有分卷，建议统一放在 /llms/ 目录下并对其放行，避免误挡主流 Agent。
  • 拦截噪声面后台、测试环境、调试接口等非公开路径，通常需要设置 Disallow，避免占用抓取额度。
  • 声明清单地址在文件末尾通过 Sitemap: 字段列出 sitemap.xml 的完整地址，为 Agent 提供后续的发现入口。
  • 进阶声明（非标准）部分厂商会仿照 Sitemap: 的写法，在 robots.txt 中额外声明 LLMs.txt: 指向根导读。该字段并非官方规范，仅作为路径不确定时的补充信号；若有分卷，无需在此列出，由根文件内的链接发现即可。

2. llms.txt：优先导读

面向 Agent 的精选导读，只收录主推知识面，并非全站清单。根文件尽量精简；若产品线较多，采用“短索引 + 分卷导读”的结构，避免单文件过大影响读取。

约定路径

  • 根导读路径默认位于站点根目录：https://{域名}/llms.txt。若文档站部署在子路径下（例如 example.com/docs），对应路径则为 https://example.com/docs/llms.txt。
  • 分卷导读路径（多产品线 / 多文档站并存时）多条产品线或独立知识面并存（如 CANN 与 Ascend C），且根文件放不下时，建议统一放到 /llms/ 子目录下，保持结构清爽。具体路径由根文件显式声明，如 /llms/cann.txt、/llms/ascend-c.txt。单产品站条目少，直接写在根文件即可，不用分卷。

最小合格示例

执行要点

  • 直接可达根路径 /llms.txt 直接返回内容，不设置跳转或登录拦截。
  • 结构与收录H1 标站点名；> 标明主推版本与分卷策略（多版本需显式写出主推）。链接文案与页面 H1 一致；仅收知识面，不收营销页。
  • 控制体量根文件保持精简；避免数万行或数 MB 的索引堆砌（过大文件会中途截断，导致后方入门条目无法获取）。
  • 分卷挂接多产品线并存时，根文件只做总索引并链向分卷；分卷按产品或文档站一层拆分，不再嵌套。分卷链接可直接 GET，并在 robots.txt 放行。单产品站条目少时，可直接写在根文件，无需分卷。

3. llms-full.txt：配套正文包

导读的配套正文包。由导读触发，用于一次性提取纯净正文。导读分卷时，正文包按同卷切分，避免单包过大导致超时或截断。

约定路径

默认遵循同目录惯例：https://{域名}/llms-full.txt。分卷时，正文包与导读成对出现在 /llms/ 下（如 /llms/full-cann.txt 对应 /llms/cann.txt），链接在根导读或分卷导读中显式写明。

最小合格示例

执行要点

  • 入口限制入口依赖导读里的链接或同目录惯例，不脱离导读单独配置。
  • 按卷拆分导读分卷时，正文包也跟着分卷，不用把全站正文打成单一超大文件（实测中这种文件容易超时，也很难完整取回）。
  • 构建同步随文档发布自动生成，不依赖人工维护，也不会单独发布空文件。
  • 结构对齐篇目和顺序跟着对应导读（根或分卷）保持一致。
  • 正文纯净只保留可引用正文，导航、页脚和侧栏都不含。

4. sitemap.xml：无导读兜底

公开知识页的 URL 清单，作为导读缺失时的兜底入口。

约定路径

该文件的地址不能像前三个文件那样直接按根路径访问，需通过 robots.txt 中的 Sitemap: 字段显式声明完整地址，才能被 Agent 找到。

最小合格示例

执行要点

  • 收录范围面向应被公开索引的知识面页面，后台和重复 URL 不纳入。
  • 语义化 URL路径与文件名带上明确的业务语义（如产品名、版本号），避免无意义参数和会话 ID。
  • 地址声明完整地址写在 robots.txt 的 Sitemap: 行，声明为绝对地址。
  • 动态维护页面增删或迁移后，清单跟着更新。

价值收益

  • 抓取资源更聚焦噪声页被隔离后，抓取额度集中用在刀刃上，知识库输入更干净，无效页面的占用明显减少。
  • 检索命中更完整主推版本优先被抓到，深层或新增页面作为补充，从「高频核心」到「边缘细节」都能覆盖到。
  • 入库链路更高效不用再一页页渲染页面壳层，直接拿纯净正文，从抓取到进入知识库的时间更短。
  • 回答出处更权威官方事实优先成为引用依据，能避开过期内容或营销页的误导，回答的整体可信度自然更高。
