邻篇导航可续读

为了帮助 Agent 沿手册结构连贯续读，相邻文档须写成「上一篇 / 下一篇」及真实篇名；禁止只写「上一页 / 下一页」。

适用对象

名称 说明
邻篇导航 当前篇与手册序列中上一篇 / 下一篇的入口，常见落点：文档页底、章节末。

适用场景

优先级 页面类型 说明
必做 手册 / 教程正文页 侧栏目录有序，最利于 Agent 沿序列续读，须提供完整的上下篇导航。
建议做 官网连载、专题系列、相关阅读块 存在邻接或推荐关系，但未必在同一手册树内，建议提供下一篇 / 相关链接。

设计UI调整

调整建议

  • 邻篇默认可见 上一篇 / 下一篇入口须默认可见，文案必须包含真实篇名；严禁仅写「上一页 / 下一页」或纯箭头。
  • 关系词写清 须使用「上一篇 / 下一篇」等明确文档关系词，严禁使用「返回 / 继续」等无法判断邻接目标的泛词。

调整示例

邻篇须写出篇名

反面

安装指南

‹ 上一页　　下一页 ›

  • 常见疏漏：仅写「上一页 / 下一页」，机器无法识别邻篇是谁。

  • 正确做法：写成「上一篇 / 下一篇」加真实篇名。

文档内容调整

调整建议

  • 篇名与正文一致 邻篇文案必须与目标页 H1、侧栏目录用语完全一致；严禁另起一套叫法导致「看得见但对不上」或同一篇被识别成多个入口。
  • 顺序与手册对齐 上一篇 / 下一篇的顺序必须与手册目录 / 教程序列严格对齐；严禁凭版式随意跳接无关页。

调整示例

邻篇篇名须与目标页一致

  • 正确做法：邻篇篇名与目标页 H1、侧栏目录使用同一套叫法。

前端调整

调整建议

  • 真实可跟链 邻篇必须使用带真实文档 URL 的 <a href> 标准链接，锚文本必须包含篇名；严禁仅用 button 或无地址的伪点击态冒充链接。
  • 首包即含邻篇 首包 HTML 须直接输出上一篇 / 下一篇的可跟链；严禁仅依赖客户端路由或脚本注入后才出现。

调整示例

邻篇须为可跟链

反面 
<button type="button">上一页</button>
<button type="button">下一页</button>
<!-- 无篇名；链接靠客户端路由注入 -->
  • 常见疏漏：无真实 href、无篇名；静态抓取跟不到邻篇。
正面 
<nav aria-label="邻篇导航">
  <a href="/docs/driver">上一篇 安装驱动</a>
  <a href="/docs/env">下一篇 配置环境变量</a>
</nav>
  • 正确做法：首包即含可跟链；锚文本含「上一篇 / 下一篇」与篇名。
