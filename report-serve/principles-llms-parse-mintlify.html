Mintlify 根 llms.txt

解析什么

对照 Mintlify 站根 https://www.mintlify.com/llms.txt。这是单站入口：同一份里分册 llms.txt 与单页 .md 并存。原则写法见根llms。

它在解决什么

文档站、博客、资料库页多，官网还有定价、法务等一页就能读完的入口。根文件只当目录：大面链分册，单页链 .md，避免全站 URL 堆砌导致截断。

这张根清单怎么分面

  • 按下一步分节文档面、站点页、分面入口、可选入口分开，不是把导航菜单原样搬家。
  • 大面写分册，单页写 .md文档 / 博客 / 资料库 / 客户案例链分册；首页、定价、法务直接 .md。
  • 正文包不是第二份根清单llms-full.txt 标在 Docs 里，是营销页正文包，不是又一本目录。

根 llms 交付示例

对照 Mintlify 站根 llms.txt 全文。收录的是入口：文档/博客/资料库/客户案例的分册 llms.txt，以及首页、定价、法务等一页就能读完的 .md。不收录文档站每一页、每一篇博文或案例的正文——那些在分册里再摊开。分册打开之后写什么，见分册llms。

根 llms.txt 交付件拆解

对照 Mintlify 站根 llms.txt：只当目录，不写文章正文。分节按 Agent 下一步要干什么，不是把站点导航原样搬家。同一文件里，分册 llms.txt、单页 .md、正文包、非目录兜底可以并存——先选面，再决定跟哪一种地址。

页顶

# Mintlify 是站点名。引用块说明本文件是全站 Markdown 索引，并约定：任意页 URL 加 .md，或发送 Accept: text/markdown，即可取平行稿。

文档面

进站主任务是找产品文档，所以单独成节。这一面页多，第一条链分册 docs/llms.txt；home、quickstart、skill 一页就能读完，直接 .md。绿行里的 llms-full.txt 是正文包，不是又一本目录，Agent 不该把它当第二份根清单。分册内部怎么写，见分册llms。

站点页

官网营销/公司页：首页、定价、招聘。每页一份平行 .md，没有「再打开一本 llms」。和 Docs 拆开，避免把「读产品手册」和「读官网一页」混在同一组。

分面入口

Blog、Library、Customers 是会持续变长的集合：一条分册 llms.txt 摊开各篇，一条 listing .md 对应人读列表。Legal、Security 也是独立的面，但页少，不单开分册，只挂 .md。同一逻辑：面大才分册，面小直接叶子。

可选入口

不在主消费路径上，放最后等于告诉 Agent：前面读完就可以停。score.md 是排行；sitemap.xml 是 HTML 页兜底，都不是 Markdown 知识目录。

价值收益

  • 先看该看的主推知识面写在清单前面，Agent 不必从营销页或全站 URL 里筛。
  • 能跟到正文分册或单页地址写明，落到单页后可直接取平行稿。
  • 读得完根文件保持精简，体量大则分册。
