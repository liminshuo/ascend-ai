页内结构模式化

原则定义

文档主体若写成自由散文，块与块之间没有稳定边界，AI Agent 难以按段识别、检索或引用。

文案应按信息块切开：一块一类信息，边界清晰、格式稳定。切成几块、叫什么名字随任务而定；重点是结构化，而不是套用某一种固定目录。

视觉规则

  1. 1-4 信息块正文按信息块切开：一块一类信息，边界清晰、可单独识别与引用。块数与节名随任务而定，本例四段仅为示意。

前端规则

  1. 按块切开每个信息块用独立 h2/h3（或 Markdown ##/###）分隔。
  2. 块内稳定块内选用稳定标签（如 ul/ol/p/pre），同页同类块写法一致。

示例如下（安装切法，非唯一）：

<h2>前提条件</h2>
<ul><li>操作系统版本 ≥ 指定基线</li></ul>
<h2>步骤</h2>
<ol><li>下载驱动包</li></ol>
<h2>验证</h2>
<p>命令输出含驱动版本号</p>
<h2>示例</h2>
<pre><code>npu-smi info</code></pre>

适用边界

适用于安装、配置、API、排障、概念说明等需要被 AI 按块识别与引用的正文。

不要求所有页面都切成「前提 → 步骤 → 验证 → 示例」；按任务选用节名与块数。一旦某类页定了切法，同页内应保持稳定。

本原则管单篇怎么切块、块内怎么写；多篇是否同名同序见「全站规范一致性」。
